4.10. 流水线#

管道，引入 高级同步原语，是一种用于暂存工作和协调多缓冲区生产者-消费者模式的机制，通常用于与计算重叠 异步数据复制.

本节主要通过以下方式详细介绍如何使用管道 cuda::pipeline API（在适用的情况下带有指向原语的指针）。

4.10.1. 初始化#

A cuda::pipeline 可以在不同的线程范围内创建。对于除以下范围之外的范围 cuda::thread_scope_thread, a cuda::pipeline_shared_state<scope, count> 需要对象来协调参与线程。该状态封装了有限的资源，允许管道处理最多 count 并发阶段。

// 在线程范围内创建管道
constexpr auto scope = cuda::thread_scope_thread;
cuda::pipeline<scope> pipeline = cuda::make_pipeline();

// 在块范围内创建管道
constexpr auto scope = cuda::thread_scope_block;
constexpr auto stages_count = 2;
__shared__ cuda::pipeline_shared_state<scope, stages_count> shared_state;
auto pipeline = cuda::make_pipeline(group, &shared_state);

管道可以是 unified 或 partitioned。在统一的管道中，所有参与的线程既是生产者又是消费者。在分区管道中，每个参与线程要么是生产者，要么是消费者，并且其角色在管道对象的生命周期内不能更改。线程本地管道无法分区。要创建分区管道，我们需要提供生产者的数量或线程的角色 cuda::make_pipeline().

// 在块范围内创建一个分区管道，其中只有线程 0 是生产者
constexpr auto scope = cuda::thread_scope_block;
constexpr auto stages_count = 2;
__shared__ cuda::pipeline_shared_state<scope, stages_count> shared_state;
auto thread_role = (group.thread_rank() == 0) ? cuda::pipeline_role::producer : cuda::pipeline_role::consumer;
auto pipeline = cuda::make_pipeline(group, &shared_state, thread_role);

为了支持分区，共享 cuda::pipeline 会产生额外的开销，包括每个阶段使用一组共享内存屏障进行同步。即使管道统一并且可以使用，也会使用这些 __syncthreads() 相反。因此，最好使用线程本地管道，尽可能避免这些开销。

4.10.2. 提交作品#

将工作提交到管道阶段涉及：

  • Collectively acquiring 管道 head 来自一组生产者线程，使用 pipeline.producer_acquire().

  • 提交异步操作，例如 memcpy_async，到管道头。

  • Collectively committing （推进）管道头使用 pipeline.producer_commit().

如果所有资源都被使用， pipeline.producer_acquire() 阻塞生产者线程，直到消费者线程释放下一个管道阶段的资源。

4.10.3. 消耗工作#

使用先前提交的阶段的工作涉及：

  • 共同等待阶段完成，例如，使用 pipeline.consumer_wait() 在一组消费者线程的尾部（最旧的）阶段等待。

  • Collectively releasing 舞台使用 pipeline.consumer_release().

With cuda::pipeline<cuda:thread_scope_thread> 还可以使用 cuda::pipeline_consumer_wait_prior<N>() 友元函数等待除最后 N 个阶段之外的所有阶段完成，类似于 __pipeline_wait_prior(N) 在原语 API 中。

4.10.4. warp 纠缠#

管道机制在同一 warp 中的 CUDA 线程之间共享。这种共享会导致提交的操作序列纠缠在warp 中，这在某些情况下可能会影响性能。

Commit。提交操作被合并，以便对于调用提交操作的所有聚合线程，管道的序列递增一次，并且它们提交的操作被批处理在一起。如果warp完全收敛，则序列加一，所有提交的操作将在管道的同一阶段进行批处理；如果 warp 完全发散，则序列将增加 32，并且所有提交的操作将分散到不同的阶段。

  • 令 PB 是warp共享管道的 actual 操作顺序。

    PB = {BP0, BP1, BP2, …, BPL}

  • 令 TB 是一个线程的 perceived 操作序列，就好像该序列仅通过该线程调用提交操作来递增。

    TB = {BT0, BT1, BT2, …, BTL}

pipeline::producer_commit() 返回值来自线程的 perceived 批次顺序。

  • 线程感知序列中的索引始终与实际warp共享序列中相同或更大的索引对齐。仅当从完全聚合的线程调用所有提交操作时，序列才相等。

    BTn ≡ BPm where n <= m

例如，当 warp完全发散时：

  • warp共享管道的实际顺序是： PB = {0, 1, 2, 3, ..., 31} (PL=31).

  • 该 warp的每个线程的感知序列将是：

    • 线程 0： TB = {0} (TL=0)

    • 主题 1： TB = {0} (TL=0)

    • …

    • 主题 31： TB = {0} (TL=0)

Wait。 CUDA 线程调用 pipeline::consumer_wait() 或 pipeline_consumer_wait_prior<N>() 等待批次 perceived sequence TB 来完成。请注意 pipeline::consumer_wait() 相当于 pipeline_consumer_wait_prior<N>(), 其中 N = PL.

提前等待 变体等待批次 actual 序列至少达到并包括 PL-N。自从 TL <= PL，等待批次达到并包括 PL-N 包括等待批次 TL-N。因此，当 TL < PL，线程将无意中等待额外的、更新的批次。在上面的极端完全发散的warp示例中，每个线程可以等待所有 32 个批次。

注

建议通过保持线程感知的批次序列与实际序列保持一致，由聚合线程进行提交调用，以免过度等待。

当这些操作之前的代码使线程发散时，应该重新聚合warp，通过 __syncwarp 在调用提交操作之前。

4.10.5. 提前退出#

当参与管道的线程必须提前退出时，该线程必须在退出之前显式退出参与 cuda::pipeline::quit()。其余参与线程可以正常进行后续操作。

4.10.6. 跟踪异步内存操作#

以下示例演示了如何使用异步内存副本将数据从全局内存集中复制到共享内存，并使用管道来跟踪复制操作。每个线程使用自己的管道独立提交内存副本，然后等待它们完成并消费数据。有关异步数据副本的更多详细信息，请参阅 第3.2.5节.

#include <cuda/pipeline>

__global__ void example_kernel(const float *in)
{
    constexpr int block_size = 128;
    __shared__ __align__(sizeof(float)) float buffer[4 * block_size];

    // 每个线程创建统一的管道
    cuda::pipeline<cuda::thread_scope_thread> pipeline = cuda::make_pipeline();

    // 第一阶段内存复制
    pipeline.producer_acquire();
    // 每个线程获取第一个块的一个元素
    cuda::memcpy_async(buffer, in, sizeof(float), pipeline);
    pipeline.producer_commit();

    // 第二阶段内存复制
    pipeline.producer_acquire();
    // 每个线程获取第二个和第三个块的一个元素
    cuda::memcpy_async(buffer + block_size, in + block_size, sizeof(float), pipeline);
    cuda::memcpy_async(buffer + 2 * block_size, in + 2 * block_size, sizeof(float), pipeline);
    pipeline.producer_commit();

    // 第三阶段内存复制
    pipeline.producer_acquire();
    // 每个线程获取最后一个块的一个元素
    cuda::memcpy_async(buffer + 3 * block_size, in + 3 * block_size, sizeof(float), pipeline);
    pipeline.producer_commit();

    // 等待最旧的阶段（等待第一个阶段）
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // 使用第一阶段的数据

    // 等待最旧的阶段（等待第二阶段）
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // 使用第二阶段的数据

    // 等待最旧的阶段（等待第三阶段）
    pipeline.consumer_wait();
    pipeline.consumer_release();

    // __syncthreads();
    // 使用第三阶段的数据
}

#include <cuda_pipeline.h>

__global__ void example_kernel(const float *in)
{
    constexpr int block_size = 128;
    __shared__ __align__(sizeof(float)) float buffer[4 * block_size];

    // 第一批内存副本
    // 每个线程获取第一个块的一个元素
    __pipeline_memcpy_async(buffer, in, sizeof(float));
    __pipeline_commit();

    // 第二批内存副本
    // 每个线程获取第二个和第三个块的一个元素
    __pipeline_memcpy_async(buffer + block_size, in + block_size, sizeof(float));
    __pipeline_memcpy_async(buffer + 2 * block_size, in + 2 * block_size, sizeof(float));
    __pipeline_commit();

    // 第三批内存副本
    // 每个线程获取最后一个块的一个元素
    __pipeline_memcpy_async(buffer + 3 * block_size, in + 3 * block_size, sizeof(float));
    __pipeline_commit();

    // 等待除最后两批内存副本之外的所有内存副本（等待第一批）
    __pipeline_wait_prior(2);

    // __syncthreads();
    // 使用第一批数据

    // 等待除最后一批内存副本之外的所有内存副本（等待第二批）
    __pipeline_wait_prior(1);

    // __syncthreads();
    // 使用第二批数据

    // 等待所有批次的内存副本（等待第三批）
    __pipeline_wait_prior(0);

    // __syncthreads();
    // 使用最后一批的数据
}

4.10.7. 使用管道的生产者-消费者模式#

In 第4.9.7节，我们展示了如何使用空间分区线程块来实现生产者-消费者模式 异步屏障。与 cuda::pipeline，这可以使用每个数据缓冲区一个阶段的单个分区管道来简化，而不是每个缓冲区两个异步屏障。

#include <cuda/pipeline>
#include <cooperative_groups.h>

#pragma nv_diag_suppress static_var_with_dynamic_init

using pipeline = cuda::pipeline<cuda::thread_scope_block>;

__device__ void produce(pipeline &pipe, int num_stages, int stage, int num_batches, int batch, float *buffer, int buffer_len, float *in, int N)
{
  if (batch < num_batches)
  {
    pipe.producer_acquire();
    /* 使用异步内存复制将数据从 in(batch) 复制到 buffer(stage) */
    pipe.producer_commit();
  }
}

__device__ void consume(pipeline &pipe, int num_stages, int stage, int num_batches, int batch, float *buffer, int buffer_len, float *out, int N)
{
  pipe.consumer_wait();
  /* 消耗缓冲区（阶段）并更新输出（批量） */
  pipe.consumer_release();
}

__global__ void producer_consumer_pattern(float *in, float *out, int N, int buffer_len)
{
  auto block = cooperative_groups::this_thread_block();

  /* 下面声明的共享内存缓冲区的大小为 2 * buffer_len
     这样我们就可以在两个缓冲区之间交替工作。
     buffer_0 = 缓冲区且 buffer_1 = 缓冲区 + buffer_len */
  __shared__ extern float buffer[];

  const int num_batches = N / buffer_len;

  // 创建一个具有 2 个阶段的分区管道，其中一半线程是生产者，另一半是消费者。
  constexpr auto scope = cuda::thread_scope_block;
  constexpr int num_stages = 2;
  cuda::std::size_t producer_count = block.size() / 2;
  __shared__ cuda::pipeline_shared_state<scope, num_stages> shared_state;
  pipeline pipe = cuda::make_pipeline(block, &shared_state, producer_count);

  // 填充管道
  if (block.thread_rank() < producer_count)
  {
    for (int s = 0; s < num_stages; ++s)
    {
      produce(pipe, num_stages, s, num_batches, s, buffer, buffer_len, in, N);
    }
  }

  // 处理批次
  int stage = 0;
  for (size_t b = 0; b < num_batches; ++b)
  {
    if (block.thread_rank() < producer_count)
    {
      // 预取下一批
      produce(pipe, num_stages, stage, num_batches, b + num_stages, buffer, buffer_len, in, N);
    }
    else
    {
      // 消耗最旧的批次
      consume(pipe, num_stages, stage, num_batches, b, buffer, buffer_len, out, N);
    }
    stage = (stage + 1) % num_stages;
  }
}

在这个例子中，我们使用线程块中的一半线程作为生产者，另一半作为消费者。作为第一步，我们需要创建一个 cuda::pipeline 目的。由于我们希望一些线程成为生产者，一些线程成为消费者，所以我们需要使用 partitioned 管道与 cuda::thread_scope_block。分区管道需要 cuda::pipeline_shared_state 协调参与的线程。我们在线程块范围内初始化 2 阶段管道的状态，然后调用 cuda::make_pipeline()。接下来，生产者线程通过提交异步副本来填充管道 in 或 buffer。此时，所有数据副本都在进行中。最后，在主循环中，我们检查所有批次的数据，并根据线程是生产者还是消费者，我们要么为未来的批次提交另一个异步副本，要么消耗当前的批次。
