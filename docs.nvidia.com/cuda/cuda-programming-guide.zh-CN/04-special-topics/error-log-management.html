4.8. 错误日志管理#

错误日志管理 机制可以用描述问题原因的简明英文格式， 向开发人员报告 CUDA API 错误。

4.8.1. 背景#

传统上，CUDA API 调用失败时，唯一的提示是返回一个非零代码。 截至 CUDA Toolkit 12.9，CUDA 运行时为错误条件定义了 100 多种不同的返回代码， 但其中许多返回码都比较笼统，无法帮助开发人员调试具体原因。

4.8.2. 启用#

设置 CUDA_LOG_FILE 环境变量。可接受的值包括 stdout、stderr， 或系统上可写文件的有效路径。即使程序执行前未设置 CUDA_LOG_FILE， 也可以通过 API 转储日志缓冲区。 注意：没有错误的执行过程可能不会打印任何日志。

4.8.3. 输出#

日志输出格式如下：

[Time][TID][Source][Severity][API Entry Point] Message

如果开发人员尝试将错误日志管理日志转储到未分配的缓冲区，会生成如下实际错误消息：

[22:21:32.099][25642][CUDA][E][cuLogsDumpToMemory] buffer cannot be NULL

在此之前，开发人员能获得的通常只是返回码中的 CUDA_ERROR_INVALID_VALUE； 如果调用 cuGetErrorString，也许还会得到“invalid argument”。

4.8.4. API 说明#

CUDA 驱动程序提供两类 API，用于与错误日志管理功能进行交互。

该功能允许开发人员注册回调函数，在生成错误日志时使用；回调签名如下：

void callbackFunc(void *data, CUlogLevel logLevel, char *message, size_t length)

使用以下 API 注册回调：

CUresult cuLogsRegisterCallback(CUlogsCallback callbackFunc, void *userData, CUlogsCallbackHandle *callback_out)

其中，userData 会原样传递给回调函数。调用者应保存 callback_out， 以便稍后用于 cuLogsUnregisterCallback。

CUresult cuLogsUnregisterCallback(CUlogsCallbackHandle callback)

另一组 API 函数用于管理日志输出。这里的一个重要概念是日志迭代器，它指向缓冲区当前的末尾位置：

CUresult cuLogsCurrent(CUlogIterator *iterator_out, unsigned int flags)

当不希望转储整个日志缓冲区时，调用方软件可以保留迭代器位置。目前，flags 参数必须为 0，其他选项保留给未来的 CUDA 版本使用。

可以随时使用以下函数将错误日志缓冲区转储到文件或内存中：

CUresult cuLogsDumpToFile(CUlogIterator *iterator, const char *pathToFile, unsigned int flags)
CUresult cuLogsDumpToMemory(CUlogIterator *iterator, char *buffer, size_t *size, unsigned int flags)

如果 iterator 为 NULL，将转储整个缓冲区，最多转储 100 个条目。如果 iterator 不为 NULL， 日志会从该条目开始转储，并且 iterator 的值会更新为日志当前的末尾位置，就像调用过 cuLogsCurrent 一样。 如果缓冲区中写入过超过 100 个日志条目，转储开头会添加一条说明，指出发生过回卷。

flags 参数必须为 0，其他选项保留给未来的 CUDA 版本使用。

cuLogsDumpToMemory 函数还需要注意以下事项：

  1. 缓冲区本身会以空字符结尾，但每个单独的日志条目只用换行符 (n) 分隔。

  2. 缓冲区的最大大小为 25600 字节。

  3. 如果提供的 size 值不足以存储所有所需日志，会添加一条说明作为第一个条目，而放不下的最旧条目不会被转储。

  4. 返回后，size 将包含实际写入所提供缓冲区的字节数。

4.8.5. 限制和已知问题#

  1. 日志缓冲区限制为 100 个条目。达到此限制后，最旧的条目会被替换，日志转储中也会包含一行说明，指出发生过回卷。

  2. 目前还没有覆盖所有 CUDA API。这项工作仍在持续推进，目标是为所有 API 提供更好的用法错误报告。

  3. 如果给出了错误日志管理日志位置，其有效性只会在生成日志时才进行检查。

  4. 错误日志管理 API 目前只能通过 CUDA 驱动程序使用。等效 API 将在未来版本中添加到 CUDA 运行时。

  5. 日志消息不会本地化为任何语言，所有提供的日志均为美国英语。
