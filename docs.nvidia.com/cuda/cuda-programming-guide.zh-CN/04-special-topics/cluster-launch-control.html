4.12. 使用簇启动控制进行工作窃取#

在开发 CUDA 应用程序时，处理可变数据和计算量的问题至关重要。传统上，CUDA 开发人员使用两种主要方法来确定要启动的内核线程块的数量： 每个线程块的固定工作 或 固定数量的线程块。两种方法都有其优点和缺点。

每个线程块的固定工作： 在这种方法中，线程块的数量由问题的大小决定，而每个线程块完成的工作量保持不变。

这种方法的主要优点：

  • SM之间的负载均衡

    当线程块运行时间表现出可变性时 和/或当线程块的数量远大于线程块的数量时 GPU可以同时执行（产生低尾效应）， 这种方法允许 GPU 调度程序运行更多线程块 在某些短信上比其他短信更重要。

  • Preemption

    GPU调度器可以开始执行 更高优先级的内核, 即使它是在较低优先级内核启动后启动的 已经开始执行，通过调度其线程块 当较低优先级内核的线程块完成时。 一旦较高优先级的内核被执行，它就可以恢复执行较低优先级的内核。 内核已经执行完毕。

固定数量的线程块： 在这种方法中，常常 实现为块跨步或网格跨步循环， 线程块的数量不依赖于 关于问题的大小。相反，每个线程块完成的工作量 是问题大小的函数。通常，线程块的数量是 基于执行内核的 GPU 上的 SM 数量 以及所需的入住率。

这种方法的主要优点：

  • 减少线程块开销

    这种方法不仅减少了分摊线程块启动延迟 而且还最大限度地减少了与共享相关的计算开销 跨所有线程块的操作。 这些开销可能明显高于启动延迟开销。

    例如，在卷积核中，用于计算的序言 卷积系数 – 独立于线程块索引 – 由于线程块的数量固定，计算次数可以减少， 从而减少冗余计算。

集群启动控制 是 NVIDIA Blackwell GPU 架构（计算能力 10.0）中引入的一项功能，旨在结合前两种方法的优点。它允许开发人员取消线程块或线程块集群，从而为开发人员提供对线程块调度的更多控制。 这种机制可以实现工作窃取。工作窃取是并行计算中的一种动态负载平衡技术 空闲处理器主动从繁忙的工作队列中“窃取”任务 处理器，而不是等待分配工作。

通过集群启动控制，线程块尝试取消启动 另一个尚未开始执行的线程块。如果取消请求 成功后，它通过使用其“窃取”另一个线程块的工作 执行任务的索引。如果没有更多则取消失败 线程块索引可用或出于其他原因，例如 正在调度更高优先级的内核。在后一种情况下，如果线程阻塞 取消失败后退出，调度程序可以开始执行 优先级较高的内核，之后它将继续调度剩余的内核 当前内核执行的线程块。的 figure 上面介绍了执行 该程序的流程。

4.12.1. 接口详情#

通过集群启动控制 API 取消线程块已完成 使用共享内存屏障进行异步和同步， 遵循类似的编程模式 到 异步数据复制.

API，可通过 libcu++，提供：

  • 将编码的取消结果写入到的请求指令 __shared__ variable.

  • 解码提取成功/失败状态和取消的线程块索引的指令。

请注意，集群启动控制操作被建模为异步代理操作（请参阅 异步线程和异步代理).

4.12.1.1. 线程块取消#

使用集群启动控制的首选方法是从单个线程， 即一次一个请求。

取消过程包括五个步骤：

  • 设置阶段 （步骤1-2）：声明并初始化取消结果和同步变量。

  • 工作窃取循环 （步骤3-5）：重复执行以请求、同步和处理取消结果。

  1. 声明线程块取消的变量：

    __shared__ uint4 result; // 请求结果。
__shared__ uint64_t bar; // 同步障碍。
int phase = 0;           // 同步屏障阶段。

  2. 使用单个到达计数初始化共享内存屏障：

    if (cg::thread_block::thread_rank() == 0)
    ptx::mbarrier_init(&bar, 1);
__syncthreads();

  3. 单线程提交异步取消请求并 设置交易数量：

    if (cg::thread_block::thread_rank() == 0) {
    cg::invoke_one(cg::coalesced_threads(), [&](){ptx::clusterlaunchcontrol_try_cancel(&result, &bar);});
    ptx::mbarrier_arrive_expect_tx(ptx::sem_relaxed, ptx::scope_cta, ptx::space_shared, &bar, sizeof(uint4));
}

    注

    由于线程块取消是统一指令， 建议在里面提交 invoke_one 线程选择器。 这允许编译器优化剥离循环。

  4. 同步（完成）异步取消请求：

    while (!ptx::mbarrier_try_wait_parity(&bar, phase))
{}
phase ^= 1;

  5. 检索取消状态和取消的线程块索引：

    bool success = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result);
if (success) {
    // 1D/2D 线程块不需要全部三个：
    int bx = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_x(result);
    int by = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_y(result);
    int bz = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_z(result);
}

  6. 确保异步和通用之间共享内存操作的可见性 proxies, 并防止工作窃取循环迭代之间的数据竞争。

4.12.1.2. 线程块取消的约束#

这些限制与失败的取消请求相关：

  • 之后再次提交取消请求 observing 一个 之前失败的请求是 未定义的行为.

    在下面的两个代码示例中，假设第一个取消请求 失败，只有第一个示例表现出未定义的行为。 第二个例子是正确的，因为在 取消请求：

    无效代码：

    // 第一个请求：
ptx::clusterlaunchcontrol_try_cancel(&result0, &bar0);

// 第一个请求查询：
[Synchronize bar0 code here.]
bool success0 = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result0);
assert(!success0); // 观察到的故障；第二次取消将无效。

// 第二个请求 - 下一行是未定义的行为：
ptx::clusterlaunchcontrol_try_cancel(&result1, &bar1);

    有效代码：

    // 第一个请求：
ptx::clusterlaunchcontrol_try_cancel(&result0, &bar0);

// 第二个请求：
ptx::clusterlaunchcontrol_try_cancel(&result1, &bar1);

// 第一个请求查询：
[Synchronize bar0 code here.]
bool success0 = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result0);
assert(!success0); // 观察到的故障；第二次取消有效。

  • 检索失败的取消请求的线程块索引 是未定义的行为。

  • 不建议从多个线程提交取消请求。 导致多个线程块被取消 并且需要小心处理， 如：

    • 每个提交线程必须提供唯一的 __shared__ 结果 避免数据竞争的指针。

    • 如果使用相同的屏障进行同步，则到达和 交易数量必须相应调整。

4.12.2. 示例：矢量标量乘法#

在以下小节中，我们将演示通过使用向量标量乘法内核的集群启动控制来窃取工作。我们展示了同一问题的两种变体：一种使用线程块，一种使用线程块集群。

4.12.2.1. 用例：线程块#

下面的三个内核演示了 每个线程块的固定工作, 固定数量的线程块, 和 集群启动控制 方法 用于矢量标量乘法 \(\overline{v} := \alpha \overline{v}\).

  • 每个线程块的固定工作：

    __global__
void kernel_fixed_work (float* data, int n)
{
    // 序言：
    float alpha = compute_scalar();

    // 计算：
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n)
        data[i] *= alpha;
}

// 启动：kernel_fixed_work<<<1024, (n + 1023) / 1024>>>(数据, n);

  • 固定数量的线程块：

    __global__
void kernel_fixed_blocks (float* data, int n)
{
    // 序言：
    float alpha = compute_scalar();

    // 计算：
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    while (i < n) {
        data[i] *= alpha;
        i += gridDim.x * blockDim.x;
    }
}

// 启动：kernel_fixed_blocks<<<1024，SM_COUNT>>>（数据，n）；

  • 集群启动控制：

    #include <cooperative_groups.h>
#include <cuda/ptx>

namespace cg = cooperative_groups;
namespace ptx = cuda::ptx;

__global__
void kernel_cluster_launch_control (float* data, int n)
{
    // 集群启动控制初始化：
    __shared__ uint4 result;
    __shared__ uint64_t bar;
    int phase = 0;

    if (cg::thread_block::thread_rank() == 0)
        ptx::mbarrier_init(&bar, 1);

    // 序言：
    float alpha = compute_scalar(); // 此代码片段中未显示设备功能。

    // 工作窃取循环：
    int bx = blockIdx.x; // 假设 1D x 轴线程块。

    while (true) {
        // 保护结果在下一次迭代中不被覆盖，
        // （还确保第一次迭代时的屏障初始化）：
        __syncthreads();

        // 取消请求：
        if (cg::thread_block::thread_rank() == 0) {
            // 获取异步代理中结果的写入：
            ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_acquire, ptx::space_cluster, ptx::scope_cluster);

            cg::invoke_one(cg::coalesced_threads(), [&](){ptx::clusterlaunchcontrol_try_cancel(&result, &bar);});
            ptx::mbarrier_arrive_expect_tx(ptx::sem_relaxed, ptx::scope_cta, ptx::space_shared, &bar, sizeof(uint4));
        }

        // 计算：
        int i = bx * blockDim.x + threadIdx.x;
        if (i < n)
            data[i] *= alpha;

        // 取消请求同步：
        while (!ptx::mbarrier_try_wait_parity(ptx::sem_acquire, ptx::scope_cta, &bar, phase))
        {}
        phase ^= 1;

        // 取消请求解码：
        bool success = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result);
        if (!success)
            break;

        bx = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_x<int>(result);

        // 将结果读取释放到异步代理：
        ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_release, ptx::space_shared, ptx::scope_cluster);
    }
}

// 启动：kernel_cluster_launch_control<<<1024, (n + 1023) / 1024>>>(数据, n);

4.12.2.2. 用例：线程块集群#

如果是 线程块簇, 线程块取消步骤与非集群设置中的相同， 进行细微调整。 与非集群情况一样，从多个提交取消请求 线程 簇内 不推荐， 因为这将尝试取消多个集群。

  • 取消由单个集群线程提交。

  • 每个集群的线程块的共享内存结果将收到 已取消线程块索引的相同（编码）值 （即，结果值被多播）。 所有线程块收到的结果都对应本地 块索引 {0, 0, 0} 在一个集群内。 因此，集群内的线程块需要添加 本地块索引。

  • 同步是由每个集群的线程块使用 本地人 __shared__ 内存障碍。必须进行屏障操作 与 ptx::scope_cluster scope.

  • 在集群情况下取消需要所有线程块都存在。 用户可以通过使用来保证所有线程块都在运行 cg::cluster_group::sync() from sync API。

下面的内核演示了使用线程块集群的集群启动控制方法。

#include <cooperative_groups.h>
#include <cuda/ptx>

namespace cg = cooperative_groups;
namespace ptx = cuda::ptx;

__global__ __cluster_dims__(2, 1, 1)
void kernel_cluster_launch_control (float* data, int n)
{
    // 集群启动控制初始化：
    __shared__ uint4 result;
    __shared__ uint64_t bar;
    int phase = 0;

    if (cg::thread_block::thread_rank() == 0) {
        ptx::mbarrier_init(&bar, 1);
        ptx::fence_mbarrier_init(ptx::sem_release, ptx::scope_cluster); // CGA级围栏。
    }

    // 序言：
    float alpha = compute_scalar(); // 此代码片段中未显示设备功能。

    // 工作窃取循环：
    int bx = blockIdx.x; // 假设 1D x 轴线程块。

    while (true) {
        // 保护结果在下一次迭代中不被覆盖，
        // （还要确保所有线程块已在第一次迭代时启动）：
        cg::cluster_group::sync();

        // 单个集群线程的取消请求：
        if (cg::cluster_group::thread_rank() == 0) {
            // 获取异步代理中结果的写入：
            ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_acquire, ptx::space_cluster, ptx::scope_cluster);

            cg::invoke_one(cg::coalesced_threads(), [&](){ptx::clusterlaunchcontrol_try_cancel_multicast(&result, &bar);});
        }

        // 每个线程块跟踪的取消完成：
        if (cg::thread_block::thread_rank() == 0)
            ptx::mbarrier_arrive_expect_tx(ptx::sem_relaxed, ptx::scope_cluster, ptx::space_shared, &bar, sizeof(uint4));

        // 计算：
        int i = bx * blockDim.x + threadIdx.x;
        if (i < n)
            data[i] *= alpha;

        // 取消请求同步：
        while (!ptx::mbarrier_try_wait_parity(ptx::sem_acquire, ptx::scope_cluster, &bar, phase))
        {}
        phase ^= 1;

        // 取消请求解码：
        bool success = ptx::clusterlaunchcontrol_query_cancel_is_canceled(result);
        if (!success)
            break;

        bx = ptx::clusterlaunchcontrol_query_cancel_get_first_ctaid_x<int>(result);
        bx += cg::cluster_group::block_index().x; // 添加局部偏移。

        // 将结果读取释放到异步代理：
        ptx::fence_proxy_async_generic_sync_restrict(ptx::sem_release, ptx::space_shared, ptx::scope_cluster);
    }
}

// 启动：kernel_cluster_launch_control<<<1024, (n + 1023) / 1024>>>(数据, n);
