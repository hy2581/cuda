4.17. 扩展 GPU 内存#

扩展 GPU 内存 (EGM) 功能，利用高带宽 NVLink-C2C，促进 GPU 对所有系统内存的高效访问， 在单节点和多节点系统中。 EGM 通过允许物理内存应用于集成 CPU-GPU NVIDIA 系统 可以从任何 GPU 访问的分配 设置中的线程。 EGM 确保所有 GPU 都可以访问 以 GPU-GPU NVLink 或 NVLink-C2C 的速度访问其资源。

在此设置中，内存访问通过本地高带宽进行 NVLink-C2C。对于远程内存访问， 使用 GPU NVLink，在某些情况下使用 NVLink-C2C。带 EGM、GPU 线程获得访问所有可用内存资源的能力， 包括通过 NVSwitch 结构连接 CPU 的内存和 HBM3。

4.17.1. 预备知识#

在深入研究 EGM 功能的 API 更改之前，我们将 涵盖当前支持的拓扑、标识符分配、 虚拟内存管理的先决条件以及 EGM 的 CUDA 类型。

4.17.1.1. EGM 平台：系统拓扑#

目前，EGM 可以在多个平台上启用： (1) 单节点、单GPU: 由基于 Arm 的 CPU、CPU 连接内存和 GPU 组成。 CPU之间 与 GPU 之间存在高带宽 C2C（芯片到芯片）互连。 (2) 单节点、多GPU：由基于 ARM 的 CPU 组成，每个 CPU 都带有附加内存， 以及通过基于 NVLink 的网络连接的多个 GPU。 (3) 多节点、多GPU：两个或多个单节点系统，每个系统如上述 (1) 或 (2) 所示， 通过基于 NVLink 的网络连接。

注

Using cgroups 限制可用设备将阻止通过 EGM 进行路由 并导致性能问题。使用 CUDA_VISIBLE_DEVICES instead.

4.17.1.2. 套接字标识符：它们是什么？如何访问它们？#

NUMA（非统一内存访问）是一种内存架构 多处理器计算机系统，内存被分为 多个节点。每个节点都有自己的处理器和内存。在这样一个 系统中，NUMA将系统划分为节点并分配唯一的 标识符（numaID）到每个节点。

EGM 使用由操作分配的 NUMA 节点标识符 系统。请注意，该标识符与 a 的序数不同 设备并且它与最近的主机节点关联。除了 现有的方法，用户可以获得主机的标识符 节点（numaID）通过调用 cuDeviceGetAttribute CU_DEVICE_ATTRIBUTE_HOST_NUMA_ID 属性类型如下：

int numaId;
cuDeviceGetAttribute(&numaId, CU_DEVICE_ATTRIBUTE_HOST_NUMA_ID, deviceOrdinal);

4.17.1.3. 分配者和临时股东大会支持#

将系统内存映射为 EGM 不会导致任何性能问题。在 事实上，访问映射为 EGM 的远程套接字的系统内存正在进行 更快。因为，使用 EGM 可以保证流量通过 NVLink。目前， cuMemCreate 或 cudaMemPoolCreate 分配器是 通过适当的位置类型和 NUMA 标识符来支持。

4.17.1.4. 对当前 API 的内存管理扩展#

目前，EGM内存可以与虚拟内存（cuMemCreate）或 流有序内存（cudaMemPoolCreate) 分配器。用户是 负责分配物理内存并将其映射到虚拟内存 所有套接字上的内存地址空间。

注

多节点、多GPU平台需要进程间 沟通。因此我们鼓励读者看到 第4.15章.

注

我们鼓励读者阅读 CUDA 编程指南 第4.16章 和 第4.3章 为了更好的理解。

API 中添加了新的 CUDA 属性类型，以允许这些属性 使用类似 NUMA 的节点了解分配位置的方法 标识符：

CUDA类型

请参阅 CUDA驱动程序API —CUDA 运行时数据类型 查找有关 NUMA 特定 CUDA 类型的更多信息。

4.17.2. 使用 EGM 界面#

4.17.2.1. 单节点、单 GPU#

任何现有的 CUDA 主机分配器以及系统分配器 内存可用于从高带宽 C2C 中受益。对于用户来说， 本地访问就是今天的主机分配。

注

有关内存分配器和页面大小的更多信息，请参阅调优指南。

4.17.2.2. 单节点、多GPU#

在多 GPU 系统中，用户必须提供主机信息 的安置。正如我们提到的，表达这一点的自然方式 信息将通过使用 NUMA 节点 ID 和 EGM 遵循此 方法。因此，使用 cuDeviceGetAttribute 函数 用户应该能够了解最接近的 NUMA 节点 ID。 （参见 套接字标识符：它们是什么？如何访问它们？）。 然后用户可以使用VMM（Virtual Virtual Machine）来分配和管理EGM内存。 内存管理）API 或 CUDA 内存池。

4.17.2.2.1. 使用 VMM API#

使用虚拟内存管理 API 进行内存分配的第一步 是创建一个物理内存块，为 分配。请参阅 CUDA 编程指南 虚拟内存管理部分 了解更多详情。在 EGM 分配中，用户必须明确提供 CU_MEM_LOCATION_TYPE_HOST_NUMA  作为位置类型和 numaID 作为位置标识符。同样在临时股东大会中，分配必须 与平台的适当粒度保持一致。以下 代码片段显示了分配物理内存 cuMemCreate:

CUmemAllocationProp prop{};
prop.type = CU_MEM_ALLOCATION_TYPE_PINNED;
prop.location.type = CU_MEM_LOCATION_TYPE_HOST_NUMA;
prop.location.id = numaId;
size_t granularity = 0;
cuMemGetAllocationGranularity(&granularity, &prop, MEM_ALLOC_GRANULARITY_MINIMUM);
size_t padded_size = ROUND_UP(size, granularity);
CUmemGenericAllocationHandle allocHandle;
cuMemCreate(&allocHandle, padded_size, &prop, 0);

分配物理内存后，我们要预留一个地址空间 并将其映射到一个指针。这些程序没有特别股东大会特定的 变化：

CUdeviceptr dptr;
cuMemAddressReserve(&dptr, padded_size, 0, 0, 0);
cuMemMap(dptr, padded_size, 0, allocHandle, 0);

最后，用户必须显式保护映射的虚拟地址 范围。否则访问映射空间将导致崩溃。 与内存分配类似，用户必须提供 CU_MEM_LOCATION_TYPE_HOST_NUMA 作为位置类型和 numaId 作为位置标识符。以下代码片段创建 主机节点和 GPU 的访问描述符，用于提供读取和 对映射内存的写访问权限对它们两者：

CUmemAccessDesc accessDesc[2]{{}};
accessDesc[0].location.type = CU_MEM_LOCATION_TYPE_HOST_NUMA;
accessDesc[0].location.id = numaId;
accessDesc[0].flags = CU_MEM_ACCESS_FLAGS_PROT_READWRITE;
accessDesc[1].location.type = CU_MEM_LOCATION_TYPE_DEVICE;
accessDesc[1].location.id = currentDev;
accessDesc[1].flags = CU_MEM_ACCESS_FLAGS_PROT_READWRITE;
cuMemSetAccess(dptr, size, accessDesc, 2);

4.17.2.2.2. 使用 CUDA 内存池#

为了定义EGM，用户可以在节点上创建一个内存池并给出 访问同行。在这种情况下，用户必须明确定义 cudaMemLocationTypeHostNuma 作为位置类型和 numaId 作为位置标识符。以下代码片段显示创建一个 内存池 cudaMemPoolCreate:

cudaSetDevice(homeDevice);
cudaMemPoolProps props{};
props.allocType = cudaMemAllocationTypePinned;
props.location.type = cudaMemLocationTypeHostNuma;
props.location.id = numaId;
cudaMemPoolCreate(&memPool, &props);

此外，对于直接连接对等访问，还可以使用 现有的对等访问 API， cudaMemPoolSetAccess。一个例子 对于一个 accessingDevice 如下面的代码片段所示：

cudaMemAccessDesc desc{};
desc.flags = cudaMemAccessFlagsProtReadWrite;
desc.location.type = cudaMemLocationTypeDevice;
desc.location.id = accessingDevice;
cudaMemPoolSetAccess(memPool, &desc, 1);

当创建内存池并给出访问权限时，用户可以 将创建的内存池设置为 residentDevice 并开始分配 内存使用 cudaMallocAsync:

cudaDeviceSetMemPool(residentDevice, memPool);
cudaMallocAsync(&ptr, size, memPool, stream);

注

EGM 映射有 2MB 页面。因此，用户可能会遇到更多的TLB 访问非常大的分配时会丢失。

4.17.2.3. 多节点、多GPU#

除了内存分配之外，远程对等访问没有 EGM 特定的 修改并遵循 CUDA 进程间 (IPC) 协议。参见 CUDA warp 有关 IPC 的更多详细信息。

用户应该使用分配内存 cuMemCreate 再次 用户必须明确提供 CU_MEM_LOCATION_TYPE_HOST_NUMA 作为 位置类型和 numaID 作为位置标识符。在 加法 CU_MEM_HANDLE_TYPE_FABRIC 应定义为 请求的句柄类型。下面的代码片段显示了分配 节点 A 上的物理内存：

CUmemAllocationProp prop{};
prop.type = CU_MEM_ALLOCATION_TYPE_PINNED;
prop.requestedHandleTypes = CU_MEM_HANDLE_TYPE_FABRIC;
prop.location.type = CU_MEM_LOCATION_TYPE_HOST_NUMA;
prop.location.id = numaId;
size_t granularity = 0;
cuMemGetAllocationGranularity(&granularity, &prop,
                              MEM_ALLOC_GRANULARITY_MINIMUM);
size_t padded_size = ROUND_UP(size, granularity);
size_t page_size = ...;
assert(padded_size % page_size == 0);
CUmemGenericAllocationHandle allocHandle;
cuMemCreate(&allocHandle, padded_size, &prop, 0);

使用创建分配句柄后 cuMemCreate 用户可以 将该句柄导出到另一个节点（节点 B），调用 cuMemExportToShareableHandle:

cuMemExportToShareableHandle(&fabricHandle, allocHandle,
                             CU_MEM_HANDLE_TYPE_FABRIC, 0);
// 此时，fabricHandle 应该通过 TCP/IP 发送到 Node B。

在节点 B 上，可以使用以下命令导入句柄 cuMemImportFromShareableHandle 并像任何其他织物一样处理 手柄

// 此时，应该通过 TCP/IP 从节点 A 接收 FabricHandle。
CUmemGenericAllocationHandle allocHandle;
cuMemImportFromShareableHandle(&allocHandle, &fabricHandle,
                               CU_MEM_HANDLE_TYPE_FABRIC);

当在节点B导入句柄时，用户可以保留一个地址 空间并以常规方式在本地映射它：

size_t granularity = 0;
cuMemGetAllocationGranularity(&granularity, &prop,
                              MEM_ALLOC_GRANULARITY_MINIMUM);
size_t padded_size = ROUND_UP(size, granularity);
size_t page_size = ...;
assert(padded_size % page_size == 0);
CUdeviceptr dptr;
cuMemAddressReserve(&dptr, padded_size, 0, 0, 0);
cuMemMap(dptr, padded_size, 0, allocHandle, 0);

作为最后一步，用户应该给予每个 节点 B 的本地 GPU。示例代码片段给出了读取和 对八个本地 GPU 的写访问：

// 向所有 8 个本地 GPU 授予对位于节点 A 上导出的 EGM 内存的访问权限。
CUmemAccessDesc accessDesc[8];
for (int i = 0; i < 8; i++) {
   accessDesc[i].location.type = CU_MEM_LOCATION_TYPE_DEVICE;
   accessDesc[i].location.id = i;
   accessDesc[i].flags = CU_MEM_ACCESS_FLAGS_PROT_READWRITE;
}
cuMemSetAccess(dptr, size, accessDesc, 8);
