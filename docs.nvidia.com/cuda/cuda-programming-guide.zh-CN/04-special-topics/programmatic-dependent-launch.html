4.5. 程序化依赖启动与同步#

程序化依赖启动 机制允许依赖 secondary 内核 之前启动 primary 它所依赖的同一个 CUDA 流中的内核已完成执行。 从计算能力 9.0 的设备开始可用，该技术可以提供性能 的好处时 secondary 内核可以完成不依赖于结果的重要工作 primary kernel.

4.5.1. 背景#

CUDA 应用程序通过在 GPU 上启动和执行多个内核来利用 GPU。 典型的 GPU 活动时间线如图所示 图39.

在这里， secondary_kernel 之后推出 primary_kernel 完成其执行。 串行执行通常是必要的，因为 secondary_kernel 取决于结果数据 生产者 primary_kernel. If secondary_kernel 不依赖于 primary_kernel, 它们都可以通过使用同时启动 CUDA 流。 即使 secondary_kernel 取决于 primary_kernel, 有一定的潜力 并发执行。例如，几乎所有内核都有 某种 preamble 在此期间执行诸如清零缓冲区或加载之类的任务的部分 执行恒定值。

图40 演示了的部分 secondary_kernel 那可以 并发执行而不影响应用程序。 请注意，并发启动还允许我们隐藏启动延迟 secondary_kernel 后面 的执行 primary_kernel.

并发启动和执行 secondary_kernel 显示在 图41 是 使用可实现 程序化依赖启动.

程序化依赖启动 引入了对 CUDA 内核启动 API 的更改，如下节所述。 这些 API 至少需要 9.0 的计算能力才能提供重叠执行。

4.5.2. 接口说明#

在程序化依赖启动中，主内核和辅助内核在同一 CUDA 流中启动。 主内核应该执行 cudaTriggerProgrammaticLaunchCompletion 与所有线程块时 它已准备好启动辅助内核。辅助内核必须使用可扩展启动 API 启动，如图所示。

__global__ void primary_kernel() {
   // 启动辅助内核之前应完成的初始工作

   // 触发二级内核
   cudaTriggerProgrammaticLaunchCompletion();

   // 可以与辅助内核重合的工作
}

__global__ void secondary_kernel()
{
   // 独立工作

   // 将阻塞，直到辅助内核所依赖的所有主内核都已完成并将结果刷新到全局内存
   cudaGridDependencySynchronize();

   // 依赖工作
}

cudaLaunchAttribute attribute[1];
attribute[0].id = cudaLaunchAttributeProgrammaticStreamSerialization;
attribute[0].val.programmaticStreamSerializationAllowed = 1;
configSecondary.attrs = attribute;
configSecondary.numAttrs = 1;

primary_kernel<<<grid_dim, block_dim, 0, stream>>>();
cudaLaunchKernelEx(&configSecondary, secondary_kernel);

当使用辅助内核启动时 cudaLaunchAttributeProgrammaticStreamSerialization 属性， CUDA 驱动程序可以安全地提前启动辅助内核，而不是等待 在启动辅助数据库之前完成主数据库的完成和内存刷新。

当所有主线程块启动并执行后，CUDA 驱动程序可以启动辅助内核 cudaTriggerProgrammaticLaunchCompletion。 如果主内核不执行触发器，它会隐式发生在 主内核中的所有线程块都会退出。

在任何一种情况下，辅助线程块都可能启动 在主内核写入的数据可见之前。因此，当辅助内核配置为 程序化依赖启动, 它必须始终使用 cudaGridDependencySynchronize 或其他方式来验证来自主设备的结果数据是否可用。

请注意，这些方法为主内核和辅助内核提供了同时执行的机会，但是 这种行为是机会主义的，并不能保证导致并发内核执行。 以这种方式依赖并发执行是不安全的，并且可能导致死锁。

4.5.3. 在 CUDA 图表中使用#

程序化依赖启动可用于 CUDA 图形 via 流捕获 或 直接通过 边缘数据。要在具有边缘数据的 CUDA 图中对此功能进行编程，请使用 cudaGraphDependencyType 的值 cudaGraphDependencyTypeProgrammatic 在连接两个内核节点的边上。这种边缘类型使得上游内核 对 a 可见 cudaGridDependencySynchronize() 在下游内核中。此类型必须与传出端口一起使用 要么 cudaGraphKernelNodePortLaunchCompletion 或 cudaGraphKernelNodePortProgrammatic.
