4.15. 进程间通信#

由不同管理的多个 GPU 之间的通信 主机进程通过使用来支持 进程间通信 (IPC) API 和 IPC 可共享内存缓冲区， 通过创建随后用于的过程可移植句柄 获取指向对等 GPU 上的设备内存的进程本地设备指针。

主机线程创建的任何设备内存指针或事件句柄都可以由同一进程中的任何其他线程直接引用。 但是，设备指针或事件句柄在创建它们的进程之外无效，因此不能由属于不同进程的线程直接引用。 要跨进程访问设备内存和 CUDA 事件，应用程序必须使用 CUDA 进程间通信 (IPC) 或虚拟内存管理 API 来创建进程可移植句柄，这些句柄可以使用标准主机操作系统 IPC 机制（例如进程间共享内存或文件）与其他进程共享。 一旦在进程之间交换了进程可移植句柄，就必须使用 CUDA IPC 或 VMM API 从句柄中获取进程本地设备指针。 然后可以像在单个进程中一样使用进程本地设备指针。

与 IPC 中使用的便携式手柄方法相同 单节点、单一操作系统实例 也用于点对点通信 在多节点 NVLink 连接的集群中的 GPU 之间。 在多节点情况下，通信 GPU 由运行的进程管理 在每个集群节点上的独立操作系统实例中， 需要操作系统实例级别之上的额外抽象。 多节点对等通信是通过创建和交换来实现的 多节点 GPU 对等体之间所谓的“结构”处理，以及 然后获取参与的进程本地设备指针 进程和操作系统实例对应 到多节点行列。

请参阅下面（单节点 CUDA IPC）和参考：：virtual-memory-management 为了 用于建立和交换过程可移植和 用于获取节点和操作系统实例可移植句柄 用于 GPU 通信的进程本地设备指针。

注

用于 IPC 时，使用 CUDA IPC API 和虚拟内存管理 (VMM) API 存在各自的优点和限制。

目前仅 Linux 平台支持 CUDA IPC API。

CUDA 虚拟内存管理 API 允许按分配控制 内存分配时的对等可访问性和共享，但需要使用 CUDA 驱动程序 API。

4.15.1. 使用传统进程间通信 API 的 IPC#

要跨进程共享设备内存指针和事件，应用程序必须使用 CUDA 进程间通信 API，参考手册中对此进行了详细描述。 IPC API 允许应用程序使用以下命令获取给定设备内存指针的 IPC 句柄 cudaIpcGetMemHandle()。 可以使用标准主机操作系统 IPC 机制（例如进程间共享内存或文件）将 CUDA IPC 句柄传递给另一个进程。 cudaIpcOpenMemHandle() 使用 IPC 句柄检索可在其他进程中使用的有效设备指针。 可以使用类似的入口点共享事件句柄。

使用 IPC API 的一个示例是，单个主进程生成一批输入数据，使数据可供多个辅助进程使用，而无需重新生成或复制。

注

IPC API 仅在 Linux 上受支持。

请注意，IPC API 不支持 cudaMallocManaged allocations.

使用 CUDA IPC 相互通信的应用程序应使用相同的 CUDA 驱动程序和运行时进行编译、链接和运行。

分配由 cudaMalloc() 出于性能原因，可能会从较大的内存块中进行子分配。在这种情况下，CUDA IPC API 将共享整个底层内存块，这可能会导致其他子分配被共享，从而可能导致进程之间的信息泄露。为了防止这种行为，建议仅共享 2MiB 对齐大小的分配。

具有 7.x 及更高计算能力的 L4T 和嵌入式 Linux Tegra 设备仅支持 IPC 事件共享 API。 Tegra 平台不支持 IPC 内存共享 API。

4.15.2. 使用虚拟内存管理 API 的 IPC#

CUDA 虚拟内存管理 API 允许创建 IPC可共享内存分配，支持多种操作 系统凭借操作系统特定的 IPC 处理数据结构。
