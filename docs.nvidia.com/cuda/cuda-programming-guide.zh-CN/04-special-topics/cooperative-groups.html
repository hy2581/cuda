4.4. 协作组#

4.4.1. 引言#

协作组是 CUDA 编程模型的扩展，用于组织协作线程组。 协作组允许开发人员控制线程协作的粒度，帮助他们表达更丰富、更高效的并行分解。 合作组还提供常见并行原语的实现，例如扫描和并行化简。

从历史上看，CUDA 编程模型提供了一个用于同步协作线程的单一、简单的构造：线程块的所有线程之间的屏障，如通过 __syncthreads() 内在功能。 为了表达更广泛的并行交互模式，许多面向性能的程序员诉诸于编写自己的临时且不安全的原语，以在单个 warp 内或跨在单个 GPU 上运行的线程块集之间同步线程。 虽然所实现的性能改进通常很有价值，但这导致了脆弱代码的不断增加，随着时间的推移和跨代 GPU 的编写、调整和维护成本高昂。 合作组为编写高性能代码提供了安全且面向未来的机制。

完整的合作组 API 可在 合作组API.

4.4.2. 协作组处理及成员功能#

合作组通过合作组句柄进行管理。 协作组句柄允许参与线程了解它们在组中的位置、组大小和其他组信息。 选择组成员功能如下表所示。

表10 选择会员功能#

Accessor

返回值

thread_rank()

调用线程的等级。

num_threads()

组中的线程总数。

thread_index()

已启动块内线程的 3 维索引。

dim_threads()

已启动块的 3D 尺寸（以线程为单位）。

成员函数的完整列表可在 合作组API.

4.4.3. 默认行为/无组执行#

表示网格和线程块的组是根据内核启动配置隐式创建的。 这些“隐式”组提供了一个起点，开发人员可以将其显式分解为更细粒度的组。 可以使用以下方法访问隐式组：

表11 CUDA 运行时隐式创建的协作组#

Accessor

集团范围

this_thread_block()

返回包含当前线程块中所有线程的组的句柄。

this_grid()

返回包含网格中所有线程的组的句柄。

coalesced_threads() [1]

返回warp 中一组当前活动线程的句柄。

this_cluster() [2]

返回当前集群中一组线程的句柄。
[1]

coalesced_threads() 运算符返回该时间点的活动线程集，并且不保证返回哪些线程（只要它们是活动的）或它们在整个执行过程中保持合并。

[2]

this_cluster() 当启动非集群网格时，假定为 1x1x1 集群。需要计算能力 9.0 或更高。

更多信息可在 合作组API.

4.4.3.1. 尽早创建隐式组句柄#

为了获得最佳性能，建议您预先（尽早，在发生任何分支之前）为隐式组创建一个句柄，并在整个内核中使用该句柄。

4.4.3.2. 仅通过引用传递组句柄#

建议您在将组句柄传递到函数时通过引用函数来传递组句柄。 组句柄必须在声明时初始化，因为没有默认构造函数。 不鼓励复制构造组句柄。

4.4.4. 创建合作组#

组是通过将父组划分为子组来创建的。 当对组进行分区时，将创建组句柄来管理生成的子组。 开发者可以进行以下分区操作：

表12 协作组分区操作#

分区类型

warp

tiled_partition

将父组划分为一系列以一维、行优先格式排列的固定大小的子组。

stride_partition

将父组划分为大小相等的子组，其中线程以循环方式分配给子组。

labeled_partition

根据条件标签将父组划分为一维子组，条件标签可以是任何整数类型。

binary_partition

标签分区的特殊形式，其中标签只能是“0”或“1”。

以下示例显示了如何创建平铺分区：

namespace cg = cooperative_groups;
// 获取当前线程的协作组
cg::thread_block my_group = cg::this_thread_block();

// 将合作组划分为大小为 8 的图块
cg::thread_block_tile<8> my_subgroup = cg::tiled_partition<8>(cta);

// 作为 my_subgroup 工作

使用的最佳分区策略取决于上下文。更多信息可在 合作组API.

4.4.4.1. 避免群体创建的危险#

对组进行分区是一项集体操作，组中的所有线程都必须参与。 如果该组是在并非所有线程都到达的条件分支中创建的，则可能会导致死锁或数据损坏。

4.4.5. 同步#

在引入协作组之前，CUDA 编程模型仅允许在内核完成边界处的线程块之间进行同步。 协作组允许开发人员以不同的粒度同步协作线程组。

4.4.5.1. 同步#

您可以通过调用集合来同步群组 sync() 功能。喜欢 __syncthreads(), 的 sync() 函数做出以下保证： - 同步点之前组中的线程进行的所有内存访问（例如，读取和写入）对于同步点之后组中的所有线程都是可见的。 - 在任何线程被允许继续超越同步点之前，组中的所有线程都到达同步点。

以下示例显示了一个 cooperative_groups::sync() 这相当于 __syncthreads().

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

// 同步块中的线程
cg::sync(my_group);

协作组可用于同步整个网格。从 CUDA 13 开始，协作组不能再用于多设备同步。 详细信息请参阅 大型团体 一节。

有关同步的更多信息，请参阅 合作组API.

4.4.5.2. 屏障#

Cooperative Groups 提供了一个类似于 Barrier API cuda::barrier 可用于更高级的同步。 合作团体屏障 API 不同于 cuda::barrier 主要体现在以下几个方面： - 合作团体障碍自动初始化 - 每个阶段组中的所有线程必须到达屏障并等待一次。 - barrier_arrive 返回一个 arrival_token 必须传入相应的对象 barrier_wait，它被消耗并且不能再次使用。

程序员在使用合作组障碍时必须注意避免危险： - 呼叫后，组之间不能使用集体操作 barrier_arrive 在打电话之前 barrier_wait. - barrier_wait 只保证组中的所有线程都已调用 barrier_arrive. barrier_wait 不保证所有线程都已调用 barrier_wait.

namespace cg = cooperative_groups;

cg::thread_block my_group = this_block();

auto token = cluster.barrier_arrive();

// 可选：进行一些本地处理以隐藏同步延迟
local_processing(block);

// 在访问 dsmem 之前，确保集群中的所有其他块正在运行并初始化共享数据
cluster.barrier_wait(std::move(token));

4.4.6. 集体行动#

协作组包括一组可由一组线程执行的集体操作。 这些操作需要指定组中的所有线程的参与才能完成操作。

组中的所有线程必须将相应参数的相同值传递给每个集体调用，除非在 合作组API。 否则，调用的行为是未定义的。

4.4.6.1. 归约#

reduce 函数用于对指定组中每个线程提供的数据执行并行归约。 必须通过提供下表中所示的运算符之一来指定归约类型。

表13 合作团体归约算子#

Operator

返回值

plus

组中所有值的总和

less

最小值

greater

最大值

bit_and

按位与减少

bit_or

按位或减少

bit_xor

按位异或减少

硬件加速用于在可用时进行缩减（需要计算能力 8.0 或更高版本）。 软件回退可用于硬件加速不可用的旧硬件。 只有4B类型是通过硬件加速的。

有关减少的更多信息，请参阅 合作组API.

下面的例子展示了如何使用 cooperative_groups::reduce() 执行块范围的总和减少。

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[threadIdx.x];

int sum = cg::reduce(cta, val, cg::plus<int>());

// 存储归约结果
if (my_group.thread_rank() == 0) {
   result[blockIdx.x] = sum;
}

4.4.6.2. 扫描#

合作组包括实施 inclusive_scan 或 exclusive_scan 可以用于任意大小的组。 这些函数对指定组中指定的每个线程提供的数据执行扫描操作。

程序员可以选择指定一个归约运算符，如所列 归约运算符表 above.

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[my_group.thread_rank()];

int exclusive_sum = cg::exclusive_scan(my_group, val, cg::plus<int>());

result[my_group.thread_rank()] = exclusive_sum;

有关扫描的更多信息，请参阅 合作组扫描API.

4.4.6.3. 调用一#

合作团体提供 invoke_one 当单个线程必须代表组执行串行部分工作时使用的函数。 - invoke_one 从调用组中选择一个任意线程，并使用该线程使用提供的参数调用提供的可调用函数。 - invoke_one_broadcast 是一样的 invoke_one 除了调用的结果也会广播到组中的所有线程。

线程选择机制不保证是确定性的。

下面的例子展示了基本的 invoke_one utilization.

namespace cg = cooperative_groups;
cg::thread_block my_group = cg::this_thread_block();

// 确保线程块中只有一个线程打印消息
cg::invoke_one(my_group, []() {
   printf("Hello from one thread in the block!");
});

// 同步以确保所有线程等待直到消息被打印
cg::sync(my_group);

可调用函数内部不允许调用组内的通信或同步。 允许与调用组之外的线程进行通信。

4.4.7. 异步数据移动#

合作团体 memcpy_async CUDA 中的功能提供了一种在全局内存和共享内存之间执行异步内存复制的方法。 memcpy_async 对于优化内存传输以及将计算与数据传输重叠以提高性能特别有用。

memcpy_async 函数用于启动从全局内存到共享内存的异步加载。 memcpy_async 旨在像“预取”一样使用，在需要数据之前加载数据。

wait 函数强制组中的所有线程等待，直到异步内存传输完成。 wait 必须由组中的所有线程调用，然后才能访问共享内存中的数据。

下面的例子展示了如何使用 memcpy_async 或 wait 预取数据。

namespace cg = cooperative_groups;

cg::thread_group my_group = cg::this_thread_block();

__shared__ int shared_data[];

// 执行从全局内存到共享内存的异步复制
cg::memcpy_async(my_group, shared_data + my_group.rank(), input + my_group.rank(), sizeof(int));

// 通过在这里工作来隐藏延迟。无法使用共享数据

// 等待异步复制完成
cg::wait(my_group);

// 预取数据现已可用

请参阅 合作组API 了解更多信息。

4.4.7.1. Memcpy 异步对齐要求#

memcpy_async 仅当源是全局内存且目标是共享内存并且两者至少是 4 字节对齐时才异步。 为了获得最佳性能：建议共享内存和全局内存都采用 16 字节对齐。

4.4.8. 大型团体#

合作组允许跨越整个网格的大型组。 前面描述的所有合作组功能都可供这些大型组使用，但有一个值得注意的例外： 同步整个网格需要使用 cudaLaunchCooperativeKernel 运行时启动 API。

自 CUDA 13 起，多设备启动 API 和合作组的相关参考已被删除。

4.4.8.1. 何时使用 cudaLaunchCooperativeKernel#

cudaLaunchCooperativeKernel 是一个 CUDA 运行时 API 函数，用于启动采用协作组的单设备内核，专门为执行需要块间同步的内核而设计。 该功能确保内核中的所有线程都可以在整个网格上同步和协作，而这对于仅允许在各个线程块内同步的传统 CUDA 内核来说是不可能的。 cudaLaunchCooperativeKernel 确保内核启动是原子的，即如果 API 调用成功，则提供的线程块数量将在指定设备上启动。

最好首先通过查询设备属性来确保设备支持协作启动 cudaDevAttrCooperativeLaunch:

int dev = 0;
int supportsCoopLaunch = 0;
cudaDeviceGetAttribute(&supportsCoopLaunch, cudaDevAttrCooperativeLaunch, dev);

这将设置 supportsCoopLaunch 如果设备 0 支持该属性，则为 1。仅支持计算能力为 6.0 及更高的设备。此外，您需要运行以下任意一个：

  • 没有 MPS 的 Linux 平台

  • 具有 MPS 且计算能力为 7.0 或更高的设备上的 Linux 平台

  • 最新的Windows平台
