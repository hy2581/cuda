4.4. 协作组#

4.4.1. 引言#

协作组是 CUDA 编程模型的一项扩展，用于组织彼此协作的线程组。协作组允许开发人员控制线程协作的粒度，帮助他们表达更丰富、更高效的并行分解。协作组还提供了常见并行原语的实现，例如扫描和并行归约。

在历史上，CUDA 编程模型只提供了一种简单的协作线程同步结构：线程块内所有线程之间的屏障，也就是通过 __syncthreads() 内建函数实现的同步。为了表达更广泛的并行交互模式，许多注重性能的程序员不得不编写临时且不安全的原语，用于在单个 warp 内，或在同一 GPU 上运行的一组线程块之间同步线程。虽然这些做法常常能带来有价值的性能提升，但也会产生越来越多脆弱的代码；这些代码在不同 GPU 代际之间编写、调优和维护的成本都很高。协作组提供了一种安全且面向未来的机制，用于编写高性能代码。

完整的协作组 API 可参见 协作组 API。

4.4.2. 协作组句柄和成员函数#

协作组通过协作组句柄进行管理。协作组句柄允许参与线程获知自己在组中的位置、组的大小以及其他组信息。下表列出了一部分组成员函数。

表10 部分成员函数#

访问器

返回值

thread_rank()

调用线程在组中的序号。

num_threads()

组中的线程总数。

thread_index()

线程在已启动线程块内的三维索引。

dim_threads()

已启动线程块的三维尺寸，以线程为单位。

成员函数的完整列表可参见 协作组 API。

4.4.3. 默认行为 / 无组执行#

表示网格和线程块的组会根据内核启动配置隐式创建。这些“隐式”组提供了一个起点，开发人员可以显式地把它们分解为更细粒度的组。可以使用以下方法访问隐式组：

表11 CUDA 运行时隐式创建的协作组#

访问器

组范围

this_thread_block()

返回一个组句柄，该组包含当前线程块中的所有线程。

this_grid()

返回一个组句柄，该组包含网格中的所有线程。

coalesced_threads() [1]

返回一个组句柄，该组包含某个 warp 中当前处于活动状态的一组线程。

this_cluster() [2]

返回一个组句柄，该组包含当前集群中的一组线程。
[1]

coalesced_threads() 操作符会返回该时刻的活动线程集合；它不保证具体返回哪些线程（只要这些线程处于活动状态），也不保证这些线程会在整个执行期间保持合并状态。

[2]

启动非集群网格时，this_cluster() 会假定集群大小为 1x1x1。该函数需要计算能力 9.0 或更高版本。

更多信息可参见 协作组 API。

4.4.3.1. 尽早创建隐式组句柄#

为了获得最佳性能，建议在一开始就为隐式组创建句柄（越早越好，最好在发生任何分支之前），并在整个内核中使用该句柄。

4.4.3.2. 仅通过引用传递组句柄#

把组句柄传入函数时，建议通过引用传递。组句柄必须在声明时初始化，因为它没有默认构造函数。不建议对组句柄进行拷贝构造。

4.4.4. 创建协作组#

组是通过把父组划分为子组来创建的。对组进行分区时，会创建一个组句柄来管理生成的子组。开发人员可以使用以下分区操作：

表12 协作组分区操作#

分区类型

说明

tiled_partition

将父组划分为一系列固定大小的子组，这些子组按一维行优先格式排列。

stride_partition

将父组划分为大小相等的子组，其中线程以循环方式分配给子组。

labeled_partition

根据条件标签将父组划分为一维子组；条件标签可以是任意整数类型。

binary_partition

标签分区的一种专用形式，其中标签只能是“0”或“1”。

下面的示例展示如何创建 tile 分区：

namespace cg = cooperative_groups;
// 获取当前线程的协作组
cg::thread_block my_group = cg::this_thread_block();

// 将协作组划分为大小为 8 的 tile
cg::thread_block_tile<8> my_subgroup = cg::tiled_partition<8>(cta);

// 作为 my_subgroup 执行工作

最适合使用哪种分区策略取决于具体上下文。更多信息可参见 协作组 API。

4.4.4.1. 避免组创建隐患#

对组进行分区是一项集体操作，组中的所有线程都必须参与。如果在并非所有线程都会到达的条件分支中创建组，就可能导致死锁或数据损坏。

4.4.5. 同步#

在引入协作组之前，CUDA 编程模型只允许在线程块之间以内核完成边界为同步点进行同步。协作组允许开发人员以不同粒度同步协作线程组。

4.4.5.1. sync#

可以通过调用集体函数 sync() 来同步一个组。与 __syncthreads() 类似，sync() 函数提供以下保证： - 组中线程在同步点之前执行的所有内存访问（例如读取和写入），在同步点之后对组中所有线程可见。 - 组中的所有线程都会到达同步点，然后才允许任何线程继续越过该同步点。

下面的示例展示了一个等价于 __syncthreads() 的 cooperative_groups::sync()。

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

// 同步块中的线程
cg::sync(my_group);

协作组可用于同步整个网格。从 CUDA 13 起，协作组不能再用于多设备同步。详情请参见 大规模组 一节。

有关同步的更多信息，请参见 协作组 API。

4.4.5.2. 屏障#

协作组提供了一个类似于 cuda::barrier 的屏障 API，可用于更高级的同步。协作组屏障 API 与 cuda::barrier 在几个关键方面不同： - 协作组屏障会自动初始化。 - 每个阶段中，组内所有线程都必须到达屏障并等待一次。 - barrier_arrive 会返回一个 arrival_token 对象，该对象必须传入对应的 barrier_wait；它会在等待时被消耗，之后不能再次使用。

使用协作组屏障时，程序员必须注意避免以下隐患： - 一个组在调用 barrier_arrive 之后、调用 barrier_wait 之前，不能使用集体操作。 - barrier_wait 只保证组内所有线程都已经调用 barrier_arrive。barrier_wait 不保证所有线程都已经调用 barrier_wait。

namespace cg = cooperative_groups;

cg::thread_block my_group = this_block();

auto token = cluster.barrier_arrive();

// 可选：进行一些本地处理以隐藏同步延迟
local_processing(block);

// 在访问 dsmem 之前，确保集群中的所有其他块都已运行并初始化共享数据
cluster.barrier_wait(std::move(token));

4.4.6. 集体操作#

协作组包含一组可由线程组执行的集体操作。这些操作需要指定组中的所有线程都参与，才能完成。

除非 协作组 API 明确允许不同值，否则组中的所有线程都必须为每个集体调用的对应参数传入相同值。否则，该调用的行为未定义。

4.4.6.1. 归约#

reduce 函数用于对指定组中每个线程提供的数据执行并行归约。必须通过提供下表中的某个运算符来指定归约类型。

表13 协作组归约运算符#

运算符

返回值

plus

组中所有值的总和

less

最小值

greater

最大值

bit_and

按位与归约

bit_or

按位或归约

bit_xor

按位异或归约

在可用时，归约会使用硬件加速（需要计算能力 8.0 或更高版本）。对于不支持硬件加速的旧硬件，则会使用软件回退。只有 4 字节类型会获得硬件加速。

有关归约的更多信息，请参见 协作组 API。

下面的示例展示如何使用 cooperative_groups::reduce() 执行线程块范围的求和归约。

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[threadIdx.x];

int sum = cg::reduce(cta, val, cg::plus<int>());

// 存储归约结果
if (my_group.thread_rank() == 0) {
   result[blockIdx.x] = sum;
}

4.4.6.2. 扫描#

协作组包含 inclusive_scan 和 exclusive_scan 的实现，可用于任意大小的组。这些函数会对指定组中每个线程提供的数据执行扫描操作。

程序员可以选择指定归约运算符，如上面的 归约运算符表 所列。

namespace cg = cooperative_groups;

cg::thread_block my_group = cg::this_thread_block();

int val = data[my_group.thread_rank()];

int exclusive_sum = cg::exclusive_scan(my_group, val, cg::plus<int>());

result[my_group.thread_rank()] = exclusive_sum;

有关扫描的更多信息，请参见 协作组扫描 API。

4.4.6.3. 单线程调用#

当单个线程必须代表组执行某段串行工作时，协作组提供了可使用的 invoke_one 函数。 - invoke_one 会从调用组中任意选择一个线程，并由该线程使用传入参数调用传入的可调用函数。 - invoke_one_broadcast 与 invoke_one 相同，但还会把调用结果广播给组中的所有线程。

线程选择机制不保证是确定性的。

下面的示例展示 invoke_one 的基本用法。

namespace cg = cooperative_groups;
cg::thread_block my_group = cg::this_thread_block();

// 确保线程块中只有一个线程打印消息
cg::invoke_one(my_group, []() {
   printf("Hello from one thread in the block!");
});

// 执行同步，确保所有线程都等待消息打印完成
cg::sync(my_group);

可调用函数内部不允许与调用组内的线程进行通信或同步。允许与调用组之外的线程通信。

4.4.7. 异步数据移动#

CUDA 协作组中的 memcpy_async 提供了一种在全局内存和共享内存之间执行异步内存拷贝的方法。memcpy_async 对优化内存传输，以及通过重叠计算和数据传输来提升性能特别有用。

memcpy_async 函数用于启动一次从全局内存到共享内存的异步加载。memcpy_async 预期像“预取”一样使用，也就是在真正需要数据之前先加载数据。

wait 函数会强制组中的所有线程等待，直到异步内存传输完成。必须由组中的所有线程调用 wait，之后才能访问共享内存中的数据。

下面的示例展示如何使用 memcpy_async 和 wait 预取数据。

namespace cg = cooperative_groups;

cg::thread_group my_group = cg::this_thread_block();

__shared__ int shared_data[];

// 执行从全局内存到共享内存的异步拷贝
cg::memcpy_async(my_group, shared_data + my_group.rank(), input + my_group.rank(), sizeof(int));

// 在这里执行其他工作以隐藏延迟。此时不能使用 shared_data

// 等待异步复制完成
cg::wait(my_group);

// 预取的数据现在已经可用

更多信息请参见 协作组 API。

4.4.7.1. memcpy_async 对齐要求#

只有当源为全局内存、目标为共享内存，并且两者都至少按 4 字节对齐时，memcpy_async 才是异步的。为了获得最佳性能，建议共享内存和全局内存都按 16 字节对齐。

4.4.8. 大规模组#

协作组允许创建跨越整个网格的大规模组。前面介绍的所有协作组功能都可用于这些大规模组，但有一个重要例外：同步整个网格需要使用 cudaLaunchCooperativeKernel 运行时启动 API。

从 CUDA 13 起，多设备启动 API 以及协作组中的相关引用已被移除。

4.4.8.1. 何时使用 cudaLaunchCooperativeKernel#

cudaLaunchCooperativeKernel 是一个 CUDA 运行时 API 函数，用于启动采用协作组的单设备内核，专门面向需要块间同步的内核执行场景。该函数确保内核中的所有线程都可以在整个网格范围内同步和协作；传统 CUDA 内核只允许在各个线程块内部同步，无法做到这一点。cudaLaunchCooperativeKernel 会保证内核启动是原子的，也就是说，如果 API 调用成功，则给定数量的线程块都会在指定设备上启动。

良好的做法是先查询 cudaDevAttrCooperativeLaunch 设备属性，确认设备支持协作启动：

int dev = 0;
int supportsCoopLaunch = 0;
cudaDeviceGetAttribute(&supportsCoopLaunch, cudaDevAttrCooperativeLaunch, dev);

如果设备 0 支持该属性，这会把 supportsCoopLaunch 设置为 1。仅支持计算能力 6.0 及更高版本的设备。此外，还需要运行在以下平台之一：

  • 没有 MPS 的 Linux 平台

  • 具有 MPS 且计算能力为 7.0 或更高的设备上的 Linux 平台

  • 最新的 Windows 平台
