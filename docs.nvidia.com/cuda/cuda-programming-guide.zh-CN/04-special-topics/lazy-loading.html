4.7. 延迟加载#

4.7.1. 引言#

延迟加载会等到需要时才加载 CUDA 模块，从而缩短程序初始化时间。对于只使用其所包含少量内核的程序，延迟加载尤其有效；这类情况在使用库时很常见。按照 CUDA 编程模型编写程序时，延迟加载的设计目标是对用户透明。潜在风险 对此有更详细的说明。从 CUDA 12.3 开始，所有平台默认启用延迟加载，但可以通过 CUDA_MODULE_LOADING 环境变量控制。

4.7.2. 变更历史#

表17 按 CUDA 版本列出的部分延迟加载变更#

CUDA 版本

变更

12.3

延迟加载性能得到改进。现在 Windows 默认启用。

12.2

Linux 默认启用延迟加载。

11.7

首次引入延迟加载，默认禁用。

4.7.3. 延迟加载的要求#

延迟加载是 CUDA 运行时和驱动程序共同提供的功能。只有同时满足运行时和驱动程序的版本要求时，延迟加载才可用。

4.7.3.1. CUDA 运行时版本要求#

从 CUDA 运行时 11.7 开始可以使用延迟加载。由于 CUDA 运行时通常会静态链接到程序和库中，因此只有来自 CUDA 11.7+ 工具包，或使用 CUDA 11.7+ 工具包编译的程序和库，才能从延迟加载中受益。使用较旧 CUDA 运行时版本编译的库会立即加载所有模块。

4.7.3.2. CUDA 驱动程序版本要求#

延迟加载需要驱动程序版本 515 或更高版本。对于早于 515 的驱动程序版本，即使使用 CUDA 工具包 11.7 或更高版本，也无法使用延迟加载。

4.7.3.3. 编译器要求#

延迟加载不需要任何编译器支持。使用 11.7 之前编译器生成的 SASS 和 PTX 都可以在启用延迟加载的情况下加载，并且可以获得该功能的全部收益。不过，如上所述，仍然需要 11.7+ 版本的 CUDA 运行时。

4.7.3.4. 内核要求#

延迟加载不会影响包含托管变量的模块；这些模块仍会立即加载。

4.7.4. 用法#

4.7.4.1. 启用和禁用#

将 CUDA_MODULE_LOADING 环境变量设置为 LAZY 即可启用延迟加载；设置为 EAGER 则可禁用延迟加载。从 CUDA 12.3 开始，所有平台默认启用延迟加载。

4.7.4.2. 检查运行时是否启用延迟加载#

CUDA 驱动程序 API 中的 cuModuleGetLoadingMode API 可用于判断是否启用了延迟加载。请注意，运行此函数之前必须先初始化 CUDA。下面的代码片段展示了示例用法。

#include "<cuda.h>"
#include "<assert.h>"
#include "<iostream>"

int main() {
        CUmoduleLoadingMode mode;

        assert(CUDA_SUCCESS == cuInit(0));
        assert(CUDA_SUCCESS == cuModuleGetLoadingMode(&mode));

        std::cout << "CUDA Module Loading Mode is " << ((mode == CU_MODULE_LAZY_LOADING) ? "lazy" : "eager") << std::endl;

        return 0;
}

4.7.4.3. 在运行时强制立即加载模块#

内核和变量会自动加载，不需要显式加载。即使不执行内核，也可以通过以下方式显式加载它们：

  • cuModuleGetFunction() 函数会使模块加载到设备内存中。

  • cudaFuncGetAttributes() 函数会使内核加载到设备内存中。

注

cuModuleLoad() 不保证模块会立即加载。

4.7.5. 潜在风险#

延迟加载的设计目标是让应用程序无需任何修改即可使用它。话虽如此，仍然有一些注意事项，尤其是当应用程序没有完全遵循 CUDA 编程模型时，如下所述。

4.7.5.1. 对并发内核执行的影响#

某些程序会错误地假设并发内核执行一定得到保证。如果需要跨内核同步，而内核执行又已经被串行化，就可能发生死锁。要尽量减小延迟加载对并发内核执行的影响，请采取以下做法：

  • 在启动之前预加载希望并发执行的所有内核；或者

  • 使用 CUDA_MODULE_LOADING = EAGER 运行应用程序，强制立即加载数据，而不强制每个函数都立即加载。

4.7.5.2. 大内存分配#

延迟加载会把 CUDA 模块的内存分配从程序初始化阶段推迟到更接近执行的时间。如果应用程序在启动时就分配了全部 VRAM，CUDA 可能无法在运行时为模块分配内存。可能的解决方案包括：

  • 使用 cudaMallocAsync()，而不是使用会在启动时分配全部 VRAM 的分配器。

  • 预留一些缓冲空间，以补偿内核延迟加载带来的额外需求。

  • 在尝试初始化分配器之前，预加载程序中将要使用的所有内核。

4.7.5.3. 对性能测量的影响#

延迟加载可能会把 CUDA 模块初始化移入被测执行窗口，从而影响性能测量。为避免这种情况：

  • 测量之前至少进行一次预热迭代。

  • 启动之前预加载被基准测试的内核。
