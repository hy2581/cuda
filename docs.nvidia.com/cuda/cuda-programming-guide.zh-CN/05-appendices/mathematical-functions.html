5.5. 浮点计算#

5.5.1. 浮点简介#

自该法案通过以来 IEEE-754 标准 对于 1985 年的二进制浮点运算，几乎所有主流计算系统，包括 NVIDIA 的 CUDA 架构，都实现了该标准。 IEEE-754 标准指定了如何近似浮点运算的结果。

为了获得准确的结果并以所需的精度实现最高的性能，考虑浮点行为的许多方面非常重要。这在异构计算环境中尤其重要，其中操作在不同类型的硬件上执行。

以下各节回顾浮点计算的基本属性，并介绍融合乘加 (FMA) 运算和点积。这些示例说明了不同的实现选择如何影响准确性。

5.5.1.1. 浮点格式#

浮点格式和功能定义在 IEEE-754 标准.

该标准要求二进制浮点数据在三个字段上进行编码：

  • Sign：一位表示正数或负数。

  • Exponent：通过数字偏差对基 2 指数偏移进行编码。

  • Significand （也称为 mantissa 或 fraction)：对数字的小数值进行编码。

最新的 IEEE-754 标准定义了以下二进制格式的编码和属性：

  • 16位，也称为半精度，对应于 __half CUDA 中的数据类型。

  • 32位，也称为单精度，对应于 float C、C++ 和 CUDA 中的数据类型。

  • 64位，也称为双精度，对应于 double C、C++ 和 CUDA 中的数据类型。

  • 128位，也称为四精度，对应于 __float128 或 _Float128 CUDA 中的数据类型。

5.5.1.2. 正常值和次正常值#

任何具有既不是全零也不是全一的指数字段的浮点值被称为 normal.

浮点值的一个重要方面是最小可表示正正规数之间的巨大差距， FLT_MIN和零。这个差距比之间的差距要大得多 FLT_MIN 和第二小的正常数。

Floating-point subnormal 数字，也称为 denormals，被引入来解决这个问题。次正规浮点值用指数中的所有位设置为零且有效数中的至少一位设置来表示。次正规数是 IEEE-754 浮点标准的必需部分。

次正规数允许逐渐损失精度，作为突然四舍五入到零的替代方案。然而，次正规数的计算成本更高。因此，不需要严格精度的应用程序可以选择避免它们以提高性能。的 nvcc 编译器允许通过设置禁用次正规数 -ftz=true 选项（清零），也包含在 --use_fast_math.

5.5.1.3. 特殊值#

IEEE-754 标准为浮点数定义了三个特殊值：

Zero:

  • 数学零。

  • 请注意，浮点零有两种可能的表示形式： +0 或 -0。这与整数零的表示不同。

  • +0 == -0 评估为 true.

  • 零被编码，所有位设置为 0 在指数和有效数中。

Infinity:

  • 浮点数的行为遵循饱和算术，其中溢出可表示范围的运算会导致 +Infinity 或 -Infinity.

  • 无穷大用指数中的所有位进行编码设置为 1 有效数中的所有位都设置为 0。无穷大值恰好有两种编码。

  • 涉及无穷大和有限非零值的算术运算通常会导致无穷大。不定形式如 Inf * 0.0, Inf - Inf, Inf / Inf, 和 0.0 / 0.0 结果为 NaN。

非数字 (NaN)：

  • NaN 是一个特殊符号，表示未定义或不可表示的值。常见的例子有 0.0 / 0.0, sqrt(-1.0), or +Inf - Inf.

  • NaN 使用指数中的所有位进行编码设置为 1 以及有效数中的任何位模式，除了所有设置为 0 的位之外。有 \(2^{\mathrm{尾数} + 1} - 2\) 可能的编码。

  • 任何涉及 NaN 的算术运算都将得到 NaN。

  • 任何有序比较（<, <=, >, >=, ==) 涉及 NaN 将导致 false，包括 NaN == NaN （非反射）。无序比较 NaN != NaN returns true.

  • NaN 以两种形式提供：

    • 安静的 NaN qNaN 用于传播由无效操作或值导致的错误。无效的算术运算通常会产生安静的 NaN。它们的编码方式是将有效数字的最高有效位设置为 1.

    • 发信号 NaN sNaN 旨在引发无效操作异常。信号 NaN 通常是显式创建的。它们的编码方式是将有效数字的最高有效位设置为 0.

    • Quiet 和 Signaling NaN 的确切位模式是由实现定义的。 CUDA 提供了 cuda::std::numeric_limits<T>::quiet_NaN 和 cuda::std::numeric_limits<T>::signaling_NaN 常量以获得其特殊值。

5.5.1.4. 结合律#

值得注意的是，由于浮点运算的精度有限，数学运算的规则和属性并不直接适用于浮点运算。下面的示例显示单精度值 A, B, 和 C 以及使用不同关联性计算出的总和的精确数学值。

\[\开始{分割}\开始{对齐} A &= 2^{1} \times 1.00000000000000000000001 \\ B &= 2^{0} \times 1.00000000000000000000001 \\ C &= 2^{3} \times 1.00000000000000000000001 \\ (A + B) + C &= 2^{3} \times 1.01100000000000000000001011 \\ A + (B + C) &= 2^{3} \times 1.01100000000000000000001011 \end{对齐}\end{分割}\]

从数学上来说， \((A + B) + C\) 等于 \(A + (B + C)\).

令 \(\mathrm{rn}(x)\) 表示一个舍入步骤 \(x\)。根据 IEEE-754 在单精度浮点运算中以舍入到最近模式执行相同的计算，我们得到：

\[\开始{分割}\开始{对齐} A + B &= 2^{1} \times 1.1000000000000000000000110000\ldots \\ \mathrm{rn}(A+B) &= 2^{1} \times 1.10000000000000000000010 \\ B + C &= 2^{3} \times 1.0010000000000000000000100100\ldots \\ \mathrm{rn}(B+C) &= 2^{3} \times 1.00100000000000000000001 \\ A + B + C &= 2^{3} \times 1.01100000000000000000000101100\ldots \\ \mathrm{rn}\big(\mathrm{rn}(A+B) + C\big) &= 2^{3} \times 1.01100000000000000000010 \\ \mathrm{rn}\big(A + \mathrm{rn}(B+C)\big) &= 2^{3} \times 1.01100000000000000000001 \end{对齐}\end{分割}\]

作为参考，上面还计算了精确的数学结果。根据 IEEE-754 计算的结果与精确的数学结果不同。此外，与总和相对应的结果 \(\mathrm{rn}(\mathrm{rn}(A + B) + C)\)— \(\mathrm{rn}(A + \mathrm{rn}(B + C))\) 彼此不同。在这种情况下， \(\mathrm{rn}(A + \mathrm{rn}(B + C))\) 比正确的数学结果更接近 \(\mathrm{rn}(\mathrm{rn}(A + B) + C)\).

此示例表明，即使所有基本操作都符合 IEEE-754，看似相同的计算也可能产生不同的结果。

5.5.1.5. 乘加融合 (FMA)#

融合乘加 (FMA) 运算仅通过一个舍入步骤来计算结果。如果没有 FMA，结果将需要两个舍入步骤：一个用于乘法，另一个用于加法。由于 FMA 仅使用一个舍入步骤，因此它会产生更准确的结果。

融合乘加运算对 NaN 传播的影响与两个单独的运算不同。然而，FMA NaN 处理并非在所有目标上都完全相同。具有多个 NaN 操作数的不同实现可能更喜欢安静的 NaN 或传播一个操作数的有效负载。此外，当存在多个 NaN 操作数时，IEEE-754 并不严格要求确定性的有效负载选择顺序。 NaN 也可能出现在中间计算中，例如， \(\infty \乘以0 + 1\)—\(1 \times \infty - \infty\)，产生实现定义的 NaN 有效负载。

为了清楚起见，首先考虑一个使用十进制算术的示例来说明 FMA 运算的工作原理。我们将计算 \(x^2 - 1\) 使用总共五位精度，小数点后四位。

  • For \(x = 1.0008\)，正确的数学结果是 \(x^2 - 1 = 1.60064 \乘以10^{-4}\)。仅使用小数点后四位数字的最接近的数字是 \(1.6006 \乘以10^{-4}\).

  • 融合乘加运算仅使用一个舍入步骤即可获得正确的结果 \(\mathrm{rn}(x \times x - 1) = 1.6006 \times 10^{-4}\).

  • 另一种方法是分别计算乘法和加法步骤。 \(x^2 = 1.00160064\) 翻译为 \(\mathrm{rn}(x \times x) = 1.0016\)。最终结果是 \(\mathrm{rn}(\mathrm{rn}(x \times x) -1) = 1.6000 \times 10^{-4}\).

分别对乘法和加法进行四舍五入产生的结果相差 \(0.00064\)。相应的 FMA 计算仅是错误的 \(0.00004\) 其结果最接近正确的数学答案。结果总结如下：

\[\开始{分割}\开始{对齐} x &= 1.0008 \\ x^{2} &= 1.00160064 \\ x^{2} - 1 &= 1.60064 \times 10^{-4} && \text{真值} \\ \mathrm{rn}\big(x^{2} - 1\big) &= 1.6006 \times 10^{-4} && \text{融合乘加} \\ \mathrm{rn}\big(x^{2}\big) &= 1.0016 \\ \mathrm{rn}\big(\mathrm{rn}(x^{2}) - 1\big) &= 1.6000 \times 10^{-4} && \text{相乘，然后相加} \end{对齐}\end{分割}\]

下面是另一个使用二进制单精度值的示例：

\[\开始{分割}\开始{对齐} A &= 2^{0} \times 1.00000000000000000000001 \\ B &= -2^{0} \times 1.00000000000000000000010 \\ \mathrm{rn}\big(A \times A + B\big) &= 2^{-46} \times 1.00000000000000000000000000000000 && \text{融合乘加} \\ \mathrm{rn}\big(\mathrm{rn}(A \times A) + B\big) &= 0 && \text{相乘，然后相加} \end{对齐}\end{分割}\]

  • 分别计算乘法和加法会导致所有精度位的丢失，从而产生 \(0\).

  • 另一方面，计算 FMA 提供的结果等于数学值。

融合乘法加法有助于防止减法消除期间精度损失。当大小相似但符号相反的数量相加时，就会发生减法抵消。在这种情况下，许多前导位被抵消，导致有意义的位减少。融合乘加在乘法期间计算双宽度乘积。因此，即使在加法过程中发生减法抵消，乘积中仍然有足够的有效位来产生精确的结果。

CUDA 中的融合乘加支持：

CUDA 以多种方式为两者提供融合乘加运算 float 或 double 数据类型：

  • x * y + z 当使用标志编译时 -fmad=true 或 --use_fast_math.

  • fma(x, y, z) 或 fmaf(x, y, z) C 标准库函数.

  • __fmaf_[rd, rn, ru, rz], __fmaf_ieee_[rd, rn, ru, rz], 和 __fma_[rd, rn, ru, rz] CUDA 数学内在函数.

  • cuda::std::fma(x, y, z) 或 cuda::std::fmaf(x, y, z) CUDA C++ 标准库函数.

主机平台上的融合乘加支持：

是否使用融合操作取决于该操作在平台上的可用性以及代码的编译方式。在比较 CPU 和 GPU 结果时，了解主机平台对融合乘加的支持非常重要。

  • 编译器标志和融合乘加硬件支持：

    • -mfma 和 GCC 和 Clang, -Mfma 和 NVC++, 和 /fp:contract 和 微软视觉工作室.

    • 例如，使用 AVX2 ISA 的 x86 平台，使用 -mavx2 使用 GCC 或 Clang 进行标记，以及 /arch:AVX2 与 Microsoft Visual Studio。

    • 具有高级 SIMD (Neon) ISA 的 Arm64 (AArch64) 平台。

  • fma(x, y, z) 或 fmaf(x, y, z) C 标准库函数.

  • std::fma(x, y, z) 或 std::fmaf(x, y, z) C++ 标准库函数.

  • cuda::std::fma(x, y, z) 或 cuda::std::fmaf(x, y, z) CUDA C++ 标准库函数.

5.5.1.6. 点积示例#

考虑求两个短向量点积的问题 \(\overrightarrow{a}\)—\(\overrightarrow{b}\) 两者都有四个元素。

\[\begin{split}\overrightarrow{a} = \begin{bmatrix} a_{1} \\ a_{2} \\ a_{3} \\ a_{4} \end{bmatrix} \qquad \overrightarrow{b} = \begin{bmatrix} b_{1} \\ b_{2} \\ b_{3} \\ b_{4} \end{bmatrix} \qquad \overrightarrow{a} \cdot \overrightarrow{b} = a_{1}b_{1} + a_{2}b_{2} + a_{3}b_{3} + a_{4}b_{4}\end{split}\]

示例算法 2： 使用融合乘加顺序计算点积。

5.5.1.7. 舍入#

IEEE-754 标准需要支持多种操作。其中包括算术运算，例如加法、减法、乘法、除法、平方根、乘加融合、求余、转换、缩放、符号和比较运算。对于给定格式和舍入模式，这些操作的结果保证在所有标准实现中保持一致。

舍入模式

IEEE-754 标准定义了四种舍入模式： round-to-nearest, 向积极方向转变, 向负值舍入, 和 向零舍入。 CUDA 支持所有四种模式。默认情况下，操作使用 round-to-nearest. 内在数学函数 可用于为各个操作选择其他舍入模式。

舍入模式

Interpretation

rn

四舍五入到最接近的值，连到偶数

rz

向零舍入

ru

绕向 \(\infty\)

rd

绕向 \(-\infty\)

5.5.1.8. 关于主机/设备计算精度的注意事项#

浮点计算结果的精度受多种因素影响。本节总结了在浮点计算中获得可靠结果的重要注意事项。其中一些方面已在前面的章节中进行了更详细的描述。

在比较 CPU 和 GPU 之间的结果时，这些方面也很重要。必须仔细解释主机和设备执行之间的差异。存在差异并不一定意味着 GPU 的结果不正确或者 GPU 有问题。

结合律:

有限精度的浮点加法和乘法不是 associative 因为它们通常会产生无法直接以目标格式表示的数学值，需要舍入。这些运算的评估顺序会影响舍入误差的累积方式，并可能显着改变最终结果。

乘加融合:

乘加融合 computes \(a \乘以 b + c\) 在单次操作中，可实现更高的准确性和更快的执行时间。最终结果的准确性可能会受到其使用的影响。融合乘加依赖于硬件支持，可以通过调用相关函数显式启用或通过编译器优化标志隐式启用。

Precision:

提高浮点精度可以潜在地提高结果的准确性。更高的精度可以减少重要性的损失，并能够表示更广泛的值。然而，更高精度的类型具有更低的吞吐量并且消耗更多的寄存器。此外，使用它们显式存储输入和输出会增加内存使用和数据移动。

编译器标志和优化:

所有主要编译器都提供各种优化标志来控制浮点运算的行为。

  • GCC 的最高优化级别（-O3), 铿锵 (-O3), NVCC (-O3）和 Microsoft Visual Studio（/O2) 不影响浮点语义。但是，内联、循环展开、向量化和公共子表达式消除可能会影响结果。 NVC++ 编译器还需要标志 -Kieee -Mnofma 用于符合 IEEE-754 的语义。

  • 请参阅 GCC, Clang, 微软Visual Studio编译器, nvc++, 和 Arm C/C++ 编译器 有关影响浮点行为的选项的详细信息的文档。

  • 另请参阅 nvcc 用户手册 有关专门影响 CUDA 设备代码中浮点行为的编译器标志的详细说明： -ftz, -prec-div, -prec-sqrt, -fmad, --use_fast_math。除了这些浮点选项之外，在用户程序上下文中验证其他编译器优化的效果也很重要。鼓励用户通过广泛的测试来验证其结果的正确性，并将启用优化与禁用所有设备代码优化所获得的结果进行比较；另请参阅 -G 编译器标志。

库的实现:

在 IEEE-754 标准之外定义的函数不能保证正确舍入，并且取决于实现定义的行为。因此，不同平台（包括主机、设备和不同设备架构之间）的结果可能会有所不同。

确定性结果:

确定性结果是指每次在相同的指定条件下使用相同的输入运行时计算相同的按位数字输出。这些条件包括：

  • 硬件依赖性，例如在同一 CPU 处理器或 GPU 设备上执行。

  • 编译器方面，例如编译器的版本和 编译器标志和优化.

  • 影响计算的运行时条件，例如 舍入模式 或环境变量。

  • 计算的相同输入。

  • 线程配置，包括参与计算的线程数量及其组织，例如块和网格大小。

  • 的排序 算术原子运算 取决于硬件调度，该调度在运行之间可能有所不同。

利用 CUDA 库:

CUDA 数学库, C 标准库数学函数, 和 C++ 标准库数学函数 旨在提高开发人员对常见功能的工作效率，特别是浮点数学和数字密集型例程。这些功能提供一致的高级接口，经过优化，并跨平台和边缘情况进行了广泛测试。鼓励用户充分利用这些库并避免繁琐的手动重新实现。

5.5.3. CUDA 和 IEEE-754 合规性#

所有GPU设备都遵循 IEEE 754-2019 二进制浮点运算标准，具有以下限制：

  • 没有动态可配置的舍入模式；然而，大多数操作支持多种恒定 IEEE 舍入模式，可以通过专门指定的方式进行选择 设备内在函数.

  • 没有检测浮点异常的机制，因此所有操作的行为就好像 IEEE-754 异常始终被屏蔽一样。如果发生异常事件，将传送 IEEE-754 定义的默认屏蔽响应。因此，虽然发出 NaN 信号 SNaN 支持编码，它们不发出信号并作为安静异常处理。

  • 浮点运算可能会改变输入 NaN 有效负载的位模式。绝对值和求反等运算也可能不符合 IEEE 754 要求，这可能导致 NaN 的符号以实现定义的方式更新。

为了最大限度地提高结果的可移植性，建议用户使用默认设置 nvcc 编译器的浮点选项： -ftz=false, -prec-div=true, 和 -prec-sqrt=true，并且不使用 --use_fast_math 选项。请注意，默认情况下允许浮点表达式重新关联和收缩，类似于 --fmad=true 选项。另请参阅 nvcc 用户手册 有关这些编译标志的详细说明。

IEEE-754 和 C/C++ 语言标准没有明确解决在舍入到整数值超出目标整数格式范围的情况下将浮点值转换为整数值的问题。 GPU 设备范围的钳位行为在 PTX ISA 转换指令 部分。但是，当未通过 PTX 指令直接调用超出范围的转换时，编译器优化可能会利用未指定的行为子句，从而导致未定义的行为和无效的 CUDA 程序。 CUDA Math 文档根据每个函数/内在向用户发出警告。例如，考虑 __double2int_rz() 指示。这可能与主机编译器和库实现的行为方式不同。

原子函数非规范化行为:

无论编译器标志的设置如何，原子操作在浮点非正规化方面都具有以下行为 -ftz:

  • 全局内存上的原子单精度浮点加法始终以清零模式运行，即与 PTX 等效 add.rn.ftz.f32 semantic.

  • 共享内存上的原子单精度浮点添加始终以非规范支持运行，即行为等同于 PTX add.rn.f32 semantic.

5.5.4. CUDA 和 C/C++ 合规性#

浮点异常：

与主机实现不同，设备代码中支持的数学运算符和函数不会设置全局 errno 变量或报告 浮点异常 来指示错误。因此，如果需要错误诊断机制，用户应对功能实施额外的输入和输出筛选。

浮点运算的未定义行为：

数学运算未定义行为的常见条件包括：

  • 数学运算符和函数的无效参数：

    • 使用未初始化的浮点变量。

    • 在浮点变量的生命周期之外使用它。

    • 有符号整数溢出。

    • 取消引用无效指针。

  • 浮点特定的未定义行为：

    • 将浮点值转换为结果不可表示的整数类型是未定义的行为。这还包括 NaN 和无穷大。

用户有责任确保 CUDA 程序的有效性。无效参数可能会导致未定义的行为并受到编译器优化的影响。

与整数除以零相反，浮点除以零不是未定义的行为，并且不受编译器优化的影响；相反，它是特定于实现的行为。符合以下条件的 C++ 实现 IEC-60559 (IEEE-754)，包括 CUDA，产生无穷大。请注意，无效的浮点运算会产生 NaN，不应将其误解为未定义的行为。示例包括零除以零和无穷大除以无穷大。

浮点文字可移植性：

C 和 C++ 都允许以十进制或十六进制表示法表示浮点值。十六进制浮点文字，支持 C99 和 C++17，表示科学记数法中的实值，可以精确地以 2 为基数表示。但是，这并不能保证文字将映射到目标变量中存储的实际值（请参阅下一段）。相反，十进制浮点文字可能表示无法以 2 为基数表示的数值。

根据 C++标准规则、十六进制和十进制浮点文字四舍五入到最接近的可表示值（更大或更小），以实现定义的方式选择。主机和设备之间的舍入行为可能有所不同。

float f1 = 0.5f;    // 0.5, '0.5f' 是十进制浮点文字
float f2 = 0x1p-1f; // 0.5、'0x1p-1f'是十六进制浮点文字
float f3 = 0.1f;
// f1、f2 表示为 0 01111110 00000000000000000000000
// f3 表示为 0 01111011 10011001100110011001101

同一浮点表达式的运行时和编译时计算存在以下可移植性问题：

  • 浮点表达式的运行时计算可能会受到所选舍入模式、浮点收缩 (FMA) 和重新关联编译器设置以及浮点异常的影响。请注意，CUDA 不支持浮点异常，并且 舍入模式 设置为 round-to-nearest-ties-to-even 默认情况下。可以使用选择其他舍入模式 内在函数.

  • 编译器可以对常量表达式使用更高精度的内部表示。

  • 编译器可能会执行优化，例如常量折叠、常量传播和公共子表达式消除，这可能会导致不同的最终值或比较结果。

C 标准数学库注释：

常见数学函数的主机实现映射到 C 标准数学库函数 以特定于平台的方式。这些函数由主机编译器和各自的主机提供 libm，如果有的话。

  • 主机编译器不可用的功能在 crt/math_functions.h 头文件。例如， erfinv() 在那里实施。

  • 不太常见的功能，例如 rhypot() 或 cyl_bessel_i0()，仅在设备代码中可用。

如前所述，数学函数的主机和设备实现是独立的。有关这些函数行为的更多详细信息，请参阅主机实现的文档。

5.5.9. 内在函数#

内在数学函数是其相应函数的更快且不太准确的版本 CUDA C 标准库数学函数.

  • 它们具有相同的名称，前缀为 __，例如 __sinf(x).

  • 它们仅在设备代码中可用。

  • 它们速度更快，因为它们映射到更少的本机指令。

  • 旗帜 --use_fast_math 自动翻译对应的内容 CUDA 数学 API 函数 转化为内在函数。请参阅 –use_fast_math 效果 部分了解受影响功能的完整列表。

5.5.9.1. 基本内在函数#

数学内在函数的子集允许指定舍入模式：

  • 带有后缀的函数 _rn 操作使用 四舍五入到最接近的偶数 舍入模式。

  • 带有后缀的函数 _rz 操作使用 向零舍入 舍入模式。

  • 带有后缀的函数 _ru 操作使用 向上舍入 （朝向正无穷大）舍入模式。

  • 带有后缀的函数 _rd 操作使用 向下舍入 （向负无穷大）舍入模式。

__fadd_[rn,rz,ru,rd](), __dadd_[rn,rz,ru,rd](), __fmul_[rn,rz,ru,rd](), 和 __dmul_[rn,rz,ru,rd]() 函数映射到编译器永远不会合并到的加法和乘法运算 FFMA 或 DFMA 说明。相反，从生成的加法和乘法 * 或 + 运算符通常组合成 FFMA 或 DFMA.

5.5.9.3. --use_fast_math 的影响#
