5.7. CUDA C++ 内存模型#

标准 C++ 提出了一种观点，即同步线程的成本是统一且低的。

CUDA C++ 则不同：同步线程的成本随着线程之间的距离越来越远而增加。线程间较低 在一个块内，但在多个 GPU 和 CPU 上运行的系统中的任意线程上都很高。

为了解决并不总是很低的非统一线程同步成本，CUDA C++ 扩展了标准 C++ 内存模型和并发设施 cuda:: 命名空间与 线程范围，保留语法和 默认情况下使用标准 C++ 语义。

5.7.1. 线程范围#

A 线程范围 指定可以使用同步原语相互同步的线程类型，例如 作为 cuda::atomic 和 cuda::barrier.

namespace cuda {

enum thread_scope {
  thread_scope_system,
  thread_scope_device,
  thread_scope_block,
  thread_scope_thread
};

}  // 命名空间cuda

5.7.1.1. 范围关系#

每个程序线程通过一个或多个线程作用域关系与其他程序线程相关：

  • 系统中的每个线程通过以下方式与系统中的每个其他线程相关： system 线程范围： cuda::thread_scope_system.

  • 每个 GPU 线程都与同一 CUDA 设备和同一网络中的其他 GPU 线程相关。 内存同步域 由 device 线程范围： cuda::thread_scope_device.

  • 每个 GPU 线程通过以下方式与同一 CUDA 线程块中的其他 GPU 线程相关： block 线程范围： cuda::thread_scope_block.

  • 每个线程都通过以下方式与其自身相关 thread 线程范围： cuda::thread_scope_thread.

5.7.2. 同步原语#

命名空间中的类型 std:: 或 cuda::std:: 与命名空间中的相应类型具有相同的行为 cuda:: 当实例化范围为 cuda::thread_scope_system.

5.7.3. 原子性#

原子操作在其指定的范围内是原子的，如果：

  • 它指定的范围不是 cuda::thread_scope_system, —

  • 范围是 cuda::thread_scope_system —:

    • 它影响一个物体 系统分配的内存 和 pageableMemoryAccess is 1 [0], —

    • 它影响一个物体 管理内存 和 concurrentManagedAccess is 1, —

    • 它影响一个物体 映射内存 和 hostNativeAtomicSupported is 1, —

    • 它是影响自然对齐对象的加载或存储 尺寸 1, 2, 4, 8, or 16 字节数 映射内存 [1], —

    • 它影响GPU内存中的对象，只有GPU线程访问它， —

      • cudaDeviceGetP2PAttribute (&val, cudaDevP2PAttrNativeAtomicSupported, srcDev, dstDev) 每次访问之间 srcDev 以及对象所在的 GPU， dstDev, is 1, —

      • 只有来自单个 GPU 的 GPU 线程才能同时访问它。

注

  • [0] If PageableMemoryAccessUsesHostPagetables is 0 然后对内存映射文件进行原子操作或 hugetlbfs 分配不是原子的。

  • [1] If hostNativeAtomicSupported is 0，系统范围内的原子加载或存储操作会影响 自然对齐的 16 字节宽对象 系统分配的内存 和 映射内存 需要系统 支持。 NVIDIA 不知道任何系统缺乏此支持，并且没有可用的 CUDA API 查询 检测此类系统。

欲了解更多信息 系统分配的内存, 管理内存, 映射内存, CPU 内存和 GPU 内存，请参阅本指南的相关部分。

5.7.4. 数据竞争#

Modify 介绍种族第21段 ISO/IEC IS 14882（C++ 标准） 如下：

如果程序的执行包含两个潜在并发冲突的操作，则该程序的执行包含数据竞争 其中至少有一个不是原子的 在包括执行其他操作的线程的范围内，并且两者都不是 发生在另一个之前，除了下面描述的信号处理程序的特殊情况。 任何此类数据竞争都会导致未定义的行为。 […]

Modify thread.barrier.class 第 4 段 ISO/IEC IS 的 14882（C++ 标准）如下

4、并发调用成员函数 barrier，除了它的析构函数之外，不引入数据 比赛 就像它们是原子操作一样. […]

Modify thread.latch.class 第 2 段 ISO/IEC IS 14882 的 （C++ 标准）如下：

2、并发调用成员函数 latch，除了它的析构函数之外，不引入数据 比赛 就像它们是原子操作一样. […]

Modify thread.sema.cnt 第 3 段 ISO/IEC IS 14882 的 （C++ 标准）如下：

3、并发调用成员函数 counting_semaphore，除了它的析构函数之外，不要 引入数据竞争 就像它们是原子操作一样.

Modify thread.stoptoken.intro 第 5 段 ISO/IEC IS 的 14882（C++ 标准）如下：

调用函数 request_stop, stop_requested, 和 stop_possible 不引入数据 比赛 就像它们是原子操作一样. […]

Modify 原子围栏第 2 至 4 段 ISO/IEC IS 14882（C++标准）如下：

如果存在原子操作 X 和 Y，则释放栅栏 A 与获取栅栏 B 同步，两者都在 某个原子对象 M，使得 A 在 X 之前排序，X 修改 M，Y 在 B 之前排序，并且 Y 读取值 由 X 写入或由假设的释放序列中的任何副作用写入的值，如果它是 释放操作， 每个操作（A、B、X 和 Y）指定一个范围，其中包括执行该操作的线程 互相操作.

释放栅栏 A 与原子操作 B 同步，原子操作 B 对原子对象 M 执行获取操作，如果 存在一个原子操作X，使得A在X之前排序，X修改M，并且B读取由写入的值 X 或由假设的发布序列中的任何副作用写入的值 X 如果是发布，则将成为头 操作， 每个操作（A、B 和 X）指定一个范围，其中包括相互执行的线程 操作.

作为对原子对象 M 的释放操作的原子操作 A 与获取栅栏 B 同步，如果 M 上存在一些原子操作 X，使得 X 在 B 之前排序并读取 A 或 a 写入的值 由 A 开头的释放序列中的任何副作用写入的值， 每个操作（A、B 和 X）指定 包括执行彼此操作的线程的范围.

5.7.5. 示例：消息传递#

以下示例将存储的消息传递到 x 变量由一个 块中的线程 0 到块中的线程 1 通过旗帜 f:

Initially

 
int x = 0, f = 0;

线程 0 块 0

 
x = 42;
cuda::atomic_ref<int, cuda::thread_scope_device> flag(f);
flag.store(1, memory_order_release);

线程 0 块 1

 
cuda::atomic_ref<int, cuda::thread_scope_device> flag(f);
while(flag.load(memory_order_acquire) != 1);
assert(x == 42);

在上一示例的以下变体中，两个线程 同时访问 f 没有同步的对象，其中 导致 数据竞赛，以及展品 未定义的行为:

Initially

 
int x = 0, f = 0;

线程 0 块 0

 
x = 42;
cuda::atomic_ref<int, cuda::thread_scope_block> flag(f);
flag.store(1, memory_order_release); // UB：数据竞赛

线程 0 块 1

 
cuda::atomic_ref<int, cuda::thread_scope_device> flag(f);
while(flag.load(memory_order_acquire) != 1); // UB：数据竞赛
assert(x == 42);

当内存操作开启时 f - 商店和负载 - 是 原子性，存储操作的范围是“块范围”。自从 存储由块 0 的线程 0 执行，它仅包括所有其他 块 0 的线程。但是，执行加载的线程位于块 1 中， 即，它不在执行的存储操作所包含的范围内 块 0，导致存储和加载不是“原子的”，并且 引入数据竞争。

有关更多示例，请参阅 PTX 内存一致性模型试金石 测试.
