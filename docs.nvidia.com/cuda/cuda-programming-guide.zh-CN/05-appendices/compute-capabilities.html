5.1. 计算能力#

计算设备的一般规格和功能取决于其计算能力（请参阅 计算能力和流式多处理器版本).

表29, 表30, 和 表31 显示与当前支持的每个计算功能相关的功能和技术规格。

所有 NVIDIA GPU 架构都使用小端表示法。

5.1.1. 获取GPU计算能力#

CUDA GPU计算能力 页面提供了从 NVIDIA GPU 模型到其计算能力的全面映射。

或者， nvidia-smi 工具，随提供 英伟达驱动程序，可用于获取 GPU 的计算能力。例如，以下命令将输出系统上可用的 GPU 名称和计算能力：

nvidia-smi --query-gpu=name,compute_cap

在运行时，可以使用 CUDA Runtime API 获取计算能力 cudaDeviceGetAttribute()、CUDA Driver API cuDeviceGetAttribute()，或 NVML API nvmlDeviceGetCudaComputeCapability():

#include <cuda_runtime_api.h>

int computeCapabilityMajor, computeCapabilityMinor;
cudaDeviceGetAttribute(&computeCapabilityMajor, cudaDevAttrComputeCapabilityMajor, device_id);
cudaDeviceGetAttribute(&computeCapabilityMinor, cudaDevAttrComputeCapabilityMinor, device_id);

#include <cuda.h>

int computeCapabilityMajor, computeCapabilityMinor;
cuDeviceGetAttribute(&computeCapabilityMajor, CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MAJOR, device_id);
cuDeviceGetAttribute(&computeCapabilityMinor, CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MINOR, device_id);

#include <nvml.h> // 需要与 -lnvidia-ml 链接

int computeCapabilityMajor, computeCapabilityMinor;
nvmlDeviceGetCudaComputeCapability(nvmlDevice, &computeCapabilityMajor, &computeCapabilityMinor);

5.1.2. 功能可用性#

计算架构引入的大多数计算功能旨在在所有后续架构上可用。这显示在 表29 通过“是”表示计算功能特性在引入后可用。

5.1.2.1. 特定于架构的功能#

从计算能力 9.0 的设备开始，随架构引入的专用计算功能可能无法保证在所有后续计算能力上可用。这些特征被称为 architecture-specific 专门操作（例如 Tensor Core 操作）的功能和目标加速，并不适用于所有类别的计算功能，或者可能在未来几代中发生重大变化。 代码必须使用特定于体系结构的编译器目标进行编译（请参阅 功能集编译器目标）以启用特定于体系结构的功能。使用特定于体系结构的编译器目标编译的代码只能在其编译时所针对的确切计算能力上运行。

5.1.2.2. 系列特定功能#

从计算能力 10.0 的设备开始，一些特定于体系结构的功能对于具有多种计算能力的设备是通用的。 包含这些功能的设备属于同一系列，这些功能也可以称为 family-specific 特点。 系列特定功能保证在同一系列的所有设备上可用。需要特定于系列的编译器目标才能启用特定于系列的功能。参见 第 5.1.2.3 节。为特定系列目标编译的代码只能在属于该系列成员的 GPU 上运行。

5.1.2.3. 功能集编译器目标#

编译器可以针对三组计算功能：

基线功能集：主要的计算功能集，旨在供后续计算架构使用。 这些功能及其可用性总结在 表29.

特定于架构的功能集：一组小型且高度专业化的功能，称为特定于架构的功能，引入这些功能是为了加速专用操作，这些操作不能保证可用，或者可能在后续计算架构上发生重大变化。 这些功能在相应的“计算能力#.#”小节中进行了总结。 特定于体系结构的功能集是特定于系列的功能集的超集。 特定于架构的编译器目标是随 Compute Capability 9.0 设备一起引入的，并通过使用 a 编译目标中的后缀，例如通过指定 compute_100a 或 compute_120a 作为计算目标。

系列特定功能集：一些特定于架构的功能对于具有多种计算能力的 GPU 是通用的。这些功能在相应的“计算能力#.#”小节中进行了总结。除少数例外，具有相同主要计算能力的新一代设备都属于同一系列。 表28 指示特定于系列的目标与设备计算功能的兼容性，包括例外。系列特定功能集是基线功能集的超集。 特定于系列的编译器目标是随 Compute Capability 10.0 器件引入的，并通过使用 f 编译目标中的后缀，例如通过指定 compute_100f 或 compute_120f 作为计算目标。

从计算能力 9.0 开始的所有设备都具有一组特定于体系结构的功能。要在特定 GPU 上利用完整的这些功能集，特定于体系结构的编译器目标带有后缀 a 必须使用。此外，从计算能力 10.0 开始，在具有不同次要计算能力的多个设备中出现了一些功能集。这些指令集称为系列特定功能，共享这些功能的设备被称为同一系列的一部分。系列特定功能是该 GPU 系列所有成员共享的特定架构功能的子集。带有后缀的特定于系列的编译器目标 f 允许编译器生成使用特定于体系结构的功能的公共子集的代码。

例如：

  • compute_100 编译目标不允许使用特定于体系结构的功能。 该目标将与计算能力 10.0 及更高版本的所有设备兼容。

  • compute_100f family-specific 编译目标允许使用 GPU 系列中常见的架构特定功能的子集。该目标仅与属于 GPU 系列的设备兼容。本例中兼容Compute Capability 10.0和Compute Capability 10.3的设备。系列特定的可用功能 compute_100f 目标是基线中可用功能的超集 compute_100 target.

  • compute_100a architecture-specific 编译目标允许在 Compute Capability 10.0 设备中使用整套特定于架构的功能。该目标仅与计算能力 10.0 的设备兼容，不与其他设备兼容。中可用的功能 compute_100a 目标形成了可用功能的超集 compute_100f target.
