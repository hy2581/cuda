5.3. C++ 语言支持#

nvcc 根据以下规范处理 CUDA 和设备代码：

  • C++03 （ISO/IEC 14882:2003）， --std=c++03 标志。

  • C++11 （ISO/IEC 14882:2011）， --std=c++11 标志。

  • C++14 （ISO/IEC 14882:2014）， --std=c++14 标志。

  • C++17 （ISO/IEC 14882:2017）， --std=c++17 标志。

  • C++20 （ISO/IEC 14882:2020）， --std=c++20 标志。

向 nvcc 传入 -std=c++<version> 标志会启用与指定版本相关的所有 C++ 功能，并使用相应的 C++ 方言选项调用主机预处理器、编译器和链接器。

编译器支持受支持标准的所有语言功能，但须遵守以下各节中报告的限制。

5.3.5. CUDA C++ 标准库#

CUDA 提供了 C++ 标准库 (STL) 的实现，称为 libcu++。该库具有以下优点：

  • 这些功能在主机和设备上均可用。

  • 兼容所有 Linux 和 Windows CUDA 工具包支持的平台。

  • 兼容所有 GPU架构 受 CUDA 工具包的最新两个主要版本支持。

  • 兼容所有 CUDA工具包 与当前和以前的主要版本。

  • 提供最新标准版本中可用的 C++ 标准库功能的 C++17 向后移植，包括 C++20、C++23 和 C++26。

  • 支持扩展数据类型，例如128位整数（__int128), 半精度浮点数 (__half), Bfloat16 (__nv_bfloat16）和四精度浮点数（__float128).

  • 针对设备代码进行了高度优化。

此外， libcu++ 还提供 C++ 标准库中没有的 扩展功能，可提高生产力和应用程序性能。这些功能包括数学函数、内存操作、同步原语、容器扩展、CUDA 内在函数的高级抽象、C++ PTX 包装器等。

libcu++ 既作为 CUDA 工具包 的一部分提供，也作为开源 CCCL 仓库的一部分提供。

5.3.6. C 标准库函数#

5.3.6.1. clock() 或 clock64()#

__host__ __device__ clock_t   clock();
__device__          long long clock64();

当在设备代码中执行时，它返回每个多处理器计数器的值，该计数器在每个时钟周期递增。在内核的开始和结束处对该计数器进行采样，减去这两个值，并记录每个线程的结果，从而提供设备执行该线程所花费的时钟周期数的估计值。但是，该值并不代表设备执行线程指令所花费的实际时钟周期数。前一个数字大于后一个数字，因为线程是按时间分片的。

Hint

  • 相应的 CUDA C++ 函数 cuda::std::clock() 中提供了 <cuda/std/ctime> 头文件。

  • 出于类似目的，还提供了 <cuda/std/chrono> 头文件，作为便携式 C++ <chrono> 的实现。

5.3.6.2. printf()#

int printf(const char* format[, arg, ...]);

该函数将格式化的输出从内核打印到主机端输出流。

内核内 printf() 函数的行为与标准 C 库类似 printf() 功能。用户应参阅其主机系统的手册页以获取完整的描述 printf() 行为。本质上，传入的字符串为 format 输出到主机上的流。

printf() 命令的执行方式与任何其他设备端函数类似：每个线程并在调用线程的上下文中执行。在多线程内核中，直接调用 printf() 将由每个线程使用该线程指定的数据执行。因此，输出字符串的多个版本将出现在主机流中，每个版本对应于遇到该字符串的线程。 printf().

与C标准不同 printf()，返回打印的字符数，CUDA 的 printf() 返回已解析的参数数量。如果格式字符串后面没有参数，则返回 0。如果格式字符串是 NULL, -1 被返回。如果发生内部错误，则返回-2。

在内部， printf() 使用共享数据结构，因此可以调用 printf() 可能会改变线程的执行顺序。特别是，调用的线程 printf() 可能比不调用的线程需要更长的执行路径 printf()，该路径的长度取决于参数 printf()。但是，请注意，除了显式的情况外，CUDA 不保证线程执行的顺序。 __syncthreads() 障碍。因此，无法判断执行顺序是否已被修改 printf() 或通过硬件中的其他调度行为。

格式说明符

至于标准 printf()，格式说明符采用以下形式： %[flags][width][.precision][size]type

支持以下字段。有关所有行为的完整描述，请参阅广泛可用的文档。

  • Flags: #, ' ', 0, +, -

  • Width: *, 0-9

  • Precision: 0-9

  • Size: h, l, ll

  • Type: %cdiouxXpeEfgGaAs

Limitations

最终的格式 printf() 输出发生在主机系统上。这意味着格式字符串必须被主机系统的编译器和 C 库理解。虽然已尽一切努力确保 CUDA 支持的格式说明符 printf() 函数是最常见主机编译器支持的通用子集，确切的行为将取决于主机操作系统。

printf() 接受标志和类型的所有有效组合。这是因为它无法确定什么在最终输出格式化的主机系统上有效，什么无效。因此，如果程序发出包含无效组合的格式字符串，则输出可能是未定义的。

printf() 除了格式字符串之外，函数最多可接受 32 个参数。任何附加参数都将被忽略，格式说明符将按原样输出。

由于尺寸不同 long 在 Windows 平台（32 位）和 Linux 平台（64 位）上键入，在 Linux 计算机上编译然后在 Windows 计算机上运行的内核将为所有格式字符串生成损坏的输出，其中包括 %ld。为了保证安全，建议编译平台和执行平台匹配。

主机端缓冲区

输出缓冲器为 printf() 在内核启动之前设置为固定大小。缓冲区是循环的，因此如果内核执行期间产生的输出多于缓冲区所能容纳的输出，则旧的输出将被覆盖。仅当执行以下操作之一时才会刷新缓冲区：

  • 内核启动通过 <<< >>> 或 cuLaunchKernel()：在启动开始时，如果 CUDA_LAUNCH_BLOCKING 环境变量设置为1，在启动结束时也是如此，

  • 同步通过 cudaDeviceSynchronize(), cuCtxSynchronize(), cudaStreamSynchronize(), cuStreamSynchronize(), cudaEventSynchronize(), or cuEventSynchronize(),

  • 通过任何阻塞版本进行内存复制 cudaMemcpy*() 或 cuMemcpy*(),

  • 模块加载/卸载通过 cuModuleLoad() 或 cuModuleUnload(),

  • 上下文破坏通过 cudaDeviceReset() 或 cuCtxDestroy().

  • 在执行由添加的流回调之前 cudaLaunchHostFunc() 或 cuLaunchHostFunc().

请注意，程序退出时缓冲区不会自动刷新。

5.3.6.4. malloc() 或 free()#

__host__ __device__ void* malloc(size_t size);
// 或 <cuda/std/cstdlib> 标头中的 cuda::std::malloc()、cuda::std::calloc()

功能 malloc() （设备端）， cuda::std::malloc(), 和 cuda::std::calloc() 至少分配 size 从设备堆中获取字节并返回指向已分配内存的指针。如果内存不足以满足请求，则返回 NULL。返回的指针保证与 16 字节边界对齐。

__device__ void* __nv_aligned_device_malloc(size_t size, size_t align);
// 或 <cuda/std/cstdlib> 标头中的 cuda::std::aligned_alloc()

功能 __nv_aligned_device_malloc() 和 C++ cuda::std::aligned_alloc() 至少分配 size 从设备堆中获取字节并返回指向已分配内存的指针。如果没有足够的内存来满足请求的大小或对齐方式，则返回 NULL。分配的内存地址是以下的倍数 align. align 必须是非零的二的幂。

__host__ __device__ void free(void* ptr);
// 或 <cuda/std/cstdlib> 标头中的 cuda::std::free()

设备端功能 free() 或 cuda::std::free() 释放指向的内存 ptr，它必须是由之前的调用返回的 malloc(), cuda::std::malloc(), cuda::std::calloc(), __nv_aligned_device_malloc(), or cuda::std::aligned_alloc(). If ptr is NULL，调用 free() 或 cuda::std::free() 被忽略。多次致电 free() 或 cuda::std::free() 与相同的 ptr 有未定义的行为。

给定 CUDA 线程通过分配的内存 malloc(), cuda::std::malloc(), cuda::std::calloc(), __nv_aligned_device_malloc(), or cuda::std::aligned_alloc() 在 CUDA 上下文的生命周期内保持分配状态，或者直到通过调用显式释放它为止 free() 或 cuda::std::free()。此内存可供其他 CUDA 线程使用，甚至是后续内核启动的线程。任何 CUDA 线程都可以释放另一个线程分配的内存；但是，应注意确保同一指针不会被释放多次。

堆内存API

设备内存堆的大小必须在设备代码中分配或释放内存的任何程序之前指定，包括 new 或 delete 关键词。如果任何程序使用设备内存堆而未显式指定堆大小，则会分配 8 MB 的默认堆。

以下 API 函数获取和设置堆大小：

  • cudaDeviceGetLimit(size_t* size, cudaLimitMallocHeapSize)

  • cudaDeviceSetLimit(cudaLimitMallocHeapSize, size_t size)

授予的堆大小至少为 size bytes. cuCtxGetLimit() 和 cudaDeviceGetLimit() 返回当前请求的堆大小。

当模块加载到上下文中时，堆的实际内存分配就会发生，无论是通过 CUDA 驱动程序 API 显式加载（请参阅 模块）或通过 CUDA 运行时 API 隐式地进行。如果内存分配失败，模块加载会生成一个 CUDA_ERROR_SHARED_OBJECT_INIT_FAILED error.

加载模块后，堆大小无法更改，并且不会根据需要动态调整大小。

为设备堆保留的内存不包括通过主机端 CUDA API 调用分配的内存，例如 cudaMalloc().

与主机内存 API 的互操作性

通过设备端函数分配内存 malloc(), cuda::std::malloc(), cuda::std::calloc(), __nv_aligned_device_malloc(), cuda::std::aligned_alloc()，或 new 关键字不能与运行时或驱动程序 API 调用一起使用或释放，例如 cudaMalloc, cudaMemcpy, or cudaMemset。同样，通过主机运行时 API 分配的内存无法使用设备端函数释放 free(), cuda::std::free()，或 delete keyword.

每线程块分配示例：

#include <stdlib.h>

__global__ void block_level_allocation_kernel() {
    __shared__ int* data;
    // 块中的第一个线程执行分配并共享指针
    // 通过共享内存与所有其他线程进行交互，以便可以合并访问。
    if (threadIdx.x == 0) {
        size_t size = blockDim.x * 64; // 每个线程分配 64 字节。
        data = (int*) malloc(size);
    }
    __syncthreads();
    // 检查是否有故障
    if (data == nullptr)
        return;

    // 线程索引到内存中，确保合并
    for (int i = 0; i < 64; ++i)
        data[i * blockDim.x + threadIdx.x] = threadIdx.x;
    // 确保所有线程在释放之前完成
    __syncthreads();

    // 只有一个线程可以释放内存！
    if (threadIdx.x == 0)
        free(data);
}

int main() {
    cudaDeviceSetLimit(cudaLimitMallocHeapSize, 128 * 1024 * 1024);
    block_level_allocation_kernel<<<10, 128>>>();
    cudaDeviceSynchronize();
    return 0;
}

#include <stdlib.h>
#include <stdio.h>

const int NUM_BLOCKS = 20;

__device__ int* data_ptrs[NUM_BLOCKS]; // 每块指针

__global__ void allocate_memory_kernel() {
    // 只有块中的第一个线程执行分配
    // 因为我们每个块只需要一次分配。
    if (threadIdx.x == 0)
        data_ptrs[blockIdx.x] = (int*) malloc(blockDim.x * 4);
    __syncthreads();
    // 检查是否有故障
    if (data_ptrs[blockIdx.x] == nullptr)
        return;
    // 所有线程并行地清零数据
    data_ptrs[blockIdx.x][threadIdx.x] = 0;
}

// 简单示例：将线程 ID 存储到每个元素中
__global__ void use_memory_kernel() {
    int* ptr = data_ptrs[blockIdx.x];
    if (ptr != nullptr)
        ptr[threadIdx.x] += threadIdx.x;
}

// 在释放缓冲区之前打印缓冲区的内容
__global__ void free_memory_kernel() {
    int* ptr = data_ptrs[blockIdx.x];
    if (ptr != nullptr)
        printf("Block %d, Thread %d: final value = %d\n",
            blockIdx.x, threadIdx.x, ptr[threadIdx.x]);
    // 仅从一个线程中释放！
    if (threadIdx.x == 0)
        free(ptr);
}

int main() {
    cudaDeviceSetLimit(cudaLimitMallocHeapSize, 128*1024*1024);
    // 分配内存
    allocate_memory_kernel<<<NUM_BLOCKS, 10>>>();

    // 使用内存
    use_memory_kernel<<<NUM_BLOCKS, 10>>>();
    use_memory_kernel<<<NUM_BLOCKS, 10>>>();
    use_memory_kernel<<<NUM_BLOCKS, 10>>>();

    // 空闲内存
    free_memory_kernel<<<NUM_BLOCKS, 10>>>();
    cudaDeviceSynchronize();
    return 0;
}

5.3.7.2. 扩展 Lambda#

nvcc 标志 --extended-lambda 允许在 lambda 表达式中对执行空间进行显式注释。这些注释应出现在 lambda 引入符之后和可选 lambda 声明符之前。
nvcc 定义宏 __CUDACC_EXTENDED_LAMBDA__ 当 --extended-lambda 指定了标志。

  • An 扩展的拉姆达 是在直接块或嵌套块的范围内定义的 __host__ 或 __host__ __device__ function.

  • An 扩展设备 lambda 是一个 lambda 表达式，注释为 __device__ keyword.

  • An 扩展主机设备 lambda 是一个 lambda 表达式，注释为 __host__ __device__ keywords.

与标准 lambda 表达式不同，扩展 lambda 可以用作类型参数 __global__ functions.

示例：

void host_function() {
    auto lambda1 = [] {};                      // 不是扩展的 lambda：没有显式的执行空间注释
    auto lambda2 = [] __device__ {};           // 扩展的拉姆达
    auto lambda3 = [] __host__ __device__ {};  // 扩展的拉姆达
    auto lambda4 = [] __host__ {};             // 不是扩展的 lambda
}

__host__ __device__ void host_device_function() {
    auto lambda1 = [] {};                      // 不是扩展的 lambda：没有显式的执行空间注释
    auto lambda2 = [] __device__ {};           // 扩展的拉姆达
    auto lambda3 = [] __host__ __device__ {};  // 扩展的拉姆达
    auto lambda4 = [] __host__ {};             // 不是扩展的 lambda
}

__device__ void device_function() {
    // 此函数中的所有 lambda 都不是扩展 lambda，
    // 因为封闭函数不是 __host__ 或 __host__ __device__ 函数。
    auto lambda1 = [] {};
    auto lambda2 = [] __device__ {};
    auto lambda3 = [] __host__ __device__ {};
    auto lambda4 = [] __host__ {};
}

auto global_lambda = [] __host__ __device__ { }; // 不是扩展 lambda，因为它没有定义
                                                 // 在 __host__ 或 __host__ __device__ 函数内

5.3.7.3. 扩展 Lambda 类型特征#

编译器提供类型特征来在编译时检测扩展 lambda 的闭包类型。

bool __nv_is_extended_device_lambda_closure_type(type);

该函数返回 true if type 是为扩展创建的闭包类 __device__ 拉姆达, false otherwise.

bool __nv_is_extended_device_lambda_with_preserved_return_type(type);

该函数返回 true if type 是为扩展创建的闭包类 __device__ lambda 并且 lambda 是用尾随返回类型定义的， false 否则。如果尾随返回类型定义引用任何 lambda 参数名称，则不会保留返回类型。

bool __nv_is_extended_host_device_lambda_closure_type(type);

该函数返回 true if type 是为扩展创建的闭包类 __host__ __device__ 拉姆达, false otherwise.

lambda 类型特征可以在所有编译模式中使用，无论是否启用 lambda 或扩展 lambda。特质总会回归 false 如果扩展 lambda 模式未激活。

示例：

auto lambda0 = [] __host__ __device__ { };

void host_function() {
    auto lambda1 = [] { };
    auto lambda2 = [] __device__ { };
    auto lambda3 = [] __host__ __device__ { };
    auto lambda4 = [] __device__ () -> double { return 3.14; }
    auto lambda5 = [] __device__ (int x) -> decltype(&x) { return 0; }

    using lambda0_t = decltype(lambda0);
    using lambda1_t = decltype(lambda1);
    using lambda2_t = decltype(lambda2);
    using lambda3_t = decltype(lambda3);
    using lambda4_t = decltype(lambda4);
    using lambda5_t = decltype(lambda5);

    // “lambda0”不是扩展 lambda，因为它是在函数范围之外定义的
    static_assert(!__nv_is_extended_device_lambda_closure_type(lambda0_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda0_t));
    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda0_t));

    // 'lambda1' 不是扩展 lambda，因为它没有执行空间注释
    static_assert(!__nv_is_extended_device_lambda_closure_type(lambda1_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda1_t));
    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda1_t));

    // “lambda2”是扩展的仅限设备的 lambda
    static_assert(__nv_is_extended_device_lambda_closure_type(lambda2_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda2_t));
    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda2_t));

    // “lambda3”是扩展的主机设备 lambda
    static_assert(!__nv_is_extended_device_lambda_closure_type(lambda3_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda3_t));
    static_assert(__nv_is_extended_host_device_lambda_closure_type(lambda3_t));

    // 'lambda4' 是一个扩展的仅限设备的 lambda，具有保留的返回类型
    static_assert(__nv_is_extended_device_lambda_closure_type(lambda4_t));
    static_assert(__nv_is_extended_device_lambda_with_preserved_return_type(lambda4_t));
    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda4_t));

    // “lambda5”不是具有保留返回类型的扩展的仅限设备的 lambda
    // 因为它在尾随返回类型中引用了operator()的参数类型。
    static_assert(__nv_is_extended_device_lambda_closure_type(lambda5_t));
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(lambda5_t));
    static_assert(!__nv_is_extended_host_device_lambda_closure_type(lambda5_t));
}

5.3.7.4. 扩展 Lambda 限制#

在调用主机编译器之前，CUDA 编译器将扩展 lambda 表达式替换为命名空间范围中定义的占位符类型的实例。占位符类型的模板参数需要获取包含原始扩展 lambda 表达式的函数的地址。这是正确执行任何操作所必需的 __global__ 其模板参数涉及扩展 lambda 的闭包类型的函数模板。封闭函数计算如下。

根据定义，扩展 lambda 存在于 a 的直接或嵌套块范围内 __host__ 或 __host__ __device__ function.

  • 如果函数不是 operator() 对于 lambda 表达式，它被视为扩展 lambda 的封闭函数。

  • 否则，扩展 lambda 是在直接或嵌套块范围内定义的。 operator() 一个或多个封闭的 lambda 表达式。

    • 如果最外层 lambda 表达式是在函数的直接或嵌套块作用域内定义的 F，那么 F 是计算出的封闭函数。

    • 否则，封闭函数不存在。

示例：

void host_function() {
    auto lambda1 = [] __device__ { }; // lambda1 的封闭函数是“host_function()”
    auto lambda2 = [] {
        auto lambda3 = [] {
            auto lambda4 = [] __host__ __device__ { }; // lambda4 的封闭函数是“host_function”
        };
    };
}

auto global_lambda = [] {
    auto lambda5 = [] __host__ __device__ { }; // lambda5 的封闭函数不存在
};

扩展 Lambda 限制

  1. 扩展 lambda 不能在另一个扩展 lambda 表达式内定义。示例：

    void host_function() {
    auto lambda1 = [] __host__ __device__  {
         // 错误，在另一个扩展 lambda 中定义了扩展 lambda
        auto lambda2 = [] __host__ __device__ { };
    };
}

  2. 扩展 lambda 不能在通用 lambda 表达式内定义。示例：

    void host_function() {
    auto lambda1 = [] (auto) {
         // 错误，在通用 lambda 中定义的扩展 lambda
        auto lambda2 = [] __host__ __device__ { };
    };
}

  3. 如果扩展 lambda 是在一个或多个嵌套 lambda 表达式的直接或嵌套块作用域内定义的，则最外层 lambda 表达式必须在函数的直接或嵌套块作用域内定义。示例：

    auto lambda1 = []  {
    // 错误，外部封闭 lambda 未在非 lambda-operator() 函数中定义
    auto lambda2 = [] __host__ __device__ { };
};

  4. 扩展 lambda 的封闭函数必须命名，并且其地址必须可访问。如果封闭函数是类成员，则必须满足以下条件：

    • 所有包含成员函数的类都必须有一个名称。

    • 成员函数在其父类中不得具有私有或受保护的访问权限。

    • 所有封闭类在其各自的父类中不得具有私有或受保护的访问权限。

    示例：

    void host_function() {
    auto lambda1 = [] __device__ { return 0; }; // OK
    {
        auto lambda2 = [] __device__          { return 0; }; // OK
        auto lambda3 = [] __device__ __host__ { return 0; }; // OK
    }
}

struct MyStruct1 {
    MyStruct1() {
        auto lambda4 = [] __device__ { return 0; }; // 错误，无法访问封闭函数的地址
    }
};

class MyStruct2 {
    void foo() {
        auto temp1 = [] __device__ { return 10; }; // 错误，封闭函数在父类中具有私有访问权限
    }

    struct MyStruct3 {
        void foo() {
            auto temp1 = [] __device__ { return 10; };  // 错误，封闭类 MyStruct3 在其父类中具有私有访问权限
        }
    };
};

  5. 在定义扩展 lambda 时，必须能够明确地获取封闭例程的地址。但是，这可能并不总是可行，例如，当别名声明隐藏同名的模板类型参数时。例子：

    template <typename T>
struct A {
    using Bar = void;
    void test();
};

template<>
struct A<void> { };

template <typename Bar>
void A<Bar>::test() {
    // 在发送到主机编译器的代码中，nvcc 将在此处注入一个地址表达式，其形式为：
    // (void (A<Bar>::*)(void))(&A::test))
    // 然而，类 typedef 'Bar' （为 void）遮盖了模板参数 'Bar'，
    // 导致 A<int>::test 中的地址表达式实际引用：
    // (void (A<void> ::*)(void))(&A::test))
    // 它没有正确获取封闭例程 'A<int>::test' 的地址。
    auto lambda1 = [] __host__ __device__ { return 4; };
}

int main() {
    A<int> var;
    var.test();
}

  6. 扩展 lambda 不能在函数本地的类中定义。示例：

    void host_function() {
    struct MyStruct {
        void bar() {
            // 错误，bar() 是函数本地类的成员
            auto lambda2 = [] __host__ __device__ { return 0; };
        }
    };
}

  7. 扩展 lambda 的封闭函数不能具有推导的返回类型。示例：

    auto host_function() {
    // 错误，推导了host_function()的返回类型
    auto lambda3 = [] __host__ __device__ { return 0; };
}

  8. 主机设备扩展 lambda 不能是通用 lambda，即带有 auto 参数类型。示例：

    void host_function() {
    // 错误，__host__ __device__ 扩展 lambda 不能是通用 lambda
    auto lambda1 = [] __host__ __device__ (auto i) { return i; };

    // 错误，主机设备扩展 lambda 不能是通用 lambda
    auto lambda2 = [] __host__ __device__ (auto... i) {
        return sizeof...(i);
    };
}

  9. 如果封闭函数是函数或成员模板的实例化，或者函数是类模板的成员，则模板必须满足以下约束：

    • 模板最多只能有一个可变参数，并且它必须列在模板参数列表的最后。

    • 模板参数必须命名。

    • 模板实例化参数类型不能涉及函数的本地类型（扩展 lambda 的闭包类型除外），或者是 private 或 protected 班级成员。

    示例1：

    template <template <typename...> class T,
          typename... P1,
          typename... P2>
void bar1(const T<P1...>, const T<P2...>) {
    // 错误，封闭函数有多个参数包
    auto lambda = [] __device__ { return 10; };
}

template <template <typename...> class T,
          typename... P1,
          typename    T2>
void bar2(const T<P1...>, T2) {
    // 错误，对于封闭函数，参数包不是模板参数列表中的最后一个
    auto lambda = [] __device__ { return 10; };
}

template <typename T, T>
void bar3() {
    // 错误，对于封闭函数，第二个模板参数未命名
    auto lambda = [] __device__ { return 10; };
}

    示例2：

    template <typename T>
void bar4() {
    auto lambda1 = [] __device__ { return 10; };
}

class MyStruct {
    struct MyNestedStruct {};

    friend int main();
};

int main() {
    struct MyLocalStruct {};
    // 错误，bar4() 中设备 lambda 的封闭函数使用 main 本地类型实例化
    bar4<MyLocalStruct>();

    // 错误，bar4 中设备 lambda 的封闭函数已使用类型实例化
    // 这是一个类的私有成员
    bar4<MyStruct::MyNestedStruct>();
}

  10. 对于 Microsoft Visual Studio 主机编译器，封闭函数必须具有外部链接。存在此限制是因为主机编译器不支持使用非外部链接函数的地址作为模板参数。 CUDA 编译器转换需要这些地址来支持扩展 lambda。

  11. 对于 Microsoft Visual Studio 主机编译器，不应在 lambda 表达式体内定义扩展 lambda if constexpr block.

  12. 扩展 lambda 对捕获的变量有以下限制：

    • 在用于直接初始化表示扩展 lambda 的闭包类型的类类型的字段之前，该变量可以按值传递到发送到主机编译器的代码中的一系列辅助函数。然而，C++ 标准指定捕获的变量应该用于直接初始化闭包类型的字段。

    • 变量只能通过值来捕获。

    • 如果数组维数大于 7，则无法捕获数组类型的变量。

    • 对于数组类型变量，首先默认初始化闭包类型的数组字段，然后从发送到主机编译器的代码中捕获的数组变量的相应元素复制分配每个数组元素。因此，数组元素类型在主机代码中必须既可默认构造又可复制分配。

    • 无法捕获作为可变参数包元素的函数参数。

    • 捕获的变量类型不能是函数的本地变量，扩展 lambda 闭包类型除外，或者 private 或 protected 班级成员。

    • 主机设备扩展 lambda 不支持初始化捕获。但是，设备扩展 lambda 支持它，除非初始值设定项是数组或类型 std::initializer_list.

    • 扩展 lambda 的函数调用运算符不是 constexpr。扩展 lambda 的闭包类型不是文字类型。的 constexpr 或 consteval 声明扩展 lambda 时不能使用说明符。

    • 变量不能在内部隐式捕获 if-constexpr 词法嵌套在扩展 lambda 内部的块，除非该变量已在 lambda 外部隐式捕获 if-constexpr 阻止或出现在扩展 lambda 的显式捕获列表中。

    示例：

    void host_function() {
    // 正确，对于仅扩展设备的 lambda 允许进行初始化捕获
    auto lambda1 = [x = 1] __device__ () { return x; };

    // 错误，扩展主机设备 lambda 不允许进行初始化捕获
    auto lambda2 = [x = 1] __host__ __device__ () { return x; };

    int a = 1;
    // 错误，扩展的 __device__ lambda 无法通过引用捕获变量
    auto lambda3 = [&a] __device__ () { return a; };

    // 错误，仅扩展设备 lambda 不允许通过引用捕获
    auto lambda4 = [&x = a] __device__ () { return x; };

    struct MyStruct {};
    MyStruct s1;
    // 错误，函数的本地类型不能用于捕获变量的类型
    auto lambda6 = [s1] __device__ () { };

    // 错误，init-capture 不能是 std::initializer_list 类型
    auto lambda7 = [x = {11}] __device__ () { };

    std::initializer_list<int> b = {11,22,33};
    // 错误，init-capture 不能是 std::initializer_list 类型
    auto lambda8 = [x = b] __device__ () { };

    int  var     = 4;
    auto lambda9 = [=] __device__ {
        int result = 0;
        if constexpr(false) {
            // 错误，仅扩展设备的 lambda 无法在 if-constexpr 上下文中首先捕获“var”
            result += var;
        }
        return result;
    };

    auto lambda10 = [var] __device__ {
        int result = 0;
        if constexpr(false) {
            // 正确，“var”已列在扩展 lambda 的显式捕获列表中
            result += var;
        }
        return result;
    };

    auto lambda11 = [=] __device__ {
        int result = var;
        if constexpr(false) {
            // 正确，“var”已经在“if-constexpr”块之外隐式捕获
            result += var;
        }
        return result;
    };
}

  13. 解析函数时，CUDA 编译器会为函数中的每个扩展 lambda 分配一个计数器值。此计数器值用在传递给主机编译器的替换命名类型中。因此，函数中是否存在扩展 lambda 不应取决于特定的值 __CUDA_ARCH__，也不在 __CUDA_ARCH__ 未定义。示例：

    template <typename T>
__global__ void kernel(T in) { in(); }

__host__ __device__ void host_device_function() {
    // ERROR、数量及相关声明顺序
    // 扩展 lambda 依赖于 __CUDA_ARCH__
#if defined(__CUDA_ARCH__)
    auto lambda1 = [] __device__ { return 0; };
    auto lambda2 = [] __host__ __device__ { return 10; };
#endif
    auto lambda3 = [] __device__ { return 4; };
    kernel<<<1, 1>>>(lambda3);
}

  14. 如上所述，CUDA 编译器将主机函数中定义的设备扩展 lambda 替换为命名空间范围中定义的占位符类型。占位符类型没有定义 operator() 函数等价于原始 lambda 声明，除非特征 __nv_is_extended_device_lambda_with_preserved_return_type() returns true 为扩展 lambda 的闭包类型。因此，尝试确定返回类型或参数类型 operator() 这种 lambda 的函数可能在主机代码中无法正常工作，因为主机编译器处理的代码在语义上与 CUDA 编译器处理的输入代码不同。但是，内省返回类型或参数类型 operator() 设备代码中的函数是可以接受的。请注意，此限制不适用于主机或设备扩展 lambda，其特征 __nv_is_extended_device_lambda_with_preserved_return_type() returns true。示例：

    #include <cuda/std/type_traits>

const char& getRef(const char* p) { return *p; }

void foo() {
    auto lambda1 = [] __device__ { return "10"; };

    // 错误，尝试在主机代码中提取设备 lambda 的返回类型
    cuda::std::result_of<decltype(lambda1)()>::type xx1 = "abc";

    auto lambda2 = [] __host__ __device__ { return "10"; };

    // 正确，lambda2 代表主机设备扩展 lambda
    cuda::std::result_of<decltype(lambda2)()>::type xx2 = "abc";

    auto lambda3 = [] __device__ () -> const char* { return "10"; };

    // 正确，lambda3 表示具有保留返回类型的设备扩展 lambda
    cuda::std::result_of<decltype(lambda3)()>::type xx2 = "abc";
    static_assert(cuda::std::is_same_v<cuda::std::result_of<decltype(lambda3)()>::type, const char*>);

    auto lambda4 = [] __device__ (char x) -> decltype(getRef(&x)) { return 0; };
    // lambda4 的返回类型不会被保留，因为它引用了operator()的
    // 尾随返回类型中的参数类型。
    static_assert(!__nv_is_extended_device_lambda_with_preserved_return_type(decltype(lambda4)));
}

  15. 对于扩展的仅设备 lambda：

    • 自省参数类型 operator() 仅在设备代码中受支持。

    • 返回类型的自省 operator() 仅在设备代码中受支持，除非特征函数 __nv_is_extended_device_lambda_with_preserved_return_type() returns true.

  16. 如果扩展 lambda 作为参数从主机传递到设备代码 __global__ 以函数为例，那么 lambda 主体中任何捕获变量的表达式都必须保持不变，无论 __CUDA_ARCH__ 宏的定义以及它的值是什么。出现此限制是因为 lambda 的闭包类布局取决于编译器在处理 lambda 表达式时遇到捕获变量的顺序。如果设备和主机编译之间的闭包类布局不同，程序可能会错误执行。示例：

    __device__ int result;

template <typename T>
__global__ void kernel(T in) { result = in(); }

void foo(void) {
    int x1 = 1;
    // 错误，仅在定义 __CUDA_ARCH__ 时捕获“x1”。
    auto lambda1 = [=] __host__ __device__ {
#ifdef __CUDA_ARCH__
        return x1 + 1;
#else
        return 10;
#endif
    };
    kernel<<<1, 1>>>(lambda1);
}

  17. 如前所述，CUDA 编译器将发送到主机编译器的代码中的仅扩展设备 lambda 表达式替换为占位符类型实例。占位符类型在主机代码中没有定义指针到函数的转换运算符；但是，设备代码中提供了转换运算符。请注意，此限制不适用于主机设备扩展 lambda。示例：

    template <typename T>
__global__ void kernel(T in) {
    int (*fp)(double) = in;
    fp(0); // 正确，支持设备代码转换
    auto lambda1 = [](double) { return 1; };
}

void foo() {
    auto lambda_device      = [] __device__ (double) { return 1; };
    auto lambda_host_device = [] __host__ __device__ (double) { return 1; };
    kernel<<<1, 1>>>(lambda_device);
    kernel<<<1, 1>>>(lambda_host_device);

    // 正确，主机代码支持 __host__ __device__ lambda 的转换
    int (*fp1)(double) = lambda_host_device;

    // 错误，主机代码不支持设备 lambda 的转换
    int (*fp2)(double) = lambda_device;
}

  18. 如前所述，CUDA 编译器将发送到主机编译器的代码中的仅扩展设备或主机设备 lambda 表达式替换为占位符类型实例。该占位符类型可以定义 C++ 特殊成员函数，例如构造函数和析构函数。因此，对于 CUDA 前端编译器中的扩展 lambda 的闭包类型，某些标准 C++ 类型特征可能会与主机编译器中产生不同的结果。以下类型特征受到影响：： std::is_trivially_copyable, std::is_trivially_constructible, std::is_trivially_copy_constructible, std::is_trivially_move_constructible, std::is_trivially_destructible。必须小心确保这些特征的结果不会用于实例化 __global__, __device__, __constant__, or __managed__ 函数或变量模板。示例：

    #include <cstdio>
#include <type_traits>

template <bool b>
void __global__ kernel() { printf("hi"); }

template <typename T>
void kernel_launch() {
    // 错误，此内核启动可能会失败，因为 CUDA 前端编译器和主机编译器
    // 可能不同意 std::is_trivially_copyable_v 特征的结果
    // 扩展 lambda 的闭包类型
    kernel<std::is_trivially_copyable_v<T>><<<1,1>>>();
    cudaDeviceSynchronize();
}

int main() {
    int  x       = 0;
    auto lambda1 = [=] __host__ __device__ () { return x; };
    kernel_launch<decltype(lambda1)>();
}

CUDA 编译器将为中描述的部分情况生成编译器诊断信息 1-12;不会为病例生成诊断结果 13-17，但主机编译器可能无法编译生成的代码。

5.3.7.5. 主机设备 Lambda 优化说明#

与仅设备 lambda 不同，主机设备 lambda 可以从主机代码调用。如前所述，CUDA 编译器将主机代码中定义的扩展 lambda 表达式替换为命名占位符类型的实例。扩展主机设备 lambda 的占位符类型调用原始 lambda operator() 通过间接函数调用。如果扩展 lambda 模式未激活，则特征将始终返回 false。

间接函数调用的存在可能会导致主机编译器优化扩展的主机设备 lambda 少于隐式或显式的 lambda __host__ 仅。在后一种情况下，主机编译器可以轻松地将 lambda 主体内联到调用上下文中。但是，当遇到扩展的主机设备 lambda 时，主机编译器可能无法轻松内联原始 lambda 主体。

5.3.7.6. *this 按值捕获#

根据 C++11/C++14 规则，当 lambda 定义在非static 类成员函数和 lambda 的主体引用类成员变量， this 类的指针必须通过值而不是引用的成员变量来捕获。如果 lambda 是在主机函数中定义并在 GPU 上执行的仅扩展设备或主机设备 lambda，则访问 GPU 上引用的成员变量将导致运行时错误，如果 this 指针指向主机内存。

示例：

#include <cstdio>

template <typename T>
__global__ void foo(T in) { printf("value = %d\n", in()); }

struct MyStruct {
    int var;

    __host__ __device__ MyStruct() : var(10) {};

    void run() {
        auto lambda1 = [=] __device__ {
            // 对“var”的引用导致“this”指针（MyStruct*）被值捕获
            return var + 1;
        };
        // 内核启动在运行时失败，因为无法从 GPU 访问“this->var”
        foo<<<1, 1>>>(lambda1);
        cudaDeviceSynchronize();
    }
};

int main() {
    MyStruct s1;
    s1.run();
}

C++17 通过引入新的方法解决了这个问题 *this 捕捉模式。在这种模式下，编译器复制由 *this 而不是捕获 this 按值指针。的 *this 捕获模式更详细地描述在 P0018R3.

CUDA编译器支持 *this 内定义的 lambda 捕获模式 __device__ 或 __global__ 函数和主机代码中定义的扩展的仅设备 lambda，当 --extended-lambda 使用标志。

这是上面的例子修改后使用 *this 捕捉模式：

#include <cstdio>

template <typename T>
__global__ void foo(T in) { printf("\n value = %d", in()); }

struct MyStruct {
    int var;
    __host__ __device__ MyStruct() : var(10) { };

    void run() {
        // 注意“*this”捕获规范
        auto lambda1 = [=, *this] __device__ {
            // 对“var”的引用导致“*this”表示的对象被捕获
            // value，GPU代码将访问'copy_of_star_this->var'
            return var + 1;
        };
        // 内核启动成功
        foo<<<1, 1>>>(lambda1);
        cudaDeviceSynchronize();
    }
};

int main() {
    MyStruct s1;
    s1.run();
}

*this 主机代码中定义的无注释 lambda 或扩展主机设备 lambda 不允许使用捕获模式，除非 *this 捕获由所选语言方言启用。以下是支持和不支持的用法示例：

struct MyStruct {
    int var;
    __host__ __device__ MyStruct() : var(10) { };

    void host_function() {
        // 正确，在仅限扩展设备的 lambda 中使用
        auto lambda1 = [=, *this] __device__ { return var; };

        // 在扩展主机设备 lambda 中使用
        // 如果*此捕获未通过语言方言启用，则会出现错误
        auto lambda2 = [=, *this] __host__ __device__ { return var; };

        // 在宿主函数中的无注释 lambda 中使用
        // 如果*此捕获未通过语言方言启用，则会出现错误
        auto lambda3 = [=, *this]  { return var; };
    }

    __device__ void device_function() {
        // 正确，在仅设备函数中定义的 lambda 中使用
        auto lambda1 = [=, *this] __device__ { return var; };

        // 正确，在仅设备函数中定义的 lambda 中使用
        auto lambda2 = [=, *this] __host__ __device__ { return var; };

        // 正确，在仅设备函数中定义的 lambda 中使用
        auto lambda3 = [=, *this]  { return var; };
    }

    __host__ __device__ void host_device_function() {
        // 正确，在仅限扩展设备的 lambda 中使用
        auto lambda1 = [=, *this] __device__ { return var; };

        // 在扩展主机设备 lambda 中使用
        // 如果*此捕获未通过语言方言启用，则会出现错误
        auto lambda2 = [=, *this] __host__ __device__ { return var; };

        // 在主机设备函数中的未注释 lambda 中使用
        // 如果*此捕获未通过语言方言启用，则会出现错误
        auto lambda3 = [=, *this]  { return var; };
    }
};

5.3.7.7. 参数相关查找 (ADL)#

如前所述，CUDA 编译器在调用主机编译器之前将扩展 lambda 表达式替换为占位符类型。占位符类型的一个模板参数使用包含原始 lambda 表达式的函数的地址。这可能会导致额外的命名空间参与 参数相关查找 (ADL) 对于其参数类型涉及扩展 lambda 表达式的闭包类型的任何主机函数调用。因此，主机编译器可能会选择不正确的函数。

示例：

namespace N1 {

struct MyStruct {};

template <typename T>
void my_function(T);

}; // 命名空间 N1

namespace N2 {

template <typename T>
int my_function(T);

template <typename T>
void run(T in) { my_function(in); }

} // 命名空间 N2

void bar(N1::MyStruct in) {
    // 对于扩展的仅设备 lambda，发送到主机编译器的代码将替换为
    // 占位符类型实例化表达式
    // ' __nv_dl_wrapper_t< __nv_dl_tag<void (*)(N1::MyStruct in),(&bar),1>> { }'
    //
    // 因此，命名空间“N1”参与 ADL 查找
    // 在 N2::run 的主体中调用“my_function()”，导致歧义。
    auto lambda1 = [=] __device__ { };
    N2::run(lambda1);
}

在上面的示例中，CUDA 编译器将扩展 lambda 替换为涉及以下内容的占位符类型 N1 命名空间。因此， N1 命名空间参与 ADL 查找 my_function(in) 在体内 N2::run()，由于发现多个重载候选项而导致主机编译失败： N1::my_function 或 N2::my_function.

5.3.8. 多态函数包装器#

nvfunctional 头文件 提供了多态函数包装类模板， nvstd::function。此类模板的实例可以存储、复制和调用任何可调用目标，例如 lambda 表达式。 nvstd::function 可以在主机和设备代码中使用。

示例：

#include <nvfunctional>

__host__            int host_function()        { return 1; }
__device__          int device_function()      { return 2; }
__host__ __device__ int host_device_function() { return 3; }

__global__ void kernel(int* result) {
    nvstd::function<int()> fn1 = device_function;
    nvstd::function<int()> fn2 = host_device_function;
    nvstd::function<int()> fn3 = [](){ return 10; };
    *result                    = fn1() + fn2() + fn3();
}

__host__ __device__ void host_device_test(int* result) {
    nvstd::function<int()> fn1 = host_device_function;
    nvstd::function<int()> fn2 = [](){ return 10; };
    *result                    = fn1() + fn2();
}

__host__ void host_test(int* result) {
    nvstd::function<int()> fn1 = host_function;
    nvstd::function<int()> fn2 = host_device_function;
    nvstd::function<int()> fn3 = [](){ return 10; };
    *result                    = fn1() + fn2() + fn3();
}

无效情况：

  • 实例 nvstd::function 主机代码中不能使用 a 的地址进行初始化 __device__ 函数或函子，其 operator() 是一个 __device__ function.

  • 同样，实例 nvstd::function 设备代码中不能使用a的地址进行初始化 __host__ 函数或函子，其 operator() 是一个 __host__ function.

  • nvstd::function 实例无法在运行时从主机代码传递到设备代码（反之亦然）。

  • nvstd::function 不能用在 a 的参数类型中 __global__ 函数如果 __global__ 函数是从主机代码启动的。

无效案例举例：

#include <nvfunctional>

__device__ int device_function() { return 1; }
__host__   int host_function() { return 3; }
auto       lambda_host  = [] { return 0; };

__global__ void k() {
    nvstd::function<int()> fn1 = host_function; // 错误，用 __host__ 函数的地址初始化
    nvstd::function<int()> fn2 = lambda_host;   // 错误，用函子的地址初始化
                                                // __host__ 运算符() 函数
}

__global__ void kernel(nvstd::function<int()> f1) {}

void foo(void) {
    auto lambda_device = [=] __device__ { return 1; };

    nvstd::function<int()> fn1 = device_function; // 错误，用 __device__ 函数的地址初始化
    nvstd::function<int()> fn2 = lambda_device;   // 错误，用函子的地址初始化
                                                  // __device__ 运算符() 函数
    kernel<<<1, 1>>>(fn2);                        // 错误，将 nvstd::function 从主机传递到设备
}

5.3.9.4. 变量#

5.3.9.4.1. 局部变量#

__device__, __shared__, __managed__, 和 __constant__ 内存空间说明符不允许在非extern 在主机上执行的函数内的变量声明。

示例：

__host__ void host_function() {
    int x;                   // 正确，__host__ 变量
    __device__   int y;      // 错误，主机函数内的 __device__ 变量声明
    __shared__   int z;      // 错误，主机函数内的 __shared__ 变量声明
    __managed__  int w;      // 错误，主机函数内的 __managed__ 变量声明
    __constant__ int h;      // 错误，主机函数内的 __constant__ 变量声明
    extern __device__ int k; // 正确，外部 __device__ 变量
}

在设备上执行的函数内，extern 或 static 变量声明中不允许使用 __device__, __constant__, 和 __managed__ 内存空间说明符。

__device__ void device_function() {
    int x;                   // 正确，__device__ 变量
    __constant__      int y; // 错误，设备函数中的 __constant__ 变量声明
    __managed__       int z; // 错误，设备函数内的 __managed__ 变量声明
    extern __device__ int k; // 正确，外部 __device__ 变量
}

另请参阅 静态变量 一节。

5.3.9.4.2. const-限定变量#

A const- 没有内存空间注释的限定变量（__device__ 或 __constant__) 在全局、命名空间或类范围声明的被视为主变量。设备代码不能包含引用或获取变量的地址。

该变量可以直接在设备代码中使用，如果

  • 它在使用前已用常量表达式初始化，

  • 类型不是 volatile- 合格，并且

  • 它具有以下类型之一：

    • 内置积分型，或

    • 内置浮点类型，除非主机编译器是 Microsoft Visual Studio。

从C++14开始，推荐使用 constexpr 或 inline constexpr (C++17) 变量而不是 const- 合格的。 constexpr 变量不受相同类型的限制，可以直接在设备代码中使用。

__managed__ 变量不支持 const- 合格类型。

示例：

const            int   ConstVar          = 10;
const            float ConstFloatVar     = 5.0f;
inline constexpr float ConstexprFloatVar = 5.0f; // C++17

struct MyStruct {
    static const            int   ConstVar          = 20;
// 静态常量浮点 ConstFloatVar = 5.0f; // 错误，静态常量变量不能为浮点型
    static inline constexpr float ConstexprFloatVar = 5.0f; // 正确
};

extern const int ExternVar;

__device__ void foo() {
    int array1[ConstVar];                     // 正确
    int array2[MyStruct::ConstVar];           // 正确

    const     float var1 = ConstFloatVar;     // 正确，除非主机编译器是 Microsoft Visual Studio。
    constexpr float var2 = ConstexprFloatVar; // 正确
// int var3 = 外部变量；          // 错误，“ExternVar”未使用常量表达式初始化
// int& var4 = ConstVar;           // 错误，引用主机变量
// int* var5 = &ConstVar;          // 错误，主变量地址
}

5.3.9.4.3. volatile-限定变量#

注

volatile 支持关键字以保持与 ISO C++ 的兼容性。然而，即使有的话，也很少有 剩余的未弃用用途 适用于 GPU。

读取和写入 volatile- 限定对象不是原子的，并且被编译成一个或多个 易失指令 不保证：

  • 内存操作的顺序，或

  • 硬件执行的内存操作数量与 PTX 指令数量相匹配。

CUDA C++ volatile 不适合：

  • 线程间同步: 使用原子操作 cuda::atomic_ref, cuda::atomic, or 原子函数 instead.

    原子内存操作提供线程间同步保证并提供比 volatile 操作。 然而，CUDA C++ volatile 操作不提供任何线程间同步保证，因此不适合此目的。 以下示例演示如何使用原子操作在两个线程之间传递消息。

    #include <cuda/atomic>

__global__ void kernel(int* flag, int* data) {
    cuda::atomic_ref<int, cuda::thread_scope_device> atomic_ref{*flag};
    if (threadIdx.x == 0) {
        // 消费者：阻塞直到生产者设置标志，然后读取数据
        while(atomic_ref.load(cuda::memory_order_acquire) == 0)
            ;
        if (*data != 42)
            __trap(); // 如果读取错误数据，则会出现错误
    }
    else if (threadIdx.x == 1) {
        // 生产者：写入数据然后设置标志
        *data = 42;
        atomic_ref.store(1, cuda::memory_order_release);
    }
}

    #include <cuda/atomic>

__global__ void kernel(cuda::atomic<int, cuda::thread_scope_device>* flag, int* data) {
    if (threadIdx.x == 0) {
        // 消费者：阻塞直到生产者设置标志，然后读取数据
        while(flag->load(cuda::memory_order_acquire) == 0)
            ;
        if (*data != 42)
            __trap(); // 如果读取错误数据，则会出现错误
    }
    else if (threadIdx.x == 1) {
        // 生产者：写入数据然后设置标志
        *data = 42;
        flag->store(1, cuda::memory_order_release);
    }
}

    __global__ void kernel(int* flag, int* data) {
    if (threadIdx.x == 0) {
        // 消费者：阻塞直到生产者设置标志，然后读取数据
        while(atomicAdd(flag, 0) == 0)
            ;                // 通过轻松的读取-修改-写入进行加载
        __threadfence();     // 顺序一致栅栏
        if (*data != 42)
            __trap();        // 如果读取错误数据，则会出现错误
    } else if (threadIdx.x == 1) {
        // 生产者：写入数据然后设置标志
        *data = 42;
        __threadfence();     // 顺序一致栅栏
        atomicExch(flag, 1); // 以轻松的读-修改-写方式存储
    }
}

  • 内存映射IO (MMIO)：使用 PTX MMIO 操作 通过内联 PTX 代替。

    PTX MMIO 操作严格保留执行的内存访问次数。 然而，CUDA C++ volatile 操作不会保留执行的内存访问次数，并且可能会以不确定的方式执行比请求更多或更少的访问。这使得它们不适合 MMIO。 以下示例演示如何使用 PTX MMIO 操作读取和写入寄存器。

    __global__ void kernel(int* mmio_reg0, int* mmio_reg1) {
    // 写入MMIO寄存器：
    int value = 13;
    asm volatile("st.relaxed.mmio.sys.u32 [%0], %1;"
        :
        : "l"(mmio_reg0), "r"(value) : "memory");

    // 读取MMIO寄存器：
    asm volatile("ld.relaxed.mmio.sys.u32 %0, [%1];"
        : "=r"(value)
        : "l"(mmio_reg1) : "memory");

    if (value != 42)
        __trap(); // 如果读取错误数据，则会出现错误
}

5.3.9.4.4. static 变量#

在以下情况下，设备代码中允许使用 static 变量：

  • 在仅限 __global__ 或 __device__ 的函数中。

  • 在 __host__ __device__ 函数中：

    • static 没有显式内存空间的变量（自动扣除）。

    • 具有显式内存空间的 static 变量，例如 static __device__/__constant__/__shared__/__managed__，仅当 __CUDA_ARCH__ 已定义时允许。

在 __host__ __device__ 函数内的 static 变量会根据执行空间持有不同的值。

函数范围的合法和非法使用示例 static 变量如下所示。

struct TrivialStruct {

struct NonTrivialStruct {

__device__ void device_function(int x) {

    static __device__   int v5; // 正确、明确
    static __constant__ int v6; // 正确、明确
    static __shared__   int v7; // 正确、明确

    static TrivialStruct    s1;     // 正确，隐式 __device__ 内存空间说明符
    static TrivialStruct    s2{22}; // 正确，隐式 __device__ 内存空间说明符

5.3.9.4.5. extern 变量#

编译时在 整个程序编译模式, __device__, __shared__, __managed__, 和 __constant__ 不能使用外部链接来定义变量 extern keyword.

唯一的例外是动态分配 __shared__ 中描述的变量 共享内存的动态分配 一节。

__device__        int x; // OK
extern __device__ int y; // 整个程序编译模式出错
extern __shared__ int z; // OK

5.3.9.5. 函数#

5.3.9.5.1. 递归#

__global__ 函数不支持递归，而 __device__ 或 __host__ __device__ 函数没有这样的限制。

5.3.9.5.2. 外部联动#

具有外部链接的设备变量或函数需要 单独编译模式 跨多个翻译单元。

在单独编译模式下，如果 __device__ 或 __global__ 要求函数定义存在于特定的翻译单元中，那么该函数的参数和返回类型必须在该翻译单元中完整。这一概念也称为单一定义规则使用或 ODR 使用。

示例：

// 首先.cu：
struct S;                   // 前向声明
__device__ void foo(S);     // 错误，类型“S”是不完整的类型
__device__ auto* ptr = foo; // ODR-使用，地址已被占用

int main() {}

// 第二个.cu：
struct S {};               // 结构体定义
__device__ void foo(S) {}  // 函数定义

5.3.9.5.3. 形式参数#

__device__, __shared__, __managed__ 或 __constant__ 形式参数上不允许使用内存空间说明符。

void device_function1(__device__ int x) { } // 错误，__device__ 参数
void device_function2(__shared__ int x) { } // 错误，__shared__ 参数

5.3.9.5.4. __global__ 功能参数#

A __global__ 函数有以下限制：

  • 它不能有可变数量的参数，即 C 省略语法 ... 和 va_list 类型。允许 C++11 可变参数模板，但须遵守 中描述的限制 __global__ 可变参数模板 一节。

  • 函数参数通过以下方式传递到设备 常量内存 它们的总大小限制为 32,764 字节。

  • 函数参数不能通过引用传递或通过右值引用传递。

  • 函数参数不能是类型 std::initializer_list.

  • 多态类参数（virtual）被视为未定义的行为。

  • 允许使用 Lambda 表达式和闭包类型，但要遵守 中描述的限制 Lambda 表达式和 __global__ 函数参数 一节。

5.3.9.5.5. __global__ 函数参数传递#

当启动一个 __global__ function 从设备代码，每个参数必须是普通可复制和普通可破坏的。

当一个 __global__ 函数是从主机代码启动的，每个参数类型都可以是非平凡可复制或非平凡可破坏的。然而，这些类型的处理并不遵循标准 C++ 模型，如下所述。用户代码必须保证这个工作流程不会影响程序的正确性。该工作流程在两个方面与标准 C++ 不同：

  1. 原始内存复制而不是复制构造函数调用

    CUDA运行时将内核参数传递给 __global__ 通过复制原始内存内容来实现功能，最终使用 memcpy。如果参数不可简单复制并提供用户定义的复制构造函数，则在主机到设备的复制中将跳过调用的操作和副作用。

    示例：

    #include <cassert>

struct MyStruct {
    int  value = 1;
    int* ptr;

    MyStruct() = default;

    __host__ __device__ MyStruct(const MyStruct&) { ptr = &value; }
};

__global__ void device_function(MyStruct my_struct) {
    // 该断言失败，因为“my_struct”是通过复制获得的
    // 原始内存内容和复制构造函数被跳过。
    assert(my_struct.ptr == &my_struct.value); // FAIL
}

void host_function(MyStruct my_struct) {
    assert(my_struct.ptr == &my_struct.value); // 正确
}

int main() {
    MyStruct my_struct;
    host_function(my_struct);
    device_function<<<1, 1>>>(my_struct); // 仅在主机端调用复制构造函数
    cudaDeviceSynchronize();
}

    请参阅示例 编译器资源管理器.

  2. 析构函数可以在 __global__ 功能已完成

    内核启动与主机执行异步。结果，如果一个 __global__ 函数参数有一个不平凡的析构函数，该析构函数甚至可以在主机代码中执行 __global__ 函数已完成执行。这可能会破坏析构函数有副作用的程序。

    示例：

    #include <cassert>

__managed__ int var = 0;

struct MyStruct {
    __host__ __device__ ~MyStruct() { var = 3; }
};

__global__ void device_function(MyStruct my_struct) {
    assert(var == 0); // 失败，MyStruct::~MyStruct() 将值设置为 3
}

int main() {
    MyStruct my_struct;
    // GPU 内核执行与主机执行异步。
    // 结果，MyStruct::~MyStruct() 可以在之前执行
    // 内核执行完毕。
    device_function<<<1, 1>>>(my_struct);
    cudaDeviceSynchronize();
}

    请参阅示例 编译器资源管理器.

5.3.9.6. 类#

5.3.9.6.1. 类类型变量#

变量定义为 __device__, __constant__, __managed__ 或 __shared__ 内存空间不能有带有非空构造函数或非空析构函数的类类型。如果类类型的构造函数很简单或者在翻译单元中的某个点满足以下所有条件，则该构造函数被视为空：

  • 构造函数已经定义。

  • 构造函数没有参数、空的初始值设定项列表和空的复合语句函数体。

  • 它的类没有 virtual 功能， virtual 基类，或非static 数据成员初始值设定项。

  • 它的所有基类的默认构造函数都可以被认为是空的。

  • 对于所有非static 如果类的数据成员属于类类型（或其数组），则默认构造函数可以被视为空。

如果类的析构函数很简单或者在翻译单元中的某个点满足以下所有条件，则该类的析构函数被视为空：

  • 析构函数已经定义。

  • 析构函数体是一个空的复合语句。

  • 它的类没有 virtual 函数或 virtual 基类。

  • 它的所有基类的析构函数都可以被认为是空的。

  • 对于所有非static 如果类的数据成员属于类类型（或其数组），则析构函数可以被认为是空的。

5.3.9.6.2. 数据成员#

__device__, __shared__, __managed__ 或 __constant__ 不允许使用内存空间说明符 class, struct, 和 union 数据成员。

Only static 支持在编译时评估的数据成员，例如 const-qualified 和 constexpr variables.

struct MyStruct {
   static inline constexpr int value1 = 10; // C++17
   static constexpr        int value2 = 10; // C++11
   static const            int value3 = 10;
// 静态整型值4； // 错误
};

5.3.9.6.3. 职能成员#

__global__ 函数不能是 a 的成员 struct, class, or union.

A __global__ 函数允许在 friend 声明，但不能定义。

示例：

struct MyStruct {
    friend __global__ void f();   // 正确，仅限好友声明

// friend __global__ void g() {} // 错误，友元定义
};

5.3.9.6.4. 隐式声明和非虚拟显式默认函数#

隐式声明的特殊成员函数是编译器在用户未声明时为类声明的函数；显式默认函数是用户声明但用其标记的函数 = default。隐式声明或显式默认的特殊成员函数是默认构造函数、复制构造函数、移动构造函数、复制赋值运算符、移动赋值运算符和析构函数。

令 F 表示一个非virtual 在其第一个声明中隐式声明或显式默认的函数。 执行空间说明符 F 是调用它的所有函数的执行空间说明符的并集。请注意，对于此分析， __global__ 调用者将被视为 __device__ 来电者。例如：

class Base {
    int x;
public:
    __host__ __device__ Base() : x(10) {}
};

class Derived : public Base {
    int y;
};

class Other: public Base {
    int z;
};

__device__ void foo() {
    Derived D1;
    Other D2;
}

__host__ void bar() {
    Other D3;
}

在这种情况下，隐式声明的构造函数 Derived::Derived() 将被视为 __device__ 函数，因为它仅从 __device__ function foo()。隐式声明的构造函数 Other::Other() 将被视为 __host__ __device__ 函数，因为它是从两个 a 调用的 __device__ function foo() 和一个 __host__ function bar().

另外，如果 F 是一个隐式声明的 virtual 函数（例如， virtual 析构函数），每个虚函数的执行空间 D 被覆盖 F 被添加到执行空间集中 F if D 没有隐式声明。

例如：

struct Base1 {
    virtual __host__ __device__ ~Base1() {}
};

struct Derived1 : Base1 {}; // 隐式声明的虚拟析构函数
                            // ~Derived1() 具有 __host__ __device__ 执行空间说明符

struct Base2 {
    virtual __device__ ~Base2() = default;
};

struct Derived2 : Base2 {}; // 隐式声明的虚拟析构函数
                            // ~Derived2() 具有 __device__ 执行空间说明符

5.3.9.6.5. 多态类#

多态类，即具有 virtual 从其他多态类派生的函数或具有多态数据成员的函数受到以下限制：

  • 将多态对象从设备复制到主机或从主机复制到设备，包括 __global__ 函数参数是未定义的行为。

  • 被覆盖的执行空间 virtual 函数必须与基类中函数的执行空间匹配。

示例：

struct MyClass {
    virtual __host__ __device__ void f() {}
};

__global__ void kernel(MyClass my_class) {
    my_class.f(); // 未定义的行为
}

int main() {
    MyClass my_class;
    kernel<<<1, 1>>>(my_class);
    cudaDeviceSynchronize();
}

5.3.9.6.6. Windows 特定的类布局#

CUDA 编译器遵循 IA64 ABI 进行类布局，而 Microsoft Visual Studio 则不然。这可以防止主机和设备代码之间特殊对象的按位复制，如下所述。

令 T 表示指向成员类型的指针，或满足以下任一条件的类类型：

  • T 是一个 多态类

  • T 具有多个直接或间接的多重继承 空基类.

  • 所有直接和间接基类 B are empty 以及第一个字段的类型 F 或 T uses B 在其定义中，这样 B 位于定义中的偏移量 0 处 F.

类型类别 T，具有类型的基类 T，或使用类型的数据成员 T，当使用 Microsoft Visual Studio 编译时，主机和设备之间可能具有不同的类布局和大小。

将此类对象从设备复制到主机或从主机复制到设备，包括 __global__ 函数参数是未定义的行为。

5.3.9.7. 模板#

类型不能用作 a 的模板参数 __global__ 函数或 __device__/__constant__ 变量 (C++14) 如果满足以下任一条件：

  • 该类型定义在一个 __host__ 或 __host__ __device__ 功能范围。

  • 该类型是未命名的，例如匿名结构或 lambda 表达式，除非该类型是本地类型 __device__ 或 __global__ function.

  • 该类型是一个类成员 private 或 protected，除非该类是本地类 __device__ 或 __global__ function.

  • 该类型是由上述任何类型组合而成的。

template <typename T>
__global__ void kernel() {}

template <typename T>
__device__ int device_var; // C++14

struct {
    int v;
} unnamed_struct;

void host_function() {

    int data = 4;

    auto lambda = [](){};

// 内核 <decltype(unnamed_struct)><<<1, 1>>>(); // 错误，未命名类型
}

class MyClass {
private:

public:

5.3.10. C++11 限制#

5.3.10.1. inline 命名空间#

不允许在一个对象中定义以下实体之一 inline 命名空间，当在封闭命名空间中定义具有相同名称和类型签名的另一个实体时：

  • __global__ function.

  • __device__, __constant__, __managed__, __shared__ variables.

  • 具有表面或纹理类型的变量，例如 cudaSurfaceObject_t 或 cudaTextureObject_t.

示例：

__device__ int my_var; // 全球范围

inline namespace NS {

__device__ int my_var; // 命名空间范围

} // 命名空间 NS

5.3.10.2. inline 未命名的命名空间#

以下实体不能在命名空间范围内声明 inline 未命名的命名空间：

  • __global__ function.

  • __device__, __constant__, __managed__, __shared__ variables.

  • 具有表面或纹理类型的变量，例如 cudaSurfaceObject_t 或 cudaTextureObject_t.

5.3.10.3. constexpr 函数#

默认情况下，一个 constexpr 无法从具有不兼容执行空间的函数调用函数，就像标准函数一样。

  • 仅调用设备 constexpr 在主机代码生成阶段，即当 __CUDA_ARCH__ 宏未定义。示例：

    constexpr __device__ int device_function() { return 0; }

int main() {
    int x = device_function();  // 错误，从主机代码调用仅限设备的 constexpr 函数
}

  • 仅呼叫主机 constexpr 函数从一个 __device__ 或 __global__ 函数，在设备代码生成阶段，即当 __CUDA_ARCH__ 宏已定义。示例：

    constexpr int host_function() { return 0; }

__device__ void device_function() {
    int x = host_function();  // 错误，从设备代码调用仅限主机的 constexpr 函数
}

请注意，函数模板特化可能不是 constexpr function 即使相应的模板函数标有关键字 constexpr.

宽松的 constexpr-函数支持

实验的 nvcc 标志 --expt-relaxed-constexpr 可以用来放松这个约束 __host__ 或 __device__ 功能。然而，一个 __global__ 函数不能声明为 constexpr. nvcc 还将定义宏 __CUDACC_RELAXED_CONSTEXPR__.

当指定该标志时，编译器将支持上述的跨执行空间调用，如下所示：

  1. 拨打电话至 constexpr 如果交叉执行空间中的函数出现在需要不断求值的上下文中，例如 a 的初始值设定项，则支持该函数 constexpr 变量。示例：

    constexpr __host__ int host_function(int x) { return x + 1; };

__global__ void kernel() {
    constexpr int val = host_function(1); // 正确，调用是在需要不断评估的上下文中进行的。
}

constexpr __device__ int device_function(int x) { return x + 1; }

int main() {
    constexpr int val = device_function(1); // 正确，调用是在需要不断评估的上下文中进行的。
}

  2. 设备代码是在为仅主机 constexpr 函数体生成设备代码期间生成的，除非未使用或仅在 constexpr 上下文。示例：

    // 注意：“host_function”在生成的设备代码中发出，因为
// 它是从非 constexpr 上下文中的设备代码调用的
constexpr int host_function(int x) { return x + 1; }

__device__ int device_function(int in) {
    return host_function(in);  // 正确，即使参数不是常量表达式
}

  3. 适用于设备功能的所有代码限制也适用于 constexpr 从设备代码调用的仅主机函数。但是，编译器可能不会针对与编译过程相关的限制发出任何构建时诊断。

    例如，主机函数主体不支持以下代码模式。这与任何设备功能类似；但是，可能不会生成编译器诊断信息。

    • 单一定义规则 (ODR) - 使用主机变量或仅主机非constexpr 功能。示例：

      int host_var1, host_var2;

constexpr int* host_function(bool b) { return b ? &host_var1 : &host_var2; };

__device__ int device_function(bool flag) {
    return *host_function(flag); // 错误，host_function() 尝试引用主机变量
                                 // “host_var1”和“host_var2”。
                                 // 该代码将编译，但不会正确执行。
}

    • 使用例外 throw/catch 和运行时类型信息 typeid/dynamic_cast。示例：

      struct Base { };
struct Derived : public Base { };

// 注意：“host_function”在生成的设备代码中发出
constexpr int host_function(bool b, Base *ptr) {
    if (b) {
        return 1;
    }
    else if (typeid(ptr) == typeid(Derived)) { // 错误，在 GPU 上执行的代码中使用了 typeid
        return 2;
    }
    else {
        throw int{4}; // 错误，在 GPU 上执行的代码中使用了 throw
    }
}

__device__ void device_function(bool flag) {
    Derived d;
    int val = host_function(flag, &d); // 错误，host_function() 尝试使用 typeid 和 throw()，
                                       // 在 GPU 上执行的代码中不允许这样做
}

  4. 在主机代码生成期间，仅设备的主体 constexpr 函数保存在发送到主机编译器的代码中。但是，如果设备函数体尝试 ODR 使用命名空间范围的设备变量或非constexpr 设备函数，不支持从主机代码调用设备函数。虽然代码可以在没有编译器诊断的情况下构建，但它在运行时可能表现不正确。示例：

    __device__ int device_var1, device_var2;

constexpr __device__ int* device_function(bool b) { return b ? &device_var1 : &device_var2; };

int host_function(bool flag) {
    return *device_function(flag); // 错误，device_function() 尝试引用设备变量
                                   // “device_var1”和“device_var2”
                                   // 该代码将编译，但不会正确执行。
}

warp

由于上述限制以及缺乏对错误使用的编译器诊断，建议避免调用标准 C++ 头文件中的函数 std:: 来自设备代码。这些功能的实现根据主机平台的不同而有所不同。相反，强烈建议调用 CUDA C++ 标准库中的等效功能 libcu++，在 cuda::std:: namespace.

5.3.10.4. constexpr 变量#

默认情况下，一个 constexpr 与标准变量一样，变量不能在执行空间不兼容的函数中使用。

A constexpr 在以下情况下，可以在设备代码中直接使用变量：

  • C++ 标量类型，不包括指针和指向成员的指针类型：

    • nullptr_t.

    • bool.

    • 整体型： char, signed char, unsigned, long long等

    • 浮点类型： float, double.

    • Enumerators: enum 或 enum class.

  • 班级类型： class, struct, 和 union 与一个 constexpr constructor.

  • 例如上述类型的原始数组 int[]，仅当它们在内部使用时 constexpr __device__ 或 __host__ __device__ function.

constexpr __managed__ 或 constexpr __shared__ 不允许使用变量。

示例：

constexpr int ConstexprVar = 4; // 标量类型

struct MyStruct {
    static constexpr int ConstexprVar = 100;
};

constexpr MyStruct my_struct = MyStruct{}; // 班级类型

constexpr int array[] = {1, 2, 3};

__device__ constexpr int get_value(int idx) {
    return array[idx];                      // 正确
}

__device__ void foo(int idx) {
    int        v1 = ConstexprVar;           // 正确
    int        v2 = MyStruct::ConstexprVar; // 正确
// const int &v3 = ConstexprVar1;          // 错误，引用主机 constexpr 变量
// const int *v4 = &ConstexprVar1;         // 错误，主机 constexpr 变量的地址
    int        v5 = get_value(2);           // 正确，“get_value(2)”是一个常量表达式。
// int v6 = get_value(idx);         // 错误，'get_value(idx)' 不是常量表达式
// int v7 = 数组[2];               // 错误，“数组”不是标量类型。
    MyStruct   v8 = my_struct;              // 正确
}

5.3.10.6. 默认功能 = default#

CUDA 编译器推断显式默认成员函数的执行空间，如中所述 隐式声明和显式默认函数.

显式默认函数上的执行空间说明符会被编译器忽略，除非该函数是外联定义的或者是一个 virtual function.

示例：

struct MyStruct1 {

};

void host_function() {
    MyStruct1 my_struct; // __host__ __device__ 构造函数
}

__device__ void device_function() {
    MyStruct1 my_struct; // __host__ __device__ 构造函数
}

struct MyStruct2 {
    __device__ MyStruct2() = default; // 警告：忽略 __device__ 注释
};

struct MyStruct3 {
    __host__ MyStruct3();
};
MyStruct3::MyStruct3() = default; // 超出范围的定义，不被忽略

__device__ void device_function2() {
// MyStruct3 my_struct； // 错误，__host__ 构造函数

struct MyStruct4 {

    virtual __host__ ~MyStruct4() = default;
};

__device__ void device_function3() {
    MyStruct4 my_struct4;
    // 'my_struct4' 的隐式析构函数调用：
    // 错误：从 __device__ 函数“device_function3”调用
    // __host__ 函数 'MyStruct4::~MyStruct4'
}

5.3.10.8. [cuda::]std::move, [cuda::]std::forward#

默认情况下，CUDA 编译器隐式考虑 std::move 或 std::forward 具有的函数模板 __host__ __device__ 执行空间说明符，因此可以直接从设备代码调用它们。的 nvcc 标志 --no-host-device-move-forward 禁用此行为； std::move 或 std::forward 然后将被视为 __host__ 函数，并且不能直接从设备代码调用。

Hint

cuda::std::move 或 cuda::std::forward 相反总是有 __host__ __device__ 执行空间。

5.3.11. C++14 限制#

5.3.11.1. 具有推导返回类型的函数#

A __global__ 函数不能有推导的返回类型 auto.

自省 a 的返回类型 __device__ 主机代码中不允许使用具有推导返回类型的函数。

注

CUDA 前端编译器更改函数声明以具有 void 返回类型，在调用主机编译器之前。这可能会破坏对推导的返回类型的自省 __device__ 主机代码中的函数。因此，CUDA 编译器将在设备函数体之外引用此类推导的返回类型时发出编译时错误。

示例：

 __device__ auto device_function(int x) { // 推导的返回类型
     return x;                            // decltype(auto) 具有相同的行为
 }

 __global__ void kernel() {
     int x = sizeof(device_function(2));         // 正确，设备代码范围
 }

 // const int size = sizeof(device_function(2)); // 错误，主机上的返回类型推导

 void host_function() {
 // 使用 T = decltype(device_function(2));     // 错误，主机上的返回类型推导
 }

void host_fn1() {
  // 错误，引用外部设备功能体
  int (*p1)(int) = fn1;

  struct S_local_t {
    // 错误，引用外部设备功能体
    decltype(fn2(10)) m1;

    S_local_t() : m1(10) { }
  };
}

// 错误，引用外部设备功能体
template <typename T = decltype(fn2)>
void host_fn2() { }

template<typename T> struct MyStruct { };

// 错误，引用外部设备功能体
struct S1_derived_t : MyStruct<decltype(fn1)> { };

5.3.11.2. 变量模板#

A __device__ 或 __constant__ 变量模板不能 const- 使用 Microsoft 编译器时限定。

示例：

// Windows 上的错误（不可移植），const 限定
template <typename T>
__device__ const T var = 0;

 // 正确，ptr1 不是 const 限定的
template <typename T>
__device__ const T* ptr1 = nullptr;

// Windows 上的错误（不可移植），ptr2 是 const 限定的
template <typename T>
__device__ const T* const ptr2 = nullptr;

请参阅示例 编译器资源管理器.

5.3.12. C++17 限制#

5.3.12.1. inline 变量#

在单个翻译单元中，使用 inline 变量不提供常规变量之外的附加功能，并且不提供任何实际优势。
nvcc allows inline 变量与 __device__, __constant__, or __managed__ 内存空间仅在 单独编译 模式或具有内部链接的变量。

注

使用时 gcc/g++ 主机编译器，一个 inline 声明的变量 __managed__ 内存空间说明符可能对调试器不可见。

示例：

inline        __device__ int device_var1;  // 正确，在单独编译模式下编译时（-rdc=true 或 -dc）
                                           // 在整个程序编译模式下编译时出现错误

static inline __device__ int device_var2;  // 正确，内部链接

namespace {

inline __device__ int device_var3;         // 正确，内部链接

inline __shared__ int shared_var;          // 正确，内部链接

static inline __device__ int device_var4;  // 正确，内部链接

inline __device__ int device_var5;         // 正确，内部链接

} // 名称空间

请参阅示例 编译器资源管理器.

5.3.12.2. 结构化绑定#

结构化绑定不能使用内存空间说明符来声明，例如 __device__, __shared__, __constant__, or __managed__.

示例：

struct S {
    int x, y;
};
// __device__ 自动 [a, b] = S{4, 5}; // 错误

5.3.13. C++20 限制#

5.3.13.1. 三路比较运算符#

三路比较运算符 (<=>）在设备代码中受支持，但某些使用隐式依赖于 C++ 标准库中的功能，该功能由主机实现提供。使用这些运算符可能需要指定标志 --expt-relaxed-constexpr 消除警告，并且该功能要求主机实现满足设备代码的要求。

示例：

#include <compare> // std::strong_ordering 实现

struct S {
    int x, y;

    auto operator<=>(const S&) const = default; // (a)

    __host__ __device__ bool operator<=>(int rhs) const { return false; } // (b)
};

__host__ __device__ bool host_device_function(S a, S b) {
    if (a <=> 1)  // 正确，调用用户定义的主机设备过载 (b)
        return true;
    return a < b; // 正确，调用隐式声明的函数 (a)
                  // 注意：它需要设备兼容的 std::strong_ordering
                  // 标头 <compare> 中提供的实现
                  // 和标志 --expt-relaxed-constexpr
}

请参阅示例 编译器资源管理器.

5.3.13.2. consteval 函数#

consteval 可以从主机和设备代码调用函数，与其执行空间无关。

示例：

consteval int host_consteval() {
    return 10;
}

__device__ consteval int device_consteval() {
    return 10;
}

__device__ int device_function() {
    return host_consteval();   // 正确，即使从设备代码调用
}

__host__ __device__ int host_device_function() {
    return device_function();  // 正确，即使是从主机设备代码调用
}
