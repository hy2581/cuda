5.8. CUDA C++ 执行模型#

CUDA C++ 旨在提供 并行前进 [intro.progress.9] 对于所有执行的设备线程，促进预先存在的 C++ 应用程序与 CUDA C++ 的并行化。

[intro.progress]

  • [intro.progress.7]：对于执行线程 提供 并发前进进度保证, 该实现确保线程只要没有终止，最终就会取得进展。

    [注 5：无论其他执行线程（如果有）是否已经或正在取得进展，这都适用。 最终满足这一要求意味着这将在未指定但有限的时间内发生。 ——尾注]

  • [intro.progress.9]：对于提供的执行线程 并行推进进度保证，实施不需要确保 如果线程还没有执行任何执行步骤，那么它最终将取得进展；一旦该线程执行了一个步骤， 它提供 并发前进进度保证.

    [注6：这并没有指定何时启动该执行线程的要求，这通常由实体指定 创建这个执行线程。例如，提供并发前进进度保证并执行的执行线程 一组任务中任意顺序的任务，一个接一个，满足这些任务并行前进的要求 任务。 ——尾注]

CUDA C++ 编程语言是 C++ 编程语言的扩展。 本节记录了对 [intro.progress] 当前的部分 ISO 国际标准 ISO/IEC 14882 – 编程语言 C++ 草稿。 修改的部分被显式地调用，它们的差异显示在 bold。 所有其他部分都是补充。

5.8.1. 主机线程#

由主机实现创建的执行线程提供的前进进度 执行 main, std::thread, 和 std::jthread 是主机的实现定义的行为 实施 [intro.progress]。 通用主机实现应该提供并发的前进进度。

如果主机实现提供 并发前进进度 [intro.progress.7], 那么CUDA C++提供 并行前进 [intro.progress.9] 对于设备线程。

5.8.2. 设备线程#

一旦设备线程取得进展：

  • 如果它是一个 合作网格, 其网格中的所有设备线程最终都将取得进展。

  • 否则，其中的所有设备线程 线程块簇 最终会取得进步。

    [注意：不保证其他线程块集群中的线程最终取得进展。 - 结束语。]

    [注意：这意味着其线程块内的所有设备线程最终都将取得进展。 - 结束语。]

Modify [intro.progress.1] 如下（修改为 bold):

该实现可以假设任何 host 线程最终将执行以下操作之一：

  1. 终止，

  2. 调用函数 std::this_thread::yield ([thread.thread.this]),

  3. 调用库 I/O 函数，

  4. 通过易失性左值执行访问，

  5. 执行同步操作或原子操作，或者

  6. 继续执行一个简单的无限循环（[stmt.iter.general]).

该实现可以假设任何设备线程最终都会执行以下操作之一：

  1. terminate,

  2. 调用库 I/O 函数,

  3. 通过易失性左值执行访问，除非指定对象具有自动存储持续时间，或者

  4. 执行同步操作或原子读取操作，除非指定对象具有自动存储持续时间。

[注意：设备线程相对于主机线程的一些当前限制 是我们已知的实施缺陷，我们可能会随着时间的推移进行修复。 示例包括设备线程产生的未定义行为 最终只执行易失性或原子操作 关于自动存储持续时间的对象。 然而，设备线程相对于主机线程的其他限制 都是有意的选择。 它们可以实现性能优化 如果设备线程严格遵循 C++ 标准，这是不可能的。 例如，为项目提供前进的进展 最终只执行原子写入或栅栏 会降低整体性能，但几乎没有什么实际好处。 - 结束语。]

向前进度的示例保证了主机和设备线程之间由于修改而存在差异 [intro.progress.1].

以下示例引用了上述主机和设备线程的实现假设的逐项子条款 分别使用“host.threads.<id>”和“device.threads.<id>”。

1// 示例：Execution.Model.Device.0
2// 结果：网格最终按 device.threads.4 终止，因为原子对象没有自动存储持续时间。
3__global__ void ex0(cuda::atomic_ref<int, cuda::thread_scope_device> atom) {
4    if (threadIdx.x == 0) {
5        while(atom.load(cuda::memory_order_relaxed) == 0);
6    } else if (threadIdx.x == 1) {
7        atom.store(1, cuda::memory_order_relaxed);
8    }
9}

1// 示例：Execution.Model.Device.1
2// 允许的结果：没有线程取得进展，因为设备线程不支持 host.threads.2。
3__global__ void ex1() {
4    while(true) cuda::std::this_thread::yield();
5}

1// 示例：Execution.Model.Device.2
2// 允许的结果：没有线程取得进展，因为设备线程不支持 host.threads.4
3// 对于具有自动存储持续时间的对象（请参阅 device.threads.3 中的异常）。
4__global__ void ex2() {
5    volatile bool True = true;
6    while(True);
7}

1// 示例：Execution.Model.Device.3
2// 允许的结果：没有线程取得进展，因为设备线程不支持 host.threads.5
3// 对于具有自动存储持续时间的对象（请参阅 device.threads.4 中的异常）。
4__global__ void ex3() {
5    cuda::atomic<bool, cuda::thread_scope_thread> True = true;
6    while(True.load());
7}

1// 示例：Execution.Model.Device.4
2// 允许的结果：没有线程取得进展，因为设备线程不支持 host.thread.6。
3__global void ex4() {
4    while(true) { /* 空的 */ }
5}

5.8.3. CUDA API#

CUDA API 调用最终应返回或确保至少一个设备线程取得进展。

CUDA 查询函数（例如 cudaStreamQuery, cudaEventQuery等）不得一致 返回 cudaErrorNotReady 没有设备线程取得进展。

[注意：设备线程不需要与 API 调用“相关”，例如，在一个流或进程上操作的 API 可以确保设备线程在另一流或进程上的进度。 - 结束语。]

[注意：测试程序是否符合 CUDA API Forward Progress 一致性的简单但不够的方法是使用以下环境变量集运行它们： CUDA_DEVICE_MAX_CONNECTIONS=1 CUDA_LAUNCH_BLOCKING=1，然后检查程序是否仍然终止。 如果没有，则程序有错误。 此方法还不够，因为它不能捕获所有前进进度错误，但它确实捕获了许多此类错误。 - 结束语。]

CUDA API 向前进度保证的示例。
 1// 示例：Execution.Model.API.1
 2// 结果：如果没有其他设备线程（例如，来自其他进程的）正在取得进展，
 3// 该程序终止并返回 cudaSuccess。
 4// 理由：CUDA 保证如果设备为空：
 5// - `cudaDeviceSynchronize` 最终确保至少一个设备线程取得进展，这意味着最终 `hello_world` 网格及其设备线程之一启动。
 6// - 所有线程块线程最终都会启动（由于“如果设备线程取得进展，则其线程块集群中的所有其他线程最终都会取得进展”）。
 7// - 一旦线程块中的所有线程到达“__syncthreads”屏障，所有等待线程都将被解除阻塞。
 8// - 因此所有设备线程最终都会退出“hello_world”网格。
 9// -“cudaDeviceSynchronize”最终解除阻塞。
10__global__ void hello_world() { __syncthreads(); }
11int main() {
12    hello_world<<<1,2>>>();
13    return (int)cudaDeviceSynchronize();
14}

 1// 示例：Execution.Model.API.2
 2// 允许的结果：最终，没有线程取得进展。
 3// 基本原理：只有当设备线程最终取得进展并设置标志时，才会调用下面的“cudaDeviceSynchronize” API。
 4// 但是，CUDA 仅保证调用同步 API 时“生产者”设备线程最终启动。
 5// 因此，主机线程可能永远不会从标志自旋循环中解除阻塞。
 6cuda::atomic<int, cuda::thread_scope_system> flag = 0;
 7__global__ void producer() { flag.store(1); }
 8int main() {
 9    cudaHostRegister(&flag, sizeof(flag));
10    producer<<<1,1>>>();
11    while (flag.load() == 0);
12    return cudaDeviceSynchronize();
13}

 1// 示例：Execution.Model.API.3
 2// 允许的结果：最终，没有线程取得进展。
 3// 基本原理：与Example.Model.API.2相同，但单个CUDA查询API调用不能保证
 4// 设备线程最终启动，仅重复 CUDA 查询 API 调用（请参阅 Execution.Model.API.4）。
 5cuda::atomic<int, cuda::thread_scope_system> flag = 0;
 6__global__ void producer() { flag.store(1); }
 7int main() {
 8    cudaHostRegister(&flag, sizeof(flag));
 9    producer<<<1,1>>>();
10    (void)cudaStreamQuery(0);
11    while (flag.load() == 0);
12    return cudaDeviceSynchronize();
13}

 1// 示例：Execution.Model.API.4
 2// 结果：终止。
 3// 原理：与Execution.Model.API.3相同，但此示例重复调用
 4// CUDA 查询 API 位于标志自旋循环内，这保证了设备线程
 5// 最终取得进步。
 6cuda::atomic<int, cuda::thread_scope_system> flag = 0;
 7__global__ void producer() { flag.store(1); }
 8int main() {
 9    cudaHostRegister(&flag, sizeof(flag));
10    producer<<<1,1>>>();
11    while (flag.load() == 0) {
12        (void)cudaStreamQuery(0);
13    }
14    return cudaDeviceSynchronize();
15}

5.8.3.1. 依赖项#

设备线程在其所有依赖项完成之前不得启动。

[注意：可以创建阻止设备线程开始取得进展的依赖关系，例如，通过 CUDA 流命令。 其中可能包括对以下事项的完成的依赖： CUDA 活动 和 CUDA 内核。 - 结束语。]

CUDA API 由于依赖关系而向前进度保证的示例
 1// 示例：Execution.Model.Stream.0
 2// 允许的结果：最终，没有线程取得进展。
 3// 理由：虽然 CUDA 保证一个设备线程取得进展，但因为
 4// “first”和“second”之间没有依赖关系，它不保证是哪个线程，
 5// 因此它总是可以从“第二个”中选择设备线程，而第二个线程永远不会
 6// 从自旋循环中解锁。
 7// 也就是说，“第二”可能会导致“第一”挨饿。
 8cuda::atomic<int, cuda::thread_scope_system> flag = 0;
 9__global__ void first() { flag.store(1, cuda::memory_order_relaxed); }
10__global__ void second() { while(flag.load(cuda::memory_order_relaxed) == 0) {} }
11int main() {
12    cudaHostRegister(&flag, sizeof(flag));
13    cudaStream_t s0, s1;
14    cudaStreamCreate(&s0);
15    cudaStreamCreate(&s1);
16    first<<<1,1,0,s0>>>();
17    second<<<1,1,0,s1>>>();
18    return cudaDeviceSynchronize();
19}

 1// 示例：Execution.Model.Stream.1
 2// 结果：终止。
 3// 基本原理：与 Execution.Model.Stream.0 相同，但此示例具有流依赖性
 4// 在第一个和第二个之间，这需要 CUDA 按顺序运行网格。
 5cuda::atomic<int, cuda::thread_scope_system> flag = 0;
 6__global__ void first() { flag.store(1, cuda::memory_order_relaxed); }
 7__global__ void second() { while(flag.load(cuda::memory_order_relaxed) == 0) {} }
 8int main() {
 9    cudaHostRegister(&flag, sizeof(flag));
10    cudaStream_t s0;
11    cudaStreamCreate(&s0);
12    first<<<1,1,0,s0>>>();
13    second<<<1,1,0,s0>>>();
14    return cudaDeviceSynchronize();
15}
