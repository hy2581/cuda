2.1. CUDA C++ 入门#

本章通过 C++ 示例介绍 CUDA 编程模型中的一些基础概念。

本编程指南重点关注 CUDA Runtime API。它是 C++ 中最常用的 CUDA 使用方式，并构建在更基础的 CUDA Driver API 之上。

CUDA 运行时 API 和 CUDA 驱动程序 API 讨论 API 和 API 之间的区别 CUDA驱动程序API 讨论编写混合 API 的代码。

本指南假设已安装 CUDA 工具包和 NVIDIA 驱动程序，并且存在受支持的 NVIDIA GPU。参见 CUDA 快速入门指南 有关安装必要的 CUDA 组件的说明。

2.1.1. 使用 NVCC 编译#

使用C++编写的GPU代码通过NVIDIA CUDA编译器 nvcc 进行编译。 nvcc 是一个编译器驱动程序，可简化编译 C++ 或 PTX 代码的过程：它提供简单且熟悉的命令行选项，并通过调用实现不同编译阶段的工具集合来执行它们。

本指南将展示 nvcc 命令行，可在安装了 CUDA 工具包的任何 Linux 系统、Windows 命令行或 Power shell 或带有 CUDA 工具包的 Windows Subsystem for Linux 上使用。 的 NVCC 分会 本指南涵盖了以下常见用例 nvcc，完整的文档由 nvcc 用户手册.

2.1.2. 内核（Kernel）#

正如 CUDA 编程模型 一章提到，不可主机端调用并在 GPU 上执行称为内核（kernel）的函数。内核被编写为由许多并行线程同时运行。

2.1.2.1. 定义内核#

内核的代码是使用以下命令指定的 __global__ 声明说明符。这向编译器表明该函数将以允许从内核启动调用它的方式为 GPU 编译。内核启动是通常从 CPU 启动内核运行的操作。内核是带有 void 返回类型。

// 内核定义
__global__ void vecAdd(float* A, float* B, float* C)
{

}

2.1.2.2. 启动内核#

内核线程执行的线程数量在内核启动时进行指定，这称为执行配置（executionconfiguration）。同一内核的不同调用可能会使用不同的执行配置，例如不同数量的线程或线程块。

有两种从 CPU 代码启动内核的方法， 三重 V 形符号 和 cudaLaunchKernelEx。这里介绍了三重 V 形符号，这是启动内核的最常见方式。使用以下命令启动内核的示例 cudaLaunchKernelEx 在章节中详细显示和讨论 第3.1.1节.

2.1.2.2.1. 三尖括号语法#

三重 V 形符号是 CUDA C++ 语言扩展 用于启动内核。它被称为三重 V 形，因为它使用三个 V 形字符来封装内核启动的执行配置，即 <<< >>>。执行配置参数被指定为 V 形内的逗号分隔列表，类似于函数调用的参数。内核启动的语法 vecAdd 内核如下所示。

 __global__ void vecAdd(float* A, float* B, float* C)
 {

 }

int main()
{
    ...
    // 内核调用
    vecAdd<<<1, 256>>>(A, B, C);
    ...
}

三重 V 形符号的前两个参数分别是网格尺寸和线程块尺寸。当使用一维线程块或网格时，可以使用整数来指定维度。

上面的代码启动了一个包含 256 个线程的线程块。每个线程将执行完全相同的内核代码。在 线程和网格索引内在函数，我们将展示每个线程如何使用其在线程块和网格中的索引来更改其操作的数据。

每个块的线程数量是有限的，因为块中的所有线程都驻留在同一个流式多处理器 (SM) 上，并且必须共享 SM 的资源。在当前的 GPU 上，一个线程块最多可以包含 1024 个线程。如果资源允许，可以在SM上同时调度多个线程块。

内核启动相对于主机线程是异步的。也就是说，内核将被设置为在 GPU 上执行，但主机代码不会等待内核在 GPU 上完成（甚至开始）执行，然后再继续。必须使用 GPU 和 CPU 之间某种形式的同步来确定内核是否已完成。最基本的版本，完全同步整个GPU，如图所示 同步CPU和GPU。更复杂的同步方法包含在 异步执行.

当使用 2 或 3 维网格或线程块时，CUDA 类型 dim3 用作网格和线程块尺寸参数。下面的代码片段显示了内核启动 MatAdd 内核使用 16 x 16 网格的线程块，每个线程块是 8 x 8。

int main()
{
    ...
    dim3 grid(16,16);
    dim3 block(8,8);
    MatAdd<<<grid, block>>>(A, B, C);
    ...
}

2.1.2.3. 线程与网格索引内建变量#

在内核代码中，CUDA 提供了一组内建变量，可访问执行配置参数以及线程/线程块索引。

  • threadIdx 给出线程在其线程块中的索引。线程块中的每个线程都会有不同的索引。

  • blockDim 给出线程块的尺寸，该尺寸在内核启动的执行配置中指定。

  • blockIdx 给出网格内线程块的索引.每个线程块都会有不同的索引。

  • gridDim 给出网格的尺寸，该尺寸在内核启动时在执行配置中指定。

这些内在函数中的每一个都是一个 3 分量向量，其中 .x, .y, 和 .z 会员。启动配置未指定的维度将默认为 1。 threadIdx 或 blockIdx 是零索引的。也就是说， threadIdx.x 将采用从 0 到（包括）的值 blockDim.x-1. .y 或 .z 在各自的维度上操作相同。

同样， blockIdx.x 值从 0 到（包括） gridDim.x-1，同样对于 .y 或 .z 尺寸，分别。

这些允许单个线程识别它应该执行什么工作。回到 vecAdd kernel，内核采用三个参数，每个参数都是浮点数向量。内核执行逐元素加法 A 或 B 并将结果存储在 C。内核是并行的，每个线程都会执行一次加法。它计算哪个元素由其线程和网格索引决定。

__global__ void vecAdd(float* A, float* B, float* C)
{
   // 计算这个线程负责计算哪个元素
   int workIndex = threadIdx.x + blockDim.x * blockIdx.x

   // 执行计算
   C[workIndex] = A[workIndex] + B[workIndex];
}

int main()
{
    ...
    // A、B 和 C 是 1024 个元素的向量
    vecAdd<<<4, 256>>>(A, B, C);
    ...
}

在此示例中，使用 256 个线程的 4 个线程块来添加 1024 个元素的向量。在第一个线程块中， blockIdx.x 将为零，因此每个线程的 workIndex 将只是其 threadIdx.x。在第二个线程块中， blockIdx.x 将是 1，所以 blockDim.x * blockIdx.x 将与以下相同 blockDim.x，在本例中为 256。的 workIndex 对于第二个线程块中的每个线程将是其 threadIdx.x + 256。在第三个线程块中 workIndex 将是 threadIdx.x + 512.

这个计算 workIndex 对于一维并行化来说非常常见。扩展到二维或三维通常在每个维度中遵循相同的模式。

2.1.2.3.1. 边界检查#

上面给出的示例假设向量的长度是线程块大小的倍数，在本例中为 256 个线程。为了使内核处理任何向量长度，我们可以添加检查以确保内存访问不超过数组的边界，如下所示，然后启动一个线程块，该线程块将包含一些不活动的线程。

__global__ void vecAdd(float* A, float* B, float* C, int vectorLength)
{
     // 计算这个线程负责计算哪个元素
     int workIndex = threadIdx.x + blockDim.x * blockIdx.x

     if(workIndex < vectorLength)
     {
         // 执行计算
         C[workIndex] = A[workIndex] + B[workIndex];
     }
}

使用上述内核代码，可以启动比需要更多的线程，而不会导致对数组的越界访问。什么时候 workIndex exceeds vectorLength，线程退出并且不做任何工作。在不执行任何工作的块中启动额外的线程不会产生较大的开销成本，但是应避免启动其中没有线程执行工作的线程块。该内核现在可以处理不是块大小倍数的向量长度。

所需线程块的数量可以计算为所需线程数量的上限（本例中为向量长度）除以每个块的线程数量。即所需线程数除以每块线程数的整数，向上取整。下面给出了将其表示为单个整数除法的常用方法。通过添加 threads - 1 在整数除法之前，这就像一个上限函数，仅当向量长度不能被每个块的线程数整除时才添加另一个线程块。

// vectorLength 是一个整数，存储向量中元素的数量
int threads = 256;
int blocks = (vectorLength + threads-1)/threads;
vecAdd<<<blocks, threads>>>(devA, devB, devC, vectorLength);

CUDA 核心计算库 (CCCL) 提供了方便的实用工具， cuda::ceil_div，用于执行此上限除法来计算内核启动所需的块数。该实用程序可通过包含标头来使用 <cuda/cmath>.

// vectorLength 是一个整数，存储向量中元素的数量
int threads = 256;
int blocks = cuda::ceil_div(vectorLength, threads);
vecAdd<<<blocks, threads>>>(devA, devB, devC, vectorLength);

这里每个块 256 个线程的选择是任意的，但这通常是一个很好的开始值。

2.1.3. GPU 计算中的内存#

要使用上文的 vecAdd 内核，数组 A、B、C 必须位于 GPU 可访问的内存中。有几种不同的方法可以做到这一点，这里将说明其中两种。其他方法将在后面的章节中介绍 统一内存。 GPU 上运行的代码可用的内存空间在 显存 并在以下内容中有更详细的介绍 GPU 设备内存空间.

2.1.3.1. 统一内存#

统一内存是 CUDA 运行时的一项功能，可让 NVIDIA 驱动程序管理主机和设备之间的数据移动。内存分配使用 cudaMallocManaged API 或通过声明变量 __managed__ 说明符。每当 GPU 或 CPU 尝试访问内存时，NVIDIA 驱动程序都会确保该内存可供访问。

下面的代码显示了启动的完整功能 vecAdd 内核使用统一内存来存储将在 GPU 上使用的输入和输出向量。 cudaMallocManaged 分配可以从 CPU 或 GPU 访问的缓冲区。这些缓冲区被释放使用 cudaFree.

void unifiedMemExample(int vectorLength)
{
    // 指向内存向量的指针
    float* A = nullptr;
    float* B = nullptr;
    float* C = nullptr;
    float* comparisonResult = (float*)malloc(vectorLength*sizeof(float));

    // 使用统一内存分配缓冲区
    cudaMallocManaged(&A, vectorLength*sizeof(float));
    cudaMallocManaged(&B, vectorLength*sizeof(float));
    cudaMallocManaged(&C, vectorLength*sizeof(float));

    // 在主机上初始化向量
    initArray(A, vectorLength);
    initArray(B, vectorLength);

    // 启动内核。统一内存将确保 A、B 和 C
    // GPU 可以访问
    int threads = 256;
    int blocks = cuda::ceil_div(vectorLength, threads);
    vecAdd<<<blocks, threads>>>(A, B, C, vectorLength);
    // 等待内核完成执行
    cudaDeviceSynchronize();

    // 在CPU上串行执行计算以进行比较
    serialVecAdd(A, B, comparisonResult, vectorLength);

    // 确认CPU和GPU得到相同的答案
    if(vectorApproximatelyEqual(C, comparisonResult, vectorLength))
    {
        printf("Unified Memory: CPU and GPU answers match\n");
    }
    else
    {
        printf("Unified Memory: Error - CPU and GPU answers do not match\n");
    }

    // 清理
    cudaFree(A);
    cudaFree(B);
    cudaFree(C);
    free(comparisonResult);

}

CUDA 支持的所有操作系统和 GPU 均支持统一内存，但底层机制和性能可能因系统架构而异。 统一内存 提供更多详细信息。在某些 Linux 系统上（例如那些带有 地址翻译服务 和 异构内存管理）所有系统内存自动统一内存，无需使用 cudaMallocManaged 或 __managed__ specifier.

2.1.3.2. 显式内存管理#

显式管理内存空间之间的内存分配和数据迁移有助于提高应用程序性能，尽管它确实会导致更冗长的代码。下面的代码使用显式分配 GPU 上的内存 cudaMalloc。使用相同的方法释放 GPU 上的内存 cudaFree 在前面的示例中，API as 用于统一内存。

void explicitMemExample(int vectorLength)
{
    // 主机内存指针
    float* A = nullptr;
    float* B = nullptr;
    float* C = nullptr;
    float* comparisonResult = (float*)malloc(vectorLength*sizeof(float));
    
    // 设备内存指针
    float* devA = nullptr;
    float* devB = nullptr;
    float* devC = nullptr;

    // 使用 cudaMallocHost API 分配主机内存。这是最佳实践
    // 何时使用缓冲区在 CPU 和 GPU 内存之间进行复制
    cudaMallocHost(&A, vectorLength*sizeof(float));
    cudaMallocHost(&B, vectorLength*sizeof(float));
    cudaMallocHost(&C, vectorLength*sizeof(float));

    // 在主机上初始化向量
    initArray(A, vectorLength);
    initArray(B, vectorLength);

    // 开始分配和复制
    // 在 GPU 上分配内存
    cudaMalloc(&devA, vectorLength*sizeof(float));
    cudaMalloc(&devB, vectorLength*sizeof(float));
    cudaMalloc(&devC, vectorLength*sizeof(float));

    // 将数据复制到GPU
    cudaMemcpy(devA, A, vectorLength*sizeof(float), cudaMemcpyDefault);
    cudaMemcpy(devB, B, vectorLength*sizeof(float), cudaMemcpyDefault);
    cudaMemset(devC, 0, vectorLength*sizeof(float));
    // 结束分配和复制

    // 启动内核
    int threads = 256;
    int blocks = cuda::ceil_div(vectorLength, threads);
    vecAdd<<<blocks, threads>>>(devA, devB, devC, vectorLength);
    // 等待内核执行完成
    cudaDeviceSynchronize();

    // 将结果复制回主机
    cudaMemcpy(C, devC, vectorLength*sizeof(float), cudaMemcpyDefault);

    // 在CPU上串行执行计算以进行比较
    serialVecAdd(A, B, comparisonResult, vectorLength);

    // 确认CPU和GPU得到相同的答案
    if(vectorApproximatelyEqual(C, comparisonResult, vectorLength))
    {
        printf("Explicit Memory: CPU and GPU answers match\n");
    }
    else
    {
        printf("Explicit Memory: Error - CPU and GPU answers to not match\n");
    }

    // 清理
    cudaFree(devA);
    cudaFree(devB);
    cudaFree(devC);
    cudaFreeHost(A);
    cudaFreeHost(B);
    cudaFreeHost(C);
    free(comparisonResult);
}

CUDA API cudaMemcpy 用于将数据从驻留在 CPU 上的缓冲区复制到驻留在 GPU 上的缓冲区。除了目标指针、源指针和字节大小之外，最后一个参数 cudaMemcpy 是一个 cudaMemcpyKind_t。这可以具有诸如以下的值 cudaMemcpyHostToDevice 对于从 CPU 到 GPU 的副本， cudaMemcpyDeviceToHost 用于从 CPU 到 GPU 的副本，或者 cudaMemcpyDeviceToDevice 用于 GPU 内或 GPU 之间的副本。

在这个例子中， cudaMemcpyDefault 作为最后一个参数传递给 cudaMemcpy。 这会导致 CUDA 使用源指针和目标指针的值来确定要执行的复制类型。

cudaMemcpy API 是同步的。也就是说，在复制完成之前它不会返回。异步副本引入于 在 CUDA 流中启动内存传输.

代码使用 cudaMallocHost 在CPU上分配内存。这分配 页锁定内存 在主机上，这可以提高复制性能，并且对于 asynchronous 内存传输。一般来说，最好将页面锁定内存用于 CPU 缓冲区，这些缓冲区将用于与 GPU 之间的数据传输。如果太多主机内存被页面锁定，某些系统上的性能可能会下降。最佳实践是仅对用于从 GPU 发送或接收数据的缓冲区进行页面锁定。

2.1.3.3. 内存管理与应用性能#

从上面的例子可以看出，显式内存管理更加冗长，需要程序员指定主机和设备之间的副本。这是显式内存管理的优点和缺点：它可以更好地控制何时在主机和设备之间复制数据、内存驻留在何处以及确切地在何处分配哪些内存。显式内存管理可以提供控制内存传输并将其与其他计算重叠的性能机会。

当使用统一内存时，有CUDA API（将在 内存建议和预取），它为管理内存的 NVIDIA 驱动程序提供提示，这可以在使用统一内存时实现使用显式内存管理的一些性能优势。

2.1.4. CPU与GPU同步#

如 启动内核 一节所述，内核启动相对于发起调用的 CPU 线程是异步的。这意味着 CPU 线程的控制流会在内核完成之前继续向前执行，甚至可能在内核尚未真正启动前就继续执行。若要保证主机端后续代码执行前内核已经完成，就必须使用某种同步机制。

同步 GPU 和主机线程的最简单方法是使用 cudaDeviceSynchronize，它会阻塞主机线程，直到 GPU 上所有先前发出的工作完成为止。在本章的示例中，这已经足够了，因为 GPU 上只执行单个操作。在较大的应用中，可能有多个 streams 在 GPU 上执行工作并 cudaDeviceSynchronize 将等待所有流中的工作完成。在这些应用中，使用 流同步 仅与特定流同步的 API 或 CUDA 活动 推荐。这些内容将在 异步执行 chapter.

2.1.5. 整合示例#

以下清单显示了本章中介绍的简单向量加法内核的完整代码，以及用于检查以验证所获得的答案是否正确的所有主机代码和实用程序函数。这些示例默认使用向量长度 1024，但接受不同的向量长度作为可执行文件的命令行参数。

#include <cuda_runtime_api.h>
#include <memory.h>
#include <cstdlib>
#include <ctime>
#include <stdio.h>
#include <cuda/cmath>

__global__ void vecAdd(float* A, float* B, float* C, int vectorLength)
{
    int workIndex = threadIdx.x + blockIdx.x*blockDim.x;
    if(workIndex < vectorLength)
    {
        C[workIndex] = A[workIndex] + B[workIndex];
    }
}

void initArray(float* A, int length)
{
     std::srand(std::time({}));
    for(int i=0; i<length; i++)
    {
        A[i] = rand() / (float)RAND_MAX;
    }
}

void serialVecAdd(float* A, float* B, float* C,  int length)
{
    for(int i=0; i<length; i++)
    {
        C[i] = A[i] + B[i];
    }
}

bool vectorApproximatelyEqual(float* A, float* B, int length, float epsilon=0.00001)
{
    for(int i=0; i<length; i++)
    {
        if(fabs(A[i] -B[i]) > epsilon)
        {
            printf("Index %d mismatch: %f != %f", i, A[i], B[i]);
            return false;
        }
    }
    return true;
}

// 统一内存开始
void unifiedMemExample(int vectorLength)
{
    // 指向内存向量的指针
    float* A = nullptr;
    float* B = nullptr;
    float* C = nullptr;
    float* comparisonResult = (float*)malloc(vectorLength*sizeof(float));

    // 使用统一内存分配缓冲区
    cudaMallocManaged(&A, vectorLength*sizeof(float));
    cudaMallocManaged(&B, vectorLength*sizeof(float));
    cudaMallocManaged(&C, vectorLength*sizeof(float));

    // 在主机上初始化向量
    initArray(A, vectorLength);
    initArray(B, vectorLength);

    // 启动内核。统一内存将确保 A、B 和 C
    // GPU 可以访问
    int threads = 256;
    int blocks = cuda::ceil_div(vectorLength, threads);
    vecAdd<<<blocks, threads>>>(A, B, C, vectorLength);
    // 等待内核完成执行
    cudaDeviceSynchronize();

    // 在CPU上串行执行计算以进行比较
    serialVecAdd(A, B, comparisonResult, vectorLength);

    // 确认CPU和GPU得到相同的答案
    if(vectorApproximatelyEqual(C, comparisonResult, vectorLength))
    {
        printf("Unified Memory: CPU and GPU answers match\n");
    }
    else
    {
        printf("Unified Memory: Error - CPU and GPU answers do not match\n");
    }

    // 清理
    cudaFree(A);
    cudaFree(B);
    cudaFree(C);
    free(comparisonResult);

}

// 显式内存开始
void explicitMemExample(int vectorLength)
{
    // 主机内存指针
    float* A = nullptr;
    float* B = nullptr;
    float* C = nullptr;
    float* comparisonResult = (float*)malloc(vectorLength*sizeof(float));
    
    // 设备内存指针
    float* devA = nullptr;
    float* devB = nullptr;
    float* devC = nullptr;

    // 使用 cudaMallocHost API 分配主机内存。这是最佳实践
    // 何时使用缓冲区在 CPU 和 GPU 内存之间进行复制
    cudaMallocHost(&A, vectorLength*sizeof(float));
    cudaMallocHost(&B, vectorLength*sizeof(float));
    cudaMallocHost(&C, vectorLength*sizeof(float));

    // 在主机上初始化向量
    initArray(A, vectorLength);
    initArray(B, vectorLength);

    // 开始分配和复制
    // 在 GPU 上分配内存
    cudaMalloc(&devA, vectorLength*sizeof(float));
    cudaMalloc(&devB, vectorLength*sizeof(float));
    cudaMalloc(&devC, vectorLength*sizeof(float));

    // 将数据复制到GPU
    cudaMemcpy(devA, A, vectorLength*sizeof(float), cudaMemcpyDefault);
    cudaMemcpy(devB, B, vectorLength*sizeof(float), cudaMemcpyDefault);
    cudaMemset(devC, 0, vectorLength*sizeof(float));
    // 结束分配和复制

    // 启动内核
    int threads = 256;
    int blocks = cuda::ceil_div(vectorLength, threads);
    vecAdd<<<blocks, threads>>>(devA, devB, devC, vectorLength);
    // 等待内核执行完成
    cudaDeviceSynchronize();

    // 将结果复制回主机
    cudaMemcpy(C, devC, vectorLength*sizeof(float), cudaMemcpyDefault);

    // 在CPU上串行执行计算以进行比较
    serialVecAdd(A, B, comparisonResult, vectorLength);

    // 确认CPU和GPU得到相同的答案
    if(vectorApproximatelyEqual(C, comparisonResult, vectorLength))
    {
        printf("Explicit Memory: CPU and GPU answers match\n");
    }
    else
    {
        printf("Explicit Memory: Error - CPU and GPU answers to not match\n");
    }

    // 清理
    cudaFree(devA);
    cudaFree(devB);
    cudaFree(devC);
    cudaFreeHost(A);
    cudaFreeHost(B);
    cudaFreeHost(C);
    free(comparisonResult);
}
// 显式内存结束

{
    int vectorLength = 1024;
    if(argc >=2)
    {
        vectorLength = std::atoi(argv[1]);

    explicitMemExample(vectorLength);		
    return 0;
}

块级同步的最基本机制是 __syncthreads() 内在的，它充当屏障，块中的所有线程都必须等待，然后才允许任何线程继续。 共享内存 给出了使用共享内存的示例。

当同步保持在线程块内时，通常可以获得最佳性能。线程块仍然可以使用以下方法处理常见结果 原子内存函数，这将在接下来的章节中介绍。

2.1.6. 运行时初始化#

CUDA 运行时创建一个 CUDA 上下文 对于系统中的每个设备。该上下文是该设备的主要上下文，并在第一个运行时函数处初始化，该函数需要该设备上的活动上下文。上下文在应用程序的所有主机线程之间共享。作为上下文创建的一部分，设备代码是 即时编译 如有必要并加载到设备内存中。这一切都是透明发生的。可以从驱动程序 API 访问由 CUDA 运行时创建的主要上下文以实现互操作性，如中所述 运行时和驱动程序 API 之间的互操作性.

从 CUDA 12.0 开始， cudaInitDevice 或 cudaSetDevice 调用初始化运行时和主 context 与指定设备关联。运行时将隐式使用设备 0 并根据需要进行自初始化，以处理运行时 API 请求（如果这些请求发生在这些调用之前）。这在计时运行时函数调用以及解释第一次调用到运行时的错误代码时非常重要。在 CUDA 12.0 之前， cudaSetDevice 不会初始化运行时。

cudaDeviceReset 破坏当前设备的主要上下文。如果在销毁主上下文后调用 CUDA 运行时 API，将为该设备创建一个新的主上下文。

注

CUDA 接口使用全局状态，该状态在主机程序启动期间初始化并在主机程序终止期间销毁。在 main 之后的程序启动或终止期间使用任何这些接口（隐式或显式）将导致未定义的行为。

从 CUDA 12.0 开始， cudaSetDevice 在更改主机线程的当前设备后，显式初始化运行时（如果尚未初始化）。以前版本的 CUDA 会延迟新设备上的运行时初始化，直到第一次运行时调用发生后 cudaSetDevice。因此，检查返回值非常重要 cudaSetDevice 对于初始化错误。

参考手册的错误处理和版本管理部分中的运行时函数不会初始化运行时。

2.1.7. CUDA 中的错误检查#

每个 CUDA API 返回一个枚举类型的值， cudaError_t。在示例代码中，这些错误通常不会被检查。在生产应用程序中，最佳实践是始终检查和管理每个 CUDA API 调用的返回值。当没有错误时，返回值是 cudaSuccess。许多应用程序选择实现实用程序宏，如下所示

#define CUDA_CHECK(expr_to_check) do {            \
    cudaError_t result  = expr_to_check;          \
    if(result != cudaSuccess)                     \
    {                                             \
        fprintf(stderr,                           \
                "CUDA Runtime Error: %s:%i:%d = %s\n", \
                __FILE__,                         \
                __LINE__,                         \
                result,\
                cudaGetErrorString(result));      \
    }                                             \
} while(0)

该宏使用 cudaGetErrorString API，它返回一个人类可读的字符串，描述特定的含义 cudaError_t 值。 使用上面的宏，应用程序将在 CUDA_CHECK(expression) 宏，如下图：

    CUDA_CHECK(cudaMalloc(&devA, vectorLength*sizeof(float)));
    CUDA_CHECK(cudaMalloc(&devB, vectorLength*sizeof(float)));
    CUDA_CHECK(cudaMalloc(&devC, vectorLength*sizeof(float)));

如果这些调用中的任何一个检测到错误，它将被打印到 stderr 使用这个宏。该宏对于较小的项目很常见，但可以适应较大应用程序中的日志系统或其他错误处理机制。

注

值得注意的是，从任何 CUDA API 调用返回的错误状态也可以指示先前发出的异步操作的错误。部分 异步错误处理 更详细地介绍了这一点。

2.1.7.1. 错误状态#

CUDA运行时维护一个 cudaError_t 每个主机线程的状态。该值默认为 cudaSuccess 并在发生错误时被覆盖。 cudaGetLastError 返回当前错误状态，然后将其重置为 cudaSuccess。或者， cudaPeekLastError 返回错误状态而不重置它。

内核启动使用 三重 V 形符号 不返回 cudaError_t。最好在内核启动后立即检查错误状态，以检测内核启动中的即时错误或 异步错误 在内核启动之前。值为 cudaSuccess 在内核启动后立即检查错误状态并不意味着内核已成功执行甚至开始执行。它仅验证传递给运行时的内核启动参数和执行配置没有触发任何错误，并且错误状态不是内核启动之前的先前错误或异步错误。

2.1.7.2. 异步错误#

CUDA 内核启动和许多运行时 API 都是异步的。异步 CUDA 运行时 API 将在 异步执行。每当发生错误时，都会设置并覆盖 CUDA 错误状态。这意味着只有在接下来检查错误状态时才会报告异步操作执行期间发生的错误。如前所述，这可能是一个调用 cudaGetLastError, cudaPeekLastError，或者它可以是任何返回的 CUDA API cudaError_t.

当 CUDA 运行时 API 函数返回错误时，错误状态不会被清除。这意味着来自异步错误的错误代码（例如内核的无效内存访问）将由每个 CUDA 运行时 API 返回，直到通过调用清除错误状态 cudaGetLastError.

    vecAdd<<<blocks, threads>>>(devA, devB, devC);
    // 内核启动后检查错误状态
    CUDA_CHECK(cudaGetLastError());
    // 等待内核执行完成
    // CUDA_CHECK将报告内核执行期间发生的错误
    CUDA_CHECK(cudaDeviceSynchronize());

注

cudaError_t 值 cudaErrorNotReady，可以通过以下方式返回 cudaStreamQuery 或 cudaEventQuery，不被视为错误并且不会被报告 cudaPeekAtLastError 或 cudaGetLastError.
