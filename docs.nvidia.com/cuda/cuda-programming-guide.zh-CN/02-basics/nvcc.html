2.5. NVCC：NVIDIA CUDA 编译器#

NVIDIA CUDA 编译器 nvcc 是 NVIDIA 提供的工具链，用于编译 CUDA C/C++ 以及 PTX 代码。该工具链属于 CUDA Toolkit，包含编译器、链接器以及 PTX 与 Cubin 汇编器等工具。顶层工具 nvcc 负责协调整个编译流程，在各阶段调用相应工具。

nvcc 负责 CUDA 代码的离线编译；这与由 CUDA 运行时编译器 nvrtc 驱动的在线或即时（JIT）编译相对。

本章介绍构建应用时最常见的 nvcc 用法与关键细节。更完整内容请参见 NVCC 文档。

2.5.1. CUDA 源文件与头文件#

由 nvcc 编译的源文件可同时包含主机代码（在 CPU 上执行）与设备代码（在 GPU 上执行）。nvcc 支持常见 C/C++ 源文件扩展名 .c、.cpp、.cc、.cxx（主机代码），以及 .cu（设备代码或主机/设备混合代码）。含设备代码的头文件通常采用 .cuh 扩展名，以区别于仅主机代码头文件（如 .h、.hpp、.hh、.hxx 等）。

2.5.2. NVCC 编译工作流#

在初始阶段，nvcc 会将设备代码与主机代码分离，并分别交由 GPU 编译器与主机编译器处理。

编译主机代码时，CUDA 编译器 nvcc 需要可用的兼容主机编译器。CUDA Toolkit 对 Linux 与 Windows 平台分别定义了主机编译器支持策略。
仅含主机代码的文件可用 nvcc 或直接用主机编译器构建。生成的目标文件可在链接阶段与由 nvcc 生成且包含 GPU 代码的目标文件合并。
GPU 编译器会将 C/C++ 设备代码编译为 PTX 汇编。命令行中每指定一个虚拟机指令集架构（如 compute_90），GPU 编译器就会执行一次对应编译。
各 PTX 代码随后会传给 ptxas 工具，为目标硬件 ISA 生成 Cubin。硬件 ISA 由其 SM 版本 标识。
可在应用或库中将多个 PTX 与 Cubin 目标嵌入单个二进制 Fatbin 容器，使一个二进制支持多个虚拟与目标硬件 ISA。

上述工具的调用与协同由 nvcc 自动完成。可使用 -v 显示完整编译流程与工具调用；可使用 -keep 保存编译产生的 中间文件，保存位置为当前目录或 --keep-dir 指定目录。

下面示例展示了 CUDA 源文件 example.cu 的编译工作流：

// ----- 示例.cu -----
#include <stdio.h>
__global__ void kernel() {
    printf("Hello from kernel\n");
}

void kernel_launcher() {
    kernel<<<1, 1>>>();
    cudaDeviceSynchronize();
}

int main() {
    kernel_launcher();
    return 0;
}

2.5.3. NVCC 基本用法#

使用 nvcc 编译 CUDA 源文件的基本命令为：

nvcc <source_file>.cu -o <output_file>

nvcc 支持常见编译参数：指定头文件目录 -I <path>、库目录 -L <path>、链接库 -l<library>，以及定义宏 -D<macro>=<value>。

nvcc example.cu -I path_to_include/ -L path_to_library/ -lcublas -o <output_file>

2.5.3.1. NVCC 的 PTX 与 Cubin 生成#

默认情况下，为最大化兼容性，nvcc 会面向 CUDA Toolkit 支持的最早 GPU 架构（最低 compute_XY 与 sm_XY 版本）生成 PTX 与 Cubin。

  • 可使用 -arch 选项 为特定 GPU 架构生成 PTX 与 Cubin。

  • 可使用 -gencode 选项 为多个 GPU 架构生成 PTX 与 Cubin。

可分别通过 --list-gpu-code 与 --list-gpu-arch 获取支持的真实/虚拟 GPU 架构列表，也可参考 nvcc 文档中的 虚拟架构列表 与 GPU 架构列表。

nvcc --list-gpu-code # 列出所有支持的真实 GPU 架构
nvcc --list-gpu-arch # 列出所有支持的虚拟 GPU 架构

nvcc example.cu -arch=compute_<XY> # 例如 -arch=compute_80 适用于 NVIDIA Ampere GPU 及更高版本
                                   # 仅 PTX，GPU 向前兼容

nvcc example.cu -arch=sm_<XY>      # 例如 -arch=sm_80 适用于 NVIDIA Ampere GPU 及更高版本
                                   # PTX 和 Cubin、GPU 向前兼容

nvcc example.cu -arch=native       # 自动检测并生成当前 GPU 的 Cubin
                                   # 没有 PTX，没有 GPU 向前兼容性

nvcc example.cu -arch=all          # 为所有支持的 GPU 架构生成 Cubin
                                   # 还包括用于 GPU 前向兼容性的最新 PTX

nvcc example.cu -arch=all-major    # 为所有主要支持的 GPU 架构生成 Cubin，例如 sm_80、sm_90、
                                   # 还包括用于 GPU 前向兼容性的最新 PTX

更高级的用法允许分别指定 PTX 与 Cubin 目标：

# 为虚拟架构 compute_80 生成 PTX，并编译为真实架构 sm_86 的 Cubin；保留 compute_80 PTX
nvcc example.cu -arch=compute_80 -gpu-code=sm_86,compute_80 # （PTX 和 Cubin）

# 为虚拟架构 compute_80 生成 PTX，并编译为面向真实架构 sm_86、sm_89 的 Cubin
nvcc example.cu -arch=compute_80 -gpu-code=sm_86,sm_89    # （无 PTX）
nvcc example.cu -gencode=arch=compute_80,code=sm_86,sm_89 # 与上面相同

# (1) 生成虚拟架构 compute_80 的 PTX，并编译为真实架构 sm_86、sm_89 的 Cubin
# (2) 生成虚拟架构 compute_90 的 PTX，并编译为真实架构 sm_90 的 Cubin
nvcc example.cu -gencode=arch=compute_80,code=sm_86,sm_89 -gencode=arch=compute_90,code=sm_90

用于控制 GPU 代码生成的 nvcc 完整命令行选项参考见 NVCC 文档。

2.5.3.2. 主机代码编译说明#

若某个编译单元（源文件及其头文件）不包含设备代码或设备符号，可直接由主机编译器编译。若任一编译单元使用 CUDA 运行时 API，应用必须链接 CUDA 运行时库。CUDA 运行时同时提供静态库 libcudart_static 与共享库 libcudart。默认情况下，nvcc 链接静态运行时库。若需使用共享库版本，可在编译或链接命令中传入 --cudart=shared。

nvcc 可通过 -ccbin <compiler> 指定用于主机函数的主机编译器。也可通过环境变量 NVCC_CCBIN 指定。-Xcompiler 用于把参数透传给主机编译器。例如下方示例中，-O3 由 nvcc 传给主机编译器。

nvcc example.cu -ccbin=clang++

export NVCC_CCBIN='gcc'
nvcc example.cu -Xcompiler=-O3

2.5.3.3. GPU 代码的分离编译#

nvcc 默认采用整程序编译，即要求使用某段 GPU 代码/符号的编译单元中已包含其定义。CUDA 设备函数可调用其他编译单元中的设备函数，或访问其中定义的设备变量，但需在 nvcc 命令行指定 -rdc=true（或其别名 -dc）以启用跨编译单元设备代码链接。该能力称为分离编译。

分离编译能带来更灵活的代码组织、潜在更快编译速度以及更小二进制体积。相较整程序编译，分离编译在构建流程上可能更复杂。由于设备代码链接可能带来性能影响，因此默认未启用。链接时优化（LTO） 可帮助降低分离编译的性能开销。

分离编译需要满足以下条件：

  • 在一个编译单元中定义的非 const 设备变量，在其他编译单元中引用时必须使用 extern 关键字。

  • 所有 const 设备变量在定义与引用时都应使用 extern。

  • 所有 CUDA 源文件 .cu 必须使用 -dc 或 -rdc=true 编译。

主机函数与设备函数默认具有外部链接属性，通常无需显式添加 extern。需注意，从 CUDA 13 开始，__global__ 函数以及 __managed__/__device__/__constant__ 变量默认改为内部链接属性。

下例中，definition.cu 定义了变量与函数，而 example.cu 对其进行引用。两个文件分别编译后再链接为最终二进制。

// ----- 定义.cu -----
extern __device__ int device_variable = 5;
__device__        int device_function() { return 10; }

// ----- 示例.cu -----
extern __device__ int  device_variable;
__device__        int device_function();

__global__ void kernel(int* ptr) {
    device_variable = 0;
    *ptr            = device_function();
}

nvcc -dc definition.cu -o definition.o
nvcc -dc example.cu    -o example.o
nvcc definition.o example.o -o program

2.5.4. 常用编译选项#

本节介绍可与 nvcc 搭配使用的重点编译选项，覆盖语言特性、优化、调试、性能分析与构建等方面。所有选项的完整说明见 NVCC 文档。

2.5.4.1. 语言特性#

nvcc 支持从 C++03 到 C++20 的 C++ 核心语言特性。可通过 -std 指定语言标准：

  • --std={c++03|c++11|c++14|c++17|c++20}

此外，nvcc 支持以下语言扩展：

  • -restrict：声明所有内核指针参数均为 restrict 指针。

  • -extended-lambda：允许在 lambda 声明中使用 __host__、__device__ 注解。

  • -expt-relaxed-constexpr：（实验性）允许主机代码调用 __device__ constexpr 函数，也允许设备代码调用 __host__ constexpr 函数。

这些特性的更多细节可参见 扩展 Lambda 与 constexpr 相关章节。

2.5.4.2. 调试选项#

nvcc 提供以下调试信息生成选项：

  • -g：生成主机代码的调试信息。gdb/lldb 等工具依赖这些信息进行主机代码调试。

  • -G：生成设备代码的调试信息。cuda-gdb 的设备代码调试依赖此类信息。该标志还会定义 __CUDACC_DEBUG__ 宏。

  • -lineinfo：生成设备代码的行号信息。该选项不会影响执行性能，并可供 compute-sanitizer 等工具在跟踪内核执行时使用。

默认情况下，nvcc 会对 GPU 代码使用最高优化级别 -O3。调试标志 -G 会阻止某些编译器优化，因此调试构建的性能通常低于非调试构建。可通过定义 -DNDEBUG 禁用运行时断言，因为断言同样会降低执行速度。

2.5.4.3. 优化选项#

nvcc 提供了大量性能优化选项。本节仅概览开发者常用的一部分，并给出进一步资料链接。完整内容见 NVCC 文档。

  • -Xptxas：将参数传递给 PTX 汇编器工具 ptxas。nvcc 文档提供了 ptxas 的 常用参数列表。例如，-Xptxas=-maxrregcount=N 可指定每个线程使用的最大寄存器数。

  • -extra-device-vectorization：启用更积极的设备代码矢量化。

  • 用于细粒度控制浮点行为的更多选项见 浮点计算 章节及 NVCC 文档。

以下选项可输出有助于高级优化分析的编译信息：

  • -res-usage：编译后打印资源使用报告。它包括为每个内核函数分配的寄存器、共享内存、常量内存和本地内存的数量。

  • -opt-info=inline：打印有关内联函数的信息。

  • -Xptxas=-warn-lmem-usage：如果使用本地内存，则发出警告。

  • -Xptxas=-warn-spills：如果寄存器溢出到本地内存，则发出警告。

2.5.4.4. 链接时优化（LTO）#

由于跨文件优化机会受限，分离编译 的性能可能低于整程序编译。链接时优化（LTO）通过在链接阶段跨编译单元优化来缓解这一问题，但会增加编译时间。LTO 可在保留分离编译灵活性的同时，恢复大量整程序编译性能。

nvcc 需通过 -dlto 选项 或 lto_<SM version> 目标启用 LTO：

nvcc -dc -dlto -arch=sm_100 definition.cu -o definition.o
nvcc -dc -dlto -arch=sm_100 example.cu    -o example.o
nvcc -dlto definition.o example.o -o program

nvcc -dc -arch=lto_100 definition.cu -o definition.o
nvcc -dc -arch=lto_100 example.cu    -o example.o
nvcc -dlto definition.o example.o -o program

2.5.4.5. 性能分析选项#

可直接使用 Nsight Compute 与 Nsight Systems 对 CUDA 应用进行分析，通常无需在编译时增加额外参数。不过，nvcc 生成的附加信息可帮助将源码与生成代码关联，从而改进分析效果：

  • -lineinfo：生成设备代码的行号信息；这允许在分析工具中查看源代码。分析工具要求原始源代码位于编译代码的同一位置。

  • -src-in-ptx：将原始源代码保留在 PTX 中，可避免上面提到的 -lineinfo 限制。该选项需要同时使用 -lineinfo。

2.5.4.6. Fatbin 压缩#

nvcc 默认会压缩应用或库二进制中的 fatbin。可通过以下选项控制 Fatbin 压缩行为：

  • -no-compress：取消 Fatbin 压缩。

  • --compress-mode={default|size|speed|balance|none}：设置压缩模式。speed 侧重更快解压，size 侧重更小体积，balance 在二者间折中。默认模式为 speed，none 表示禁用压缩。

2.5.4.7. 编译器性能控制#

nvcc 还提供了用于分析并加速编译过程本身的选项：

  • -t <N>：为同一编译单元面向多个 GPU 架构并行编译时使用的 CPU 线程数。

  • -split-compile <N>：优化阶段并行使用的 CPU 线程数。

  • -split-compile-extended <N>：更激进的分段并行编译方式，需启用链接时优化。

  • -Ofc <N>：设备代码编译速度等级。

  • -time <filename>：生成包含各编译阶段耗时的 CSV 报表。

  • -fdevice-time-trace：生成设备代码编译时间轨迹。
