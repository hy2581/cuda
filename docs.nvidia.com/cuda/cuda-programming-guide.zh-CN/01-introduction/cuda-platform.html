1.3. CUDA 平台#

NVIDIA CUDA 平台由许多软件、硬件组件以及为异构系统计算而发展出的关键技术组成。本章介绍应用开发者理解 CUDA 平台时需要掌握的一些基础概念和核心组件。与 编程模型 一章类似，本章内容不依赖具体编程语言，而适用于所有使用 CUDA 平台的场景。

1.3.1. 计算能力与 SM 版本#

每个 NVIDIA GPU 都有一个 计算能力（Compute Capability，CC）编号，用于表示该 GPU 支持哪些功能，并给出该 GPU 的若干硬件参数。这些规格记录在 第 5.1 节 的附录中。所有 NVIDIA GPU 及其计算能力的列表维护在 CUDA GPU 计算能力页面。

计算能力以 X.Y 格式表示为主版本号和次版本号，其中 X 为主版本号，Y 为次版本号。例如，CC 12.0 的主版本为 12、次版本为 0。计算能力直接对应 SM 版本号。例如，CC 12.0 GPU 内的 SM 版本为 sm_120，该版本号用于标记二进制文件。

第 5.1.1 节 展示了如何查询并确定系统中 GPU 的计算能力。

1.3.2. CUDA 工具包与 NVIDIA 驱动#

可以把 NVIDIA 驱动 理解为 GPU 的操作系统层。NVIDIA 驱动是一个必须安装在主机操作系统上的软件组件，所有 GPU 用途都离不开它，包括显示和图形功能。NVIDIA 驱动是 CUDA 平台的基础。除 CUDA 之外，Vulkan、Direct3D 等其他 GPU 使用方式也由 NVIDIA 驱动提供支持。NVIDIA 驱动具有类似 r580 这样的版本号。

CUDA 工具包 是一组库、头文件和工具，用于编写、构建和分析利用 GPU 计算的软件。CUDA Toolkit 与 NVIDIA 驱动是彼此独立的软件产品。

CUDA 运行时 是 CUDA 工具包所提供库中的一个特殊库。CUDA 运行时提供 API 和一些语言扩展，用于处理内存分配、在 GPU 与其他 GPU 或 CPU 之间复制数据、启动内核等常见任务。CUDA 运行时的 API 组件称为 CUDA 运行时 API。

CUDA 兼容性 文档提供了不同 GPU、NVIDIA 驱动和 CUDA 工具包版本之间兼容性的完整细节。

1.3.2.1. CUDA 运行时 API 和 CUDA 驱动程序 API#

CUDA 运行时 API 构建在更低层的 CUDA 驱动程序 API 之上；CUDA 驱动程序 API 是 NVIDIA 驱动公开的 API。本指南主要关注 CUDA 运行时 API 暴露的接口。如果需要，只使用驱动程序 API 也可以完成同样的功能。有些功能只通过驱动程序 API 提供。应用程序可以选择其中一个 API，也可以同时使用二者并进行互操作。CUDA 驱动程序 API 一节介绍运行时 API 与驱动程序 API 的互操作。

CUDA 运行时 API 函数的完整参考见 CUDA 运行时 API 文档。

CUDA 驱动程序 API 的完整参考见 CUDA 驱动程序 API 文档。

1.3.3. 并行线程执行（PTX）#

CUDA 平台中一个基础但有时并不显眼的层，是 并行线程执行（Parallel Thread Execution，PTX）虚拟指令集架构（ISA）。PTX 是面向 NVIDIA GPU 的高级汇编语言，在真实 GPU 硬件的物理 ISA 之上提供了一层抽象。与其他平台类似，应用也可以直接用这种汇编语言编写，不过这样通常会给软件开发增加不必要的复杂度和难度。

面向特定领域的语言，以及高级语言的编译器，可以生成 PTX 代码作为中间表示（IR），再使用 NVIDIA 的离线编译或即时（JIT）编译工具生成可执行的 GPU 二进制代码。这使 CUDA 平台不只限于 NVIDIA 工具直接支持的语言，例如 NVCC：NVIDIA CUDA 编译器，也可以被其他语言使用。

由于 GPU 能力会随时间不断变化和扩展，PTX 虚拟 ISA 规范也带有版本号。PTX 版本和 SM 版本一样，对应某个计算能力。例如，支持计算能力 8.0 全部功能的 PTX 称为 compute_80。

有关 PTX 的完整文档见 PTX ISA。

1.3.4. Cubin 与 Fatbin#

CUDA 应用和库通常使用 C++ 这类高级语言编写。高级语言先被编译为 PTX，随后 PTX 再被编译为面向物理 GPU 的真实二进制代码，称为 CUDA 二进制文件，简称 cubin。cubin 针对特定 SM 版本具有特定的二进制格式，例如 sm_120。

使用 GPU 计算的可执行文件和库二进制文件同时包含 CPU 代码和 GPU 代码。GPU 代码存放在称为 fatbin 的容器中。fatbin 可以包含面向多个不同目标的 cubin 和 PTX。例如，一个应用可以构建出面向多个不同 GPU 架构的二进制代码，也就是面向不同 SM 版本的二进制代码。应用运行时，其 GPU 代码会加载到具体 GPU 上，并从 fatbin 中选择最适合该 GPU 的二进制版本。

fatbin 还可以包含一个或多个 PTX 版本的 GPU 代码，其用途见 PTX 兼容性。图 8 展示了一个应用或库二进制文件示例，其中包含多个 cubin 版本的 GPU 代码以及一个 PTX 版本的代码。

1.3.4.1. 二进制兼容性#

NVIDIA GPU 在特定情况下保证二进制兼容性。具体来说，在同一个计算能力主版本内，如果某个 GPU 的计算能力次版本大于或等于 cubin 的目标次版本，就可以加载并执行该 cubin。例如，如果应用包含为计算能力 8.6 编译的 cubin，则该 cubin 可以在计算能力 8.6 或 8.9 的 GPU 上加载和执行。但它不能加载到计算能力 8.0 的 GPU 上，因为该 GPU 的 CC 次版本 0 低于代码的次版本 6。

NVIDIA GPU 在主要计算能力版本之间不具有二进制兼容性。也就是说，为计算能力 8.6 编译的 cubin 代码将不会加载到计算能力 9.0 的 GPU 上。

讨论二进制代码时，通常会说该二进制具有类似 sm_86 这样的版本。它等价于说该二进制是为计算能力 8.6 构建的。之所以常用这种简写，是因为开发者正是通过这种形式向 NVIDIA CUDA 编译器 nvcc 指定二进制构建目标。

注意

二进制兼容性承诺仅适用于由 NVIDIA 工具（例如 nvcc）创建的二进制文件。不支持手动编辑或生成 NVIDIA GPU 二进制代码。如果以任何方式修改二进制文件，兼容性承诺即失效。

1.3.4.2. PTX 兼容性#

如 Cubin 与 Fatbin 所述，GPU 代码可以以二进制形式或 PTX 形式存储在可执行文件中。当应用保存 GPU 代码的 PTX 版本时，该 PTX 可以在应用运行时被 JIT 编译为任意计算能力不低于该 PTX 代码计算能力的目标。例如，如果应用包含 compute_80 PTX，那么该 PTX 代码可在运行时 JIT 编译为更高的 SM 版本，例如 sm_120。这样无需重建应用或库，也能向前兼容未来 GPU。

1.3.4.3. 即时编译#

应用在运行时加载的 PTX 代码会由设备驱动编译为二进制代码，这一过程称为即时（JIT）编译。JIT 编译会增加应用加载时间，但也让应用能够受益于每个新设备驱动带来的编译器改进；同时，它还使应用能够运行在编译该应用时尚不存在的设备上。

当设备驱动为应用 JIT 编译 PTX 代码时，会自动缓存生成的二进制代码副本，以避免应用后续运行时重复编译。设备驱动升级时，该缓存（称为计算缓存）会自动失效，使应用能够受益于新驱动内置 JIT 编译器的改进。

从 CUDA 早期版本至今，运行时 JIT 编译 PTX 的方式和时机已经逐步放宽，使应用在是否以及何时 JIT 编译部分或全部内核方面拥有更大灵活性。延迟加载 一节介绍了可用选项以及如何控制 JIT 行为。还有一些环境变量可控制即时编译行为，详见 CUDA 环境变量。

除使用 nvcc 编译 CUDA C++ 设备代码外，也可以使用 NVRTC 在运行时将 CUDA C++ 设备代码编译为 PTX。NVRTC 是 CUDA C++ 的运行时编译库；更多信息见 NVRTC 用户指南。
