3.5. CUDA 特性概览#

本编程指南的第 1-3 章已介绍 CUDA 与 GPU 编程，涵盖了概念层面以及简单代码示例中的基础主题。本指南第 4 部分对具体 CUDA 特性的说明，默认读者已掌握第 1-3 章涉及的概念。

CUDA 提供了许多面向不同问题的特性，并非每项特性都适用于所有场景。本章旨在逐一介绍这些特性，说明其设计用途以及可帮助解决的问题。各特性按要解决的问题类型进行粗略分类；某些特性（如 CUDA 图）可能同时属于多个类别。

第 4 章 更完整、详细地介绍了这些 CUDA 特性。

3.5.1. 提升内核性能#

本节介绍的特性都旨在帮助内核开发者最大化其内核性能。

3.5.1.1. 异步屏障#

Asynchronous barriers were introduced in Section 3.2.4.2 and allow for more nuanced control over synchronization between threads. Asynchronous barriers separate the arrival and the wait of a barrier. This allows applications to perform work that does not depend on the barrier while waiting for other threads to arrive. Asynchronous barriers can be specified for different thread scopes. Full details of asynchronous barriers are found in 第 4 章.9.

3.5.1.2. 异步数据拷贝与张量内存加速器（TMA）#

Asynchronous data copies in the context of CUDA kernel code refers to the ability to move data between shared memory and GPU DRAM while still carrying out computations. This should not be confused with asynchronous memory copies between the CPU and GPU. This feature makes used of asynchronous barriers. 第 4 章.11 covers the use of asynchronous copies in detail.

3.5.1.3. 流水线#

流水线 are a mechanism for staging work and coordinating multi-buffer producer–consumer patterns, commonly used to overlap compute with asynchronous data copies. 第 4 章.10 has details and examples of using pipelines in CUDA.

3.5.1.4. 使用集群启动控制的工作窃取#

工作窃取是一种在负载不均场景下维持利用率的技术：已完成工作的执行单元可从其他执行单元“窃取”任务。计算能力 10.0（Blackwell）引入的集群启动控制特性，使 kernel 能直接控制飞行中的线程块调度，从而实时适应不均匀负载。线程块可取消尚未启动的其他线程块或集群的启动、接管其索引，并立即执行被窃取工作。该流程可在数据不规则或运行时波动下保持 SM 忙碌、减少空闲时间，在不完全依赖硬件调度器的情况下实现更细粒度的负载均衡。

第 4 章.12 provides details on how to use this feature.

3.5.2. 降低时延#

本节特性有一个共同主题：降低某类时延，但不同特性针对的时延类型并不相同。总体而言，它们主要关注内核启动层面及以上的时延，而不涉及内核内部 GPU 内存访问时延。

3.5.2.1. 绿色上下文#

绿色上下文（亦称执行上下文）是 CUDA 的一项特性，允许程序创建仅在 GPU 的部分 SM 子集上执行工作的 CUDA 上下文。默认情况下，kernel 启动的线程块会被分发到 GPU 内任意可满足其资源需求的 SM。影响哪些 SM 能执行线程块的因素很多，包括但不限于：共享内存使用量、寄存器使用量、是否使用集群，以及线程块总线程数。

执行上下文允许将 kernel 启动到专门创建的上下文中，并可进一步限制可用于执行该 kernel 的 SM 数量。关键在于：当程序创建了使用某组 SM 的绿色上下文后，GPU 上其他上下文将不会把线程块调度到这些已分配给绿色上下文的 SM 上。这也包括 CUDA 运行时默认使用的主上下文。由此可将这些 SM 预留给高优先级或时延敏感的工作负载。

第 4 章.6 详细介绍了绿色上下文的使用方式。绿色上下文在 CUDA 13.1 及之后版本的 CUDA 运行时中可用。

3.5.2.2. 流有序内存分配#

流有序内存分配器允许程序把 GPU 内存分配与释放编排到 CUDA 流中。不同于立即执行的 cudaMalloc/cudaFree，cudaMallocAsync/cudaFreeAsync 会将分配或释放操作插入到 CUDA 流中。关于这些 API 的全部细节，请见 第 4 章.3。

3.5.2.3. CUDA 图#

CUDA 图允许应用指定一系列 CUDA 操作（如 kernel 启动、内存拷贝）及其依赖关系，从而在 GPU 上高效执行。类似行为也可通过 CUDA 流 实现；实际上，创建图的一种机制称为 流捕获，可将流上的操作记录为 CUDA 图。图还可通过 CUDA 图 API 创建。

图创建后可被实例化并重复执行多次，这对重复型工作负载尤其有用。图可降低调用 CUDA 操作时的 CPU 启动开销，并启用仅在“预先给定完整工作负载”时可用的优化，从而带来性能收益。

第 4 章.2 介绍并演示了 CUDA 图的使用方法。

3.5.2.4. 编程式依赖启动#

编程式依赖启动是 CUDA 的一项特性，允许依赖 kernel（即依赖前序 kernel 输出的 kernel）在其依赖的主 kernel 完成前就开始执行。依赖 kernel 可先执行初始化与无关工作，直到需要主 kernel 数据时再阻塞。主 kernel 可在依赖数据就绪时发出信号，释放依赖 kernel 继续执行。这使两个 kernel 可部分重叠，有助于在降低关键数据路径时延的同时保持较高 GPU 利用率。详见 第 4 章.5。

3.5.2.5. 惰性加载#

惰性加载特性允许控制 JIT 编译器在应用启动阶段的工作方式。若应用包含大量需从 PTX JIT 编译到 cubin 的 kernel，而又在启动阶段一次性完成编译，启动时间可能很长。默认行为是模块按需编译。该行为可通过环境变量调整，详见 第 4 章.7。

3.5.3. 功能型特性#

此处介绍的特性有共同点：它们旨在提供额外能力或功能。

3.5.3.1. 扩展 GPU 内存#

扩展 GPU 内存（EGM）是 NVLink-C2C 互连系统中的一项特性，可让 GPU 高效访问系统内全部内存。详见 第 4 章.17。

3.5.3.2. 动态并行#

CUDA 应用最常见的是由 CPU 端代码启动 kernel；也可以由运行在 GPU 上的 kernel 再发起新的 kernel 调用。这一特性称为 CUDA 动态并行。关于如何在 GPU 端代码中创建新的 GPU kernel 启动，详见 第 4 章.18。

3.5.4. CUDA 互操作性#

3.5.4.1. CUDA 与其他 API 的互操作性#

在 GPU 上运行代码并不只有 CUDA 这一机制。GPU 最初用于加速计算机图形，因此有其图形 API 体系，如 Direct3D 与 Vulkan。应用可能希望一边使用图形 API 进行 3D 渲染，一边在 CUDA 中执行计算。CUDA 提供机制，用于在 CUDA 上下文与图形 API 使用的 GPU 上下文之间交换驻留在 GPU 上的数据。例如，应用可先用 CUDA 做模拟，再用 3D API 将结果可视化。这通过让部分缓冲区同时可被 CUDA 与图形 API 读取和/或写入来实现。

与图形 API 共享缓冲区所用的同一套机制，也可用于与通信机制共享缓冲区，从而在多节点环境中实现快速、直接的 GPU 到 GPU 通信。

第 4 章.19 介绍了 CUDA 如何与其他 GPU API 互操作，以及如何在 CUDA 与其他 API 间共享数据，并给出了多种 API 的具体示例。

3.5.4.2. 进程间通信#

在超大规模计算中，常会联合使用多块 GPU，以利用更大内存与更多计算资源协同求解问题。在单个系统（集群术语中的单节点）内，可在一个主机进程中使用多块 GPU，这在 第 3.4 节 已说明。

也常见跨单机或多机使用多个独立主机进程协同工作。多个进程协同时，它们之间的通信称为进程间通信（IPC）。CUDA 进程间通信（CUDA IPC）提供了在不同进程间共享 GPU 缓冲区的机制。第 4 章.15 解释并演示了如何利用 CUDA IPC 在不同主机进程间进行协调与通信。

3.5.5. 细粒度控制#

3.5.5.1. 虚拟内存管理#

如 第 2.4.1 节 所述，系统内所有 GPU 与 CPU 内存共享同一统一虚拟地址空间。大多数应用可直接使用 CUDA 默认内存管理而无需改变其行为。不过，对有需要的场景，CUDA 驱动 API 提供了对该虚拟内存空间布局更高级、细粒度的控制能力。这主要用于控制缓冲区在单系统内或跨系统 GPU 共享时的行为。

第 4 章.16 介绍了 CUDA 驱动 API 提供的这些控制能力、其工作方式，以及开发者在何种场景下可从中受益。

3.5.5.2. 驱动入口点访问#

驱动入口点访问是指从 CUDA 11.3 开始可获取 CUDA Driver 与 CUDA Runtime API 函数指针的能力。它还允许开发者获取特定变体驱动函数的函数指针，并访问比 CUDA toolkit 内置版本更新的驱动函数。详见 第 4 章.20。

3.5.5.3. 错误日志管理#

错误日志管理提供了处理与记录 CUDA API 错误的工具。只需设置一个环境变量 CUDA_LOG_FILE，即可将 CUDA 错误直接输出到 stderr、stdout 或文件。错误日志管理还支持应用注册回调，在 CUDA 遇到错误时触发。更多细节见 第 4 章.8。
