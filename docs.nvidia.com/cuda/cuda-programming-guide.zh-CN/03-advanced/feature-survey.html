3.5. CUDA 特性概览#

本编程指南第 1 到第 3 节已经介绍了 CUDA 和 GPU 编程，并通过概念说明和简单代码示例覆盖了基础主题。本指南第 4 部分介绍具体 CUDA 特性时，会假定读者已经了解第 1 到第 3 节中的概念。

CUDA 提供许多面向不同问题的特性，但并不是每个特性都适用于每一种用例。本章用于逐一介绍这些特性，说明它们的预期用途，以及它们可能帮助解决的问题。各项特性会按照所面向的问题类型作粗略分类。有些特性（例如 CUDA 图）可以归入多个类别。

第 4 节 会更完整、更详细地介绍这些 CUDA 特性。

3.5.1. 提高内核性能#

本节概述的特性都旨在帮助内核开发者尽可能提高内核性能。

3.5.1.1. 异步屏障#

异步屏障 已在 第 3.2.4.2 节 中介绍，它允许更细致地控制线程之间的同步。异步屏障将屏障的“到达”和“等待”分离开来，使应用程序在等待其他线程到达屏障时，可以先执行不依赖该屏障的工作。异步屏障可以指定不同的 线程作用域。异步屏障的完整细节见 第 4.9 节。

3.5.1.2. 异步数据拷贝和张量内存加速器 (TMA)#

在 CUDA 内核代码的语境中，异步数据拷贝 是指一边执行计算，一边在共享内存和 GPU DRAM 之间移动数据的能力。不要将它与 CPU 和 GPU 之间的异步内存拷贝混淆。此特性会使用异步屏障。第 4.11 节 详细介绍了异步拷贝的用法。

3.5.1.3. 流水线#

流水线 是一种用于暂存工作并协调多缓冲区生产者-消费者模式的机制，通常用于将计算与 异步数据拷贝 重叠执行。第 4.10 节 提供了在 CUDA 中使用流水线的细节和示例。

3.5.1.4. 使用集群启动控制进行工作窃取#

工作窃取是一种在负载不均衡场景中维持利用率的技术：已经完成自身工作的工作单元，可以从其他工作单元那里“窃取”任务。集群启动控制是计算能力 10.0 (Blackwell) 引入的特性，它让内核能够直接控制正在进行中的线程块调度，从而实时适应不均衡工作负载。线程块可以取消另一个尚未开始执行的线程块或集群的启动，认领其索引，并立即开始执行窃取来的工作。此工作窃取流程可让 SM 保持繁忙，并在数据不规则或运行时变化的情况下减少空闲时间，从而在不完全依赖硬件调度器的情况下提供更细粒度的负载均衡。

第 4.12 节 提供了此特性的使用细节。

3.5.2. 降低延迟#

本节概述的特性都有一个共同目标：降低某种类型的延迟，尽管不同特性关注的延迟类型并不相同。总体来看，它们关注的是内核启动层级或更高层级的延迟；内核内部的 GPU 内存访问延迟不在这里讨论的范围内。

3.5.2.1. 绿色上下文#

绿色上下文，也称为 执行上下文，是一项 CUDA 特性，允许程序创建只在 GPU 的一部分 SM 上执行工作的 CUDA 上下文。默认情况下，内核启动中的线程块会被分派到 GPU 内任何能够满足该内核资源需求的 SM 上。哪些 SM 能够执行线程块，会受到很多因素影响，包括但不限于共享内存用量、寄存器用量、集群使用情况以及线程块中的线程总数。

执行上下文允许把内核启动到专门创建的上下文中，从而进一步限制可用于执行该内核的 SM 数量。重要的是，当程序创建使用某一组 SM 的绿色上下文时，GPU 上的其他上下文不会把线程块调度到分配给该绿色上下文的 SM 上。这包括主上下文，也就是 CUDA 运行时默认使用的上下文。这样就可以为高优先级或延迟敏感的工作负载保留这些 SM。

第 4.6 节 提供了绿色上下文用法的完整细节。绿色上下文可在 CUDA 13.1 及更高版本的 CUDA 运行时中使用。

3.5.2.2. 流有序内存分配#

流有序内存分配器 允许程序把 GPU 内存的分配和释放操作按顺序排入 CUDA 流。与立即执行的 cudaMalloc 和 cudaFree 不同，cudaMallocAsync 和 cudaFreeAsync 会把内存分配或释放操作插入到 CUDA 流中。第 4.3 节 覆盖了这些 API 的所有细节。

3.5.2.3. CUDA 图#

CUDA 图 允许应用程序指定一系列 CUDA 操作（例如内核启动或内存拷贝）以及这些操作之间的依赖关系，使它们能够在 GPU 上高效执行。使用 CUDA 流 也可以获得类似行为；实际上，创建图的一种机制就称为 流捕获，它可以把流上的操作记录到 CUDA 图中。也可以使用 CUDA 图 API 创建图。

图一旦创建，就可以实例化并执行多次。这对于描述会重复执行的工作负载非常有用。图可以带来一些性能优势：既能降低调用 CUDA 操作时相关的 CPU 启动开销，也能启用只有在整个工作负载预先指定时才可用的优化。

第 4.2 节 描述并演示了如何使用 CUDA 图。

3.5.2.4. 程序化依赖启动#

程序化依赖启动 是一项 CUDA 特性，它允许依赖内核（也就是依赖先前内核输出的内核）在其所依赖的主内核完成之前开始执行。依赖内核可以先执行初始化代码和无关工作，直到它需要主内核产生的数据时才在那里阻塞。主内核可以在依赖内核所需数据就绪时发出信号，从而释放依赖内核继续执行。这样可以让内核之间产生一定重叠，在尽量降低关键数据路径延迟的同时，帮助维持较高的 GPU 利用率。第 4.5 节 介绍了程序化依赖启动。

3.5.2.5. 延迟加载#

延迟加载 是一项允许控制 JIT 编译器在应用程序启动时如何工作的特性。如果某个应用程序包含大量需要从 PTX JIT 编译为 cubin 的内核，而所有内核都在应用程序启动时完成 JIT 编译，那么启动时间可能会很长。默认行为是模块只有在需要时才会编译。可以通过 环境变量 改变这一行为，详见 第 4.7 节。

3.5.3. 功能性特性#

这里描述的特性有一个共同点：它们旨在启用额外能力或功能。

3.5.3.1. 扩展 GPU 内存#

扩展 GPU 内存 是 NVLink-C2C 互连系统中可用的一项特性，使 GPU 能够高效访问系统内的所有内存。EGM 详见 第 4.17 节。

3.5.3.2. 动态并行性#

CUDA 应用程序最常见的做法，是从运行在 CPU 上的代码启动内核。也可以从运行在 GPU 上的内核中创建新的内核调用。此特性称为 CUDA 动态并行。第 4.18 节 介绍了如何从运行在 GPU 上的代码创建新的 GPU 内核启动。

3.5.4. CUDA 互操作性#

3.5.4.1. CUDA 与其他 API 的互操作性#

除了 CUDA 之外，还有其他机制可以在 GPU 上运行代码。GPU 最初是为加速计算机图形而构建的，并使用 Direct3D、Vulkan 等各自的 API。应用程序可能希望在使用 CUDA 执行计算的同时，使用某个图形 API 进行 3D 渲染。CUDA 提供了相关机制，可在 CUDA 上下文和 3D API 使用的 GPU 上下文之间交换存储在 GPU 上的数据。例如，应用程序可以使用 CUDA 执行模拟，再使用 3D API 对结果进行可视化。实现方式是让某些缓冲区可由 CUDA 和图形 API 同时读取和/或写入。

允许与图形 API 共享缓冲区的同一套机制，也可用于与通信机制共享缓冲区，从而在多节点环境中实现快速、直接的 GPU 到 GPU 通信。

第 4.19 节 描述了 CUDA 如何与其他 GPU API 互操作、如何在 CUDA 与其他 API 之间共享数据，并为许多不同 API 提供了具体示例。

3.5.4.2. 进程间通信#

对于非常大的计算，通常会同时使用多个 GPU，让更多内存和更多计算资源共同解决问题。在单个系统内，或者按集群计算术语说的单个节点内，可以在一个主机进程中使用多个 GPU。相关内容见 第 3.4 节。

使用跨越一台或多台计算机的独立主机进程也很常见。当多个进程协同工作时，它们之间的通信称为进程间通信。CUDA 进程间通信 (CUDA IPC) 提供了在不同进程之间共享 GPU 缓冲区的机制。第 4.15 节 解释并演示了如何使用 CUDA IPC 在不同主机进程之间进行协调和通信。

3.5.5. 细粒度控制#

3.5.5.1. 虚拟内存管理#

如 第 2.4.1 节 所述，系统中的所有 GPU 会与 CPU 内存共享一个统一虚拟地址空间。大多数应用程序都可以直接使用 CUDA 提供的默认内存管理，而无需改变其行为。不过，对于确实需要的场景，CUDA 驱动程序 API 提供了对该虚拟内存空间布局的高级、细粒度控制。这主要适用于控制缓冲区在同一系统内多个 GPU 之间共享，或跨多个系统共享时的行为。

第 4.16 节 介绍了 CUDA 驱动程序 API 提供的控制能力、其工作方式，以及开发者在什么情况下会发现它们有用。

3.5.5.2. 驱动程序入口点访问#

驱动程序入口点访问 是指从 CUDA 11.3 开始，可以检索指向 CUDA 驱动程序 API 和 CUDA 运行时 API 的函数指针。它还允许开发者检索驱动程序函数特定变体的函数指针，并访问比 CUDA 工具包所带版本更新的驱动程序中的驱动程序函数。第 4.20 节 介绍了驱动程序入口点访问。

3.5.5.3. 错误日志管理#

错误日志管理 提供用于处理和记录 CUDA API 错误的工具。只需设置一个环境变量 CUDA_LOG_FILE，即可把 CUDA 错误直接捕获到 stderr、stdout 或文件中。错误日志管理还允许应用程序注册回调，并在 CUDA 遇到错误时触发该回调。第 4.8 节 提供了错误日志管理的更多细节。
