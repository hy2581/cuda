3.5. CUDA 特性概览#

本编程指南的第 1-3 节介绍了 CUDA 和 GPU 编程，从概念上和简单的代码示例中涵盖了基础主题。本指南第 4 部分中描述特定 CUDA 功能的部分假定您了解本指南第 1-3 部分中涵盖的概念。

CUDA 具有许多适用于不同问题的功能。并非所有这些都适用于每个用例。本章旨在介绍其中的每一项功能，并描述其预期用途以及它可能有助于解决的问题。功能按其要解决的问题类型粗略地分类。某些功能（例如 CUDA 图表）可能属于多个类别。

第 4 节 更完整地详细介绍了这些 CUDA 功能。

3.5.1. 提高内核性能#

本节中概述的功能都是为了帮助内核开发人员最大限度地提高其内核的性能。

3.5.1.1. 异步屏障#

异步屏障 被介绍于 第3.2.4.2节 并允许对线程之间的同步进行更细致的控制。异步屏障将屏障的到达和等待分开。这允许应用程序在等待其他线程到达时执行不依赖于屏障的工作。可以为不同的情况指定异步屏障 线程范围。 异步屏障的完整详细信息可在 第 4.9 节.

3.5.1.2. 异步数据副本和张量内存加速器（TMA）#

异步数据复制 在 CUDA 内核代码上下文中，指的是在执行计算的同时在共享内存和 GPU DRAM 之间移动数据的能力。这不应与 CPU 和 GPU 之间的异步内存复制相混淆。此功能利用了异步屏障。 第 4.11 节 详细介绍了异步副本的使用。

3.5.1.3. 流水线#

流水线 是一种用于暂存工作和协调多缓冲区生产者-消费者模式的机制，通常用于与计算重叠 异步数据复制. 第 4.10 节 有在 CUDA 中使用管道的详细信息和示例。

3.5.1.4. 使用集群启动控制窃取工作#

工作窃取是一种在不均匀的工作负载中保持利用率的技术，其中已完成工作的工作人员可以从其他工作人员那里“窃取”任务。集群启动控制是计算能力 10.0 (Blackwell) 中引入的一项功能，它使内核能够直接控制运行中的块调度，以便它们能够实时适应不均匀的工作负载。线程块可以取消另一个尚未启动的线程块或集群的启动，声明其索引，并立即开始执行窃取的工作。这种工作窃取流程使 SM 保持忙碌，并在不规则数据或运行时变化的情况下减少空闲时间，从而提供更细粒度的负载平衡，而无需单独依赖硬件调度程序。

第 4.12 节 提供有关如何使用此功能的详细信息。

3.5.2. 改善延迟#

本节概述的功能有一个共同的主题，即旨在减少某种类型的延迟，尽管不同功能所解决的延迟类型有所不同。总的来说，他们关注的是内核启动级别或更高级别的延迟。内核内的 GPU 内存访问延迟不是此处考虑的延迟之一。

3.5.2.1. 绿色上下文#

绿色上下文，也称为 执行上下文，是 CUDA 功能的名称，该功能使程序能够创建 CUDA 上下文 它将仅在 GPU 的 SM 子集上执行工作。默认情况下，内核启动的线程块会被调度到 GPU 内任何能够满足内核资源需求的 SM。有很多因素可以影响哪些 SM 可以执行线程块，包括但不一定限于：共享内存使用、寄存器使用、簇的使用以及线程块中的线程总数。

执行上下文允许将内核启动到专门创建的上下文中，这进一步限制了可用于执行内核的 SM 数量。重要的是，当程序创建使用某些 SM 集的绿色上下文时，GPU 上的其他上下文不会将线程块调度到分配给绿色上下文的 SM 上。这包括主上下文​​，它是 CUDA 运行时使用的默认上下文。这允许为高优先级或延迟敏感的工作负载保留这些 SM。

第 4.6 节 提供有关使用绿色上下文的完整详细信息。绿色上下文在 CUDA 13.1 及更高版本的 CUDA 运行时中可用。

3.5.2.2. 按流顺序的内存分配#

流排序内存分配器 允许程序按顺序分配和释放 GPU 内存 CUDA流。不像 cudaMalloc 或 cudaFree 立即执行， cudaMallocAsync 或 cudaFreeAsync 将内存分配或释放操作插入到 CUDA 流中。 第 4.3 节 涵盖了这些 API 的所有细节。

3.5.2.3. CUDA 图形#

CUDA 图表 使应用程序能够指定一系列 CUDA 操作（例如内核启动或内存复制）以及这些操作之间的依赖关系，以便它们可以在 GPU 上高效执行。类似的行为可以通过使用来实现 CUDA 流，实际上创建图的机制之一称为 流捕获，它可以将流上的操作记录到 CUDA 图中。还可以使用以下命令创建图表 CUDA 图形 API.

一旦创建了图，就可以对其进行实例化并执行多次。这对于指定将重复的工作负载非常有用。图形提供了一些性能优势，可降低与调用 CUDA 操作相关的 CPU 启动成本，并实现仅在提前指定整个工作负载时才可用的优化。

第 4.2 节 描述并演示如何使用 CUDA 图。

3.5.2.4. 程序化依赖启动#

程序化依赖启动 是一项 CUDA 功能，允许依赖内核（即依赖于先前内核输出的内核）在其所依赖的主内核完成之前开始执行。从属内核可以执行设置代码和不相关的工作，直到它需要来自主内核的数据并阻止在那里。主内核可以在从属内核所需的数据准备好时发出信号，这将释放从属内核以继续执行。这使得内核之间存在一定的重叠，有助于保持 GPU 的高利用率，同时最大限度地减少关键数据路径的延迟。 第 4.5 节 涵盖程序化依赖启动。

3.5.2.5. 延迟加载#

延迟加载 是一项允许控制 JIT 编译器在应用程序启动时如何运行的功能。如果所有内核都作为应用程序启动的一部分进行 JIT 编译，则具有许多内核且需要从 PTX 到 cubin 进行 JIT 编译的应用程序可能会经历较长的启动时间。默认行为是模块在需要时才进行编译。这可以通过使用来改变 环境变量，详见 第 4.7 节.

3.5.3. 功能特点#

这里描述的特性有一个共同的特征，即它们旨在实现额外的能力或功能。

3.5.3.1. 扩展 GPU 内存#

扩展 GPU 内存 是 NVLink-C2C 连接系统中可用的一项功能，可以从 GPU 内高效访问系统内的所有内存。 EGM 详细介绍于 第 4.17 条.

3.5.3.2. 动态并行性#

CUDA 应用程序通常从 CPU 上运行的代码启动内核。还可以从 GPU 上运行的内核创建新的内核调用。此功能称为 CUDA动态并行. 第 4.18 条 涵盖了从 GPU 上运行的代码创建新 GPU 内核启动的详细信息。

3.5.4. CUDA 互操作性#

3.5.4.1. CUDA 与其他 API 的互操作性#

除了 CUDA 之外，还有其他机制可以在 GPU 上运行代码。应用程序 GPU 最初是为了加速计算机图形而构建的，使用自己的一组 API，例如 Direct3D 和 Vulkan。应用程序可能希望在 CUDA 中执行计算时使用图形 API 之一进行 3D 渲染。 CUDA 提供了在 CUDA 上下文和 3D API 使用的 GPU 上下文之间交换存储在 GPU 上的数据的机制。例如，应用程序可以使用 CUDA 执行模拟，然后使用 3D API 创建结果的可视化。这是通过使某些缓冲区可从 CUDA 和图形 API 读取和/或写入来实现的。

允许与图形 API 共享缓冲区的相同机制也可用于与通信机制共享缓冲区，从而能够在多节点环境中实现快速、直接的 GPU 到 GPU 通信。

第 4.19 条 描述了 CUDA 如何与其他 GPU API 互操作以及如何在 CUDA 与其他 API 之间共享数据，并为许多不同的 API 提供了具体示例。

3.5.4.2. 进程间通信#

对于非常大的计算，通常会同时使用多个 GPU，以利用更多内存和更多计算资源来共同解决问题。在单个系统或集群计算术语中的节点中，可以在单个主机进程中使用多个 GPU。这在 第 3.4 节.

使用跨越一台计算机或多台计算机的单独主机进程也很常见。当多个进程一起工作时，它们之间的通信称为进程间通信。 CUDA 进程间通信 (CUDA IPC) 提供了在不同进程之间共享 GPU 缓冲区的机制。 第 4.15 节 解释并演示了如何使用 CUDA IPC 在不同主机进程之间进行协调和通信。

3.5.5. 细粒度控制#

3.5.5.1. 虚拟内存管理#

正如中提到的 第2.4.1节，系统中的所有 GPU 以及 CPU 内存共享一个统一的虚拟地址空间。大多数应用程序可以使用 CUDA 提供的默认内存管理，而无需更改其行为。然而， CUDA 驱动程序 API 为需要的人提供对此虚拟内存空间布局的高级和详细控制。这主要适用于在多个系统内和跨多个系统的 GPU 之间共享时控制缓冲区的行为。

第 4.16 条 涵盖了 CUDA 驱动程序 API 提供的控件、它们的工作方式以及开发人员何时会发现它们有利。

3.5.5.2. 驱动程序入口点访问#

驱动程序入口点访问 指的是从 CUDA 11.3 开始，检索指向 CUDA 驱动程序和 CUDA 运行时 API 的函数指针的能力。它还允许开发人员检索驱动程序函数特定变体的函数指针，并从比 CUDA 工具包中可用的驱动程序更新的驱动程序访问驱动程序函数。 第 4.20 条 涵盖驱动程序入口点访问。

3.5.5.3. 错误日志管理#

错误日志管理 提供用于处理和记录来自 CUDA API 的错误的实用程序。设置单个环境变量 CUDA_LOG_FILE 允许将 CUDA 错误直接捕获到 stderr、stdout 或文件。 错误日志管理还使应用程序能够注册回调，该回调在 CUDA 遇到错误时触发。 第 4.8 节 提供有关错误日志管理的更多详细信息。
